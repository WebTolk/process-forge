# Постоянный контекст Python QA для ProcessForge

Общие инструменты установлены в слое tools рабочего места, вне Core и проектов.
Их точные команды берутся из PF registry/context; пути частной установки не
фиксируются в публичном репозитории. Общий контракт — `python/toolchain.json`
в настроенном корне toolchains. Переносимые исходники и инструкция установки:
`tools/python-qa/`, `docs/ru/guides/python-quality.md`.

| PF tool id | Назначение | Применение на assurance |
| --- | --- | --- |
| python-pytest | pytest | Обязательные тесты затронутого поведения |
| python-ruff | Ruff lint | Обязательная проверка затронутого Python-кода |
| python-formatter | Ruff format check | Обязательная проверка формата затронутой области |
| python-mypy | mypy | Обязательный анализ изменённой типизированной области |
| python-docstrings | Ruff D, Google convention | При изменении документации/API и по задаче документации Core |
| python-coverage | pytest-cov / coverage.py | Для оценки покрытия затронутого поведения; общий порог Core не выдумывать |
| python-bandit | Bandit | По риску безопасности изменённого кода |
| python-pip-audit | pip-audit | При изменении зависимостей или явной задаче аудита |

Применяйте PEP 8, PEP 257 и единую Google-конвенцию docstrings. Подробное
документирование и систематическое покрытие всего Core остаются будущими задачами;
эта инструкция не утверждает, что они уже выполнены.

Запускатель QA получает явный корень проекта. Он выбирает конфигурацию проекта
раньше общей, а тесты выполняет настоящим интерпретатором проекта с его
зависимостями. Несовместимость версии Python/платформы/ABI требует подходящего
окружения, а не незаметной подмены. Не устанавливайте QA зависимости в Runtime.
Используйте зарегистрированные команды с аргументами затронутых файлов/тестов;
не сканируйте весь Core автоматически и не подменяйте существующие проверки.

На code-assurance нужны test-report и code-quality-report: реальные команды,
версии, охват, identity/байты кандидата, exit codes, результаты и ограничения.
Неудача либо недоступность обязательной проверки блокирует завершение. Для
изменений без применимого кода мотивируйте not_applicable с evidence. Ранее
выполненные проверки можно зачесть только для тех же байтов и применимой среды;
последующая правка требует повторить затронутые проверки. Фиксы/форматирование
являются отдельными операциями, а не побочным действием lint/format check.

Следующий запуск: получить свежий pf.context, прочитать .pf/AGENTS.md и этот
файл, проверить восемь id из context_requirements.tools, затем подобрать
проверки по задаче. Отсутствующее обязательное средство сообщить как конкретный
блокер; наличие записи в реестре само по себе не доказывает успешный запуск.
