# План исправления документации PF 1.1.1

Дата: 2026-09-07. Статус: принят оркестратором к исполнению по прямому запросу пользователя.

Основание: .pf/artifacts/docs-audit-1.1.1-report-20260907.md, D01-D08. Прежние изменения required outputs сохраняются. Версию, миграции, installed Core и публикацию не меняем.

1. Зафиксировать границы и сформировать отдельный multi-agent-task-orchestration Run с immutable worker capsules. Текущий MCP создал single-agent carrier; он остаётся журналом и итоговым контрольным циклом основного агента. Явный запрос оператора разрешает отдельную shell-оркестрацию через специализированный orchestrator-plan CLI; pinned Process и manifest не переписываются.
2. Параллельно, максимум три воркера: docs111-mechanical (spark, D01/D05/D08), docs111-workflow (gpt-5.4-mini, D02/D03/D04/D07), docs111-update (spark, D06). Файловые области перечислены в YAML, пересечений нет.
3. Основной агент читает diff и проверяет кодовую основу каждого изменения. Завершение shell-процесса и наличие отчёта не заменяют принятия качества. Отклонённые результаты возвращаются в отдельную попытку с уникальным attempt id.
4. После реализации docs111-tests (gpt-5.4-mini) добавляет регрессии и исправляет устаревший search-index smoke. Регистрацию нового smoke и checksum inventory выполняет только основной агент.
5. После реализации и тестов docs111-review (gpt-5.4-mini) независимо проверяет изменения без записи. Основной агент проверяет замечания, устраняет подтверждённые проблемы и принимает результат.
6. Приёмка: CLI/link inventory; новые и затронутые тесты; schema/cleanliness/checksum/diff checks; полный source release-test с терминальным результатом; scoped Run/Task doctors; отчёт по каждой D01-D08. Повторные циклы при провалах; нерелевантные дефекты не скрывать.
7. Зафиксировать итог и handoff, завершить orchestration и carrier. Релизная упаковка, тег, публикация и путь миграции 1.1.1 остаются отдельными явно указанными задачами.

Модели обнаружены в локальном каталоге Codex, доступность конкретного запуска подтверждается command/exit evidence. Runtime driver codex-exec прошёл validate. Новые daemon/Runtime/hooks/Ledger не устанавливаются и не запускаются; используются только явно запрошенные конечные worker-процессы.

Контроль: один писатель на файл; запрещена передача lifecycle воркерам; stdout/exit/report обязательны; общие logs/checksums/регистрация smoke принадлежат оркестратору. Артефакты старого аудита неизменяемы; новые проверки пишутся в эту новую папку.
