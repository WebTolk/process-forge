# T04 architecture and implementation plan

Add tools/pf_runtime/provider_adapters.py as neutral immutable Registry, AdapterPolicy, WorkerBinding and message-policy contracts; builtin_provider_adapters.py as the explicit trusted composition root; codex_adapters.py owns existing Codex hook/worker interpretation and fallback rules. No dynamic imports from event data. Host imports only the neutral registry/default composition interface; policy behavior is selected by exact registered pair. Caller-supplied registry is a trusted Python object, never a JSON/config field on incoming events.

Host ingress sequence: persist RawIngressKernel receipt unchanged; resolve registered policy; validate envelope and all common identity bindings; refuse any unsupported derived effect; then current normalized event/ledger route and conversation capture. Return explicit denied routing diagnostics for registry/provenance failures while retaining accepted raw receipt. Existing project/session authorization raises as before. Unknown native hooks in a known adapter remain raw-only. Runtime legacy wrapper uses a fixed neutral adapter key; original normalized source remains inside raw payload.

Adapter interface: validate envelope; identify worker binding when policy uses worker authorization; allow/deny exact conversation provenance; supply per-message owned-report permission and fallback duplicate participant rule. Registry is immutable and rejects duplicate registrations. Host worker helper consumes neutral binding fields (run/task/attempt, report path, input payload/hash/summary or output text/hash), validating current state, contained report path, local input contract and exact hashes/bytes. It never branches on Codex provider/event strings. Keep small existing internal helper wrappers for compatibility tests and worker summary import.

Admission also runs at direct conversation sink (Codex replay) and deferred flush. Registry propagates through ingest/flush; no cached trusted decision from an untrusted event. The private Codex replay module remains provider-owned, preserves its existing checkpoint/dedup/error contract, and its generated envelope passes admission. No raw kernel or raw identity changes.

Optional initialization helper in Core catches absence/failure of only optional status callbacks and marks telemetry unavailable, without affecting generic readiness or silently installing. CLI onboarding and Core status share it; explicit Codex repair action stays compatible and remains apply-gated. No new public MCP transport/API is needed.

Supporting legacy fix: inspect run task entries to bind exact declared process for non-governed task-batch membership; governed run process/pin equality stays strict. No fallback from a present corrupt pin. Add coverage through existing conversation/worker capture fixture and parity regression where applicable.

Ownership: primary registry, adapters, Host and legacy fix. Junior may implement only isolated optional-integration helper plus project_initialization.py and a private implementation report; primary integrates CLI line. After implementation: independent source reviewer and separate new provider-neutral regression writer, each disjoint files. Test matrix: alternate registered fixture and unknown/spoof negatives; raw-first/quarantine/dedup/repair; Codex ingress/replay/lifecycle/conversation/input/report/containment; generic init with missing module; T03 parity. Schema/public/checksum gates and EN/RU contract docs; installed proof reserved for T06.
