# T04 independent source review

Scope reviewed: the accepted T04 contract, provider-neutral registry and built-ins, Codex hook/worker policies, Host ingress and conversation capture, Codex replay, optional initialization status, CLI status integration, and the narrow legacy task-batch identity path. Source-only review; no tests, transitions, live services, or project-state writes were performed. Serena Python symbols were unavailable, so I used scoped UTF-8 source reads/searches.

## Findings and current status

- **Resolved — supplied Codex derived fields could diverge from the canonical event.** The first implementation compared only a few top-level fields; Host used nested `source.agent` and forwarded `payload`. The policy now checks supplied derived fields and source fields against the canonical mapping, and conversation messages compare participant/content/source/turn/delivery/parent fields (`codex_adapters.py:23-37, 43-48`).
- **Resolved — provider-supplied raw identity controls could alter receipt/dedup keys.** The initial Host passed native scope, stability, ID, and version claims to RawIngressKernel before denying provenance. Policies now validate identity controls; invalid claims are persisted in a deterministic rejected-identity namespace and then denied before derived effects (`host.py:1011-1041`; Codex rules in `codex_adapters.py:12-14, 59-61`). The raw kernel remains unchanged; its working-tree diff is empty and its SHA-256 matches the investigation record.
- **Resolved — replay could promote a raw receipt with forged envelope identity.** Replay now rebuilds canonical Codex identity and checks its raw event ID, payload hash, and stored source/native fields before any replay effect (`session_replay.py:142-156`).
- **Resolved — partial native envelopes could fall back to the normalized Runtime adapter.** `_ingress_envelope` now classifies partial native claims separately; the Host records them as raw-only and denies routing (`host.py:634-643, 1039-1041`).
- **Resolved — optional Codex status callback failures could break generic status.** Callback exceptions now return the bounded unavailable result (`host_integration.py:28-34`).
- **Resolved — custom policies could accidentally trust unvalidated raw identity fields.** The base policy now fails closed, while RuntimeLegacy and built-in Codex policies explicitly validate their identity fields (`provider_adapters.py:29-34, 86-98`; `codex_adapters.py:12-14, 59-61`).
- **Resolved — worker transcript metadata could claim an arbitrary participant.** Host now checks the participant against the adapter’s fixed launcher identity or the current task owner before authorization succeeds; the adapter also validates worker turn, delivery, and parent-message fields (`host.py:859-875`; `codex_adapters.py:96-122`).

The exact provider/adapter registry is immutable and rejects invalid or duplicate registrations (`provider_adapters.py:49-76`). Unknown adapters are retained as private raw receipts and denied before derived effects. The new provider modules contain no event-driven imports or executable paths. Codex-specific mapping remains in the adapter; Host uses neutral policy methods. The optional Codex repair action remains explicit. Legacy batch membership requires exact run/task membership and declared per-task process, with the exception limited to an unpinned `task-batch-execution` run (`work_context.py:290-302`).

No unresolved blocking source finding remained after reviewing the latest fixes. This verdict does not certify the primary-owned smoke/regression results; those were not independently run here.
