# Уточнение следующей задачи: токены и затраты

2026-10-22. Пользователь выбрал эту существующую карточку следующей после
evolve-20261002-27. Это дополнение к планированию, не начало реализации.
Карточка остаётся open, planning_only, writer=false, без product scope/capsule.

Первичный предполагаемый канал — драйвер агента: получать фактические usage
счётчики из поддерживаемых данных агента/провайдера и передавать их в PF.
На исследовании подтвердить источники для каждого поддерживаемого драйвера;
отделять измеренные данные от оценок. Не вычислять токены по длине текста.

Требования оператора:
- Сохранять usage в ходе задачи и итог, привязывая запись к проекту, Run,
  Assignment, попытке, агенту, драйверу, провайдеру и модели.
- Учитывать все попытки, включая ошибки и прерывания; хранить доступную разбивку
  input/output/cached/reasoning с точным смыслом счётчиков конкретного источника.
- Отличать приращения от накопительных снимков, дедуплицировать повторную
  доставку, восстановление и повторный сбор результатов. Один запрос считается
  один раз; одна и та же категория токенов не суммируется дважды.
- Показывать суммарные токены и денежные затраты по проекту, с разрезами по
  задачам, агентам и моделям. Отдельно показывать полноту доступных данных.
- Недоступный usage или неизвестную привязку не превращать в нулевой расход;
  сообщения без надёжной идентичности не приписывать произвольной задаче.
- Стоимость, сообщённую провайдером, отличать от расчёта PF. Для расчёта хранить
  валюту, версию/дату тарифа, модель и используемые категории; отсутствие тарифа
  означает неизвестную стоимость. Исторический расход не пересчитывать молча
  по сегодняшней цене. Проверку актуальных тарифов выполнить в будущей задаче.
- Связать usage с журналами попыток без публикации сырых приватных логов.

Будущая приёмка: реальные/зафиксированные driver receipts и контрольные события,
повторная доставка и restart/reconnect, частично поддерживаемые метрики,
неуспешные попытки и межпроектная изоляция; сверка итогов задач с итогом проекта
и проверяемым расчётом стоимости. Точный исполняемый scope оформить отдельно.
