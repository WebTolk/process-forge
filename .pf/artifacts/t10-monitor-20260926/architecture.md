# T10: архитектура, решения и план реализации

D01: новый tools/pf_runtime/monitor.py владеет только bounded collection, allowlist projection, pure screen rendering и terminal loop. CLI `monitor` подключает его лениво; main обходит диагностический operation wrapper, который может писать. Existing runtime status/start/stop APIs не меняются. Worker dispatch и Core flow не зависят от viewer.

D02: выделить чистую classify_lifecycle из service.inspect_lifecycle без изменения условий существующего caller. Monitor использует bounded state/lock reads, bounded PID probe и числовой loopback /readyz. Не вызывать /status, load_token, host.load_state/iter_agent_presence/update_stale, не перечислять project roots. Это честный небольшой read-only monitor, а не новая статистическая подсистема. Новый aggregate metrics contract остаётся отдельным T10 срезом.

D03: budgets: service и host cache максимум 1 MiB каждый, lock 64 KiB; JSON root object, malformed/oversize -> unknown; max 32 scheduler rows. Повторные state/lock reads вокруг probe ловят смену owner/endpoint; расхождение -> unknown, не fallback к прежнему ready. PID probe ограничен 0.75 секунды на PID; одинаковые PID проверяются один раз. Readiness probe deadline 0.75 секунды, response header/body ceilings, только GET /readyz по numeric loopback HTTP, без proxy/redirect/token. Никаких фоновых poll threads: одна последовательная проба, затем sleep interval 1–60 секунд (default 2), no catch-up burst.

D04: terminal view монохромный, `--no-color` поддерживается; control sequences используются только для TTY cursor positioning/alternate screen и не содержат внешнего текста. Windows VT разрешается для собственного output handle и исходный mode восстанавливается. Если VT или stdin TTY недоступны, один plain snapshot. JSON всегда once; no splash/ANSI. Unicode header с автоматическим ASCII fallback по encoding и `--ascii`; строки cropped по cell width, cols-1 предотвращает wrap; resize очищает экран, обычная перерисовка меняет лишь строки. Низкий экран сохраняет главный runtime status и выход; excess rows опускаются.

D05: stdin Q/Esc/Ctrl+C, POSIX cbreak или Windows msvcrt с восстановлением input mode; output restored in finally даже при collector exception/BrokenPipe. Никаких дополнительных subprocess кроме ограниченного read-only PID query на Windows. Принудительное уничтожение viewer ОС может помешать terminal cleanup, но не вызывает server stop.

D06: output schema `pf.runtime.monitor` v1 — timestamp, fixed source/freshness, runtime owner/lifecycle/health, installed CLI version отдельно от observed instance version, scheduler cached rows, registry counts/cache age, unknown activity and finite issues. Сырые errors, endpoint/auth, root paths, sessions identities и log content отсутствуют. Projections никогда не сохраняются автоматически.

Implementation plan: (1) pure service helper и collector/projection; (2) rendering/interactive loop и CLI flags/early read-only dispatch; (3) smoke using synthetic files, fake loopback endpoint, subprocess and terminal screen emulator; (4) EN/RU docs/links, smoke registry/checksums; (5) bounded regression/quality/live read-only observation, archive qualification where practical, primary review, handoff. Изменения только в scope orchestration. Не устанавливать обновление в shared Core для демонстрации команды.

Assurance: classification parity versus prior branches; missing/malformed/oversize/stale/future/owner-change/PID-failure/probe-failure states; endpoint redirect/remote and terminal injection rejection; actual subprocess offline/JSON/non-TTY/no-write; fake endpoint no /status and no POST; screen emulator checks shrink/resize/wide chars/cleared tails; q/Ctrl+C/finally restores; singleton/status existing regressions. Package inspection verifies new files/checksums, installed/shared operation remains read-only. Browser not_applicable; no external library/docs dependency introduced.
