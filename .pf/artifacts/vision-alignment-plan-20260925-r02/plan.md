## Что обязательно добавляется к общей приёмке

- MCP и source CLI согласованно оценивают тот же снимок и ресурсы, без
  отключения freshness/authorization проверок.
- Работоспособность MCP доказана реальным клиентом; успешного запуска
  сервера, HTTP health или initialize недостаточно.
- Детализацию можно выбирать для нужного компонента и периода; ошибку
  можно проследить по request/Work/session/snapshot идентификаторам.
- Severity не смешана с количеством диагностических данных; режим trace
  не выдаётся за стандартный уровень PSR-3.
- Любой профиль сохраняет приватность, чистый MCP stdout и обязательные
  процессные события/evidence.
- Сбой записи диагностического лога не скрывает исходную ошибку; потеря
  диагностик заметна. Ошибки обязательного журнала не игнорируются.
- Смена настроек логирования не требует редактирования кода; эффективные
  настройки и их источник доступны в диагностике.
- Продуктовая приёмка включает T08 и T09; CLI fallback не закрывает T08.

## Границы текущей поставки

Создана только новая ревизия плана. Задачи T01–T09 не реализованы этим Run.
Изменений продуктового кода, установки/перезапуска служб, Core/Workplace update,
публикации или глобальной миграции сейчас нет. Для T08 будущий scope должен
назвать конкретный сервер/клиент/конфигурацию, безопасную проверку, способ
отката и действительно необходимые live-операции; массовый restart не разрешён
автоматически. Public release по-прежнему требует отдельной квалификации.

Review/проверки и текущий статус документальной Work находятся в evidence
этой ревизии и её Run. Готовый план не равен утверждённой архитектуре продукта.
