# T03 capsule consumers: current source map

Read-only source map; line references are to the current source tree. `worker-capsule-field-map.md` compared the two builders; this note follows their preparation and validation consumers.

| Concern | Current source behavior | Compatibility consequence |
|---|---|---|
| Assignment checksum/status | The assignment CLI builder writes `capsule.assignment_checksum = sha256_file(assignment)` at `tools/processforge.py:13000-13012`. `existing_capsule_status` (`21222-21235`) hashes the entire current assignment YAML and returns fresh/stale; absent checksum is legacy. | Any byte-level assignment edit makes a checksummed CLI capsule stale, regardless of which field changed. No semantic projection/filter exists. |
| Lifecycle edits | `save_task` always changes `updated_at` and rewrites the YAML (`tools/processforge.py:13869-13871`). Work transition mutates evidence/notes and updated_at (`src/processforge_core/process_execution.py:453-468`), then stage/history/status/time on transition (`502-527`) and terminal status/result/time (`1084-1104`, `1287-1297`). | Status, stage, evidence, timestamps, iteration/result changes all alter the bytes covered by the current assignment checksum. This is true of any serialized preference or grant field too. T03’s acceptance that lifecycle/preferences do not invalidate intent requires a new stable intent projection or equivalent rule. Current Work capsules from `_write_capsule` (`process_execution.py:1321-1343`) omit `capsule.assignment_checksum`, so the CLI status function currently classifies them as legacy; they instead pin capsule bytes via assignment/run `process_execution.assignment_capsule_checksum`. Keep those two checksum meanings distinct. |
| Prepare/launch | `prepare_worker_run` (`tools/processforge.py:18959-19009`) applies optional model/reasoning overrides and `save_task`s them before calling `existing_capsule_status` (`18961-18975`). Fresh/legacy capsules proceed, stale fails with “create a new capsule intentionally”; a missing capsule is generated (`18977-18987`). It then writes a private workspace-access runtime file and creates the launch prompt (`18988-18993`). | A changed model/reasoning override can make an existing checksum stale immediately before the freshness check. Keep ordering/behavior in view if intent excludes runtime preferences. Legacy is deliberately accepted here. |
| Scope and outputs | `normalized_assignment_contract` normalizes files/read-files/forbidden, ownership and overlap, outputs and expected report (`tools/processforge.py:12818-12853`); builder serializes normalized fields (`13033-13049`, `13052-13055`). `render_worker_launch_prompt` reads current task fields, not capsule fields (`19975-20013`, `20031-20035`), and `command_task_doctor` checks task consistency/required outputs (`20955-20962`, `13965-14004`). | These are parallel task/capsule representations. Current worker prompt/doctor do not compare scope/output against immutable capsule; they consume task state. Preserve intended authority and compatibility between both sources. |
| Actions | Deprecated `compile_execution_context` resolves and stores `allowed_actions`/`forbidden_actions` in ECP and its optional legacy capsule (`tools/processforge.py:11922-11966`, `11973-11995`). The current `command_assignment_capsule` contract does not emit action fields. | Do not infer action parity from the legacy ECP shape. The inspected prompt, task doctor and preparation path do not consume capsule action fields. |
| Required sources | Current builder adds snapshot + assignment + declared sources (`12818-12822`), checks that required source/context-artifact paths exist (`12918-12930`), then emits sources in both context and top-level `required_sources` (`13034-13042`, `13052`). `capsule-doctor` does not recheck them (`13080-13110`). | Existence is a creation-time check, not a freshness/content pin. The Work builder currently emits empty context `required_sources` (`process_execution.py:1329-1337`); shared normalization must not accidentally treat this as equivalent completeness. |
| Capabilities | CLI builder resolves required/optional records and fails before capsule creation for missing required capabilities (`tools/processforge.py:12967-12979`); serialized as `capabilities` and legacy aliases (`13050-13055`). | `capsule-doctor` checks snapshot pin and latest-resource reproducibility only; it does not re-resolve capabilities (`13080-13110`). Work builder has no capabilities block (`process_execution.py:1325-1341`). |
| Workspace grants | Builder normalizes public refs and rejects private/raw paths (`tools/processforge.py:12849`, `12898-12916`, `12986-12989`), then emits `workspace_access` (`13043-13049`). Preparation resolves grants into private `workspace-access.json`: `workspace_access_runtime_document` prefers task grants, otherwise capsule grants, matches selected capsule `resolved_resources`, and resolves path refs (`9856-9911`); prompt directs workers to that file (`19979-20007`). | Runtime resolution needs both refs and resolved resources in the CLI capsule, or a deliberate replacement. Task grants can take precedence over capsule grants. Work capsules use resource bindings and omit `resolved_resources`/`workspace_access`; T02 `WorkResourceService` is a separate consumer, not this preparation path. |

Preserve these focused regressions while changing the shared builder/consumers: `smoke_worker_workspace_access.py` (public-ref/no-private-path checks, prompt/runtime grant), `smoke_capsule_pins_context_snapshot.py` (snapshot identity remains pinned), `smoke_parameter_assignment_capsule.py` (parameter values/source provenance), `smoke_multi_process_work_capsule.py` (single process and pinned definition), and `smoke_work_transition_updates_assignment_stage.py` plus the T02 resource-binding regression (stage/evidence lifecycle while capsule bytes remain immutable). Worker execution coverage also lives in `smoke_codex_worker_governance.py`, `smoke_codex_exec_worker.py`, and `smoke_worker_run_shell.py`.

Boundary: this map records existing consumers and their current source of truth. It does not prescribe the shared contract shape or propose source changes.
