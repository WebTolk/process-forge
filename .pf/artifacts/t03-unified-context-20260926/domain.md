# T03 domain rules

Execution contract v1 is a versioned block inside the existing capsule v1 envelope. It contains identity, normalized immutable assignment intent/checksum, pinned snapshot/process, explicit permission scope and actions, immutable required-source identities, declared outputs, capability requirements/resolution, workspace grants and T02 resource bindings. A standalone assignment without a run is explicitly identity.kind=assignment; it is readable but cannot masquerade as a governed Work.

Intent digest covers objective, execution security mode, allowed/forbidden paths/actions, ownership/non-overlap restrictions, required inputs/context-artifact declarations, outputs/report obligations, required/optional capabilities, workspace access, process reference, specialization and subagent/coordination restrictions, and assignment semantic parameters. Status, stage, stage history/evidence, timestamps, result, retry/session, provider/model/reasoning and diagnostic preferences are excluded. Invalid/malformed permission-bearing values fail explicitly, never normalize to broader access.

File permission requires an explicit matching allowlist and action, with denies first. Empty allowlists grant nothing. Output paths do not grant write access. Ownership cannot widen an explicit empty allowed_files list. Analysis/read-only/planning modes cannot enable product-write actions, even via contradictory defaults. PF's own lifecycle/evidence persistence is a service operation, not worker file permission.

Required immutable sources are bounded project-relative regular files; capture a byte checksum and enforce containment, existence, readability and size. Assignment and project snapshot references in the old envelope are navigation/lifecycle references, excluded from raw source hashing; explicit attempts to treat mutable lifecycle files as immutable inputs are diagnosed. Context artifacts declared mutable are not hashed as immutable corpus, and do not gain write permission. Missing required source/capability produces specific readiness blockers; optional ones remain optional.

Known complete contracts validate current assignment intent and pinned identity before reuse/read. Stage state is derived from the pinned process plus the current assignment and cannot change the immutable contract. Unknown versions fail explicitly. Legacy records remain readable; restrictive execution cannot infer missing permissions and requests a successor where facts are incomplete. No in-place migration or --force overwrite is allowed. Existing legacy raw checksums retain their historical meaning, not promoted to semantic intent.

Resolved absolute private paths remain outside the public contract. Resource bodies retain T02 declaration/budget/current-authorization rules. Source files and material grants do not silently refresh from current project selection. There is no OS sandbox claim.
