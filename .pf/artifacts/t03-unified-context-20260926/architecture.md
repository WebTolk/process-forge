# T03 architecture and implementation plan

Decision: local extraction to src/processforge_core/work_context.py. Its common normalized_assignment_contract accepts the existing core helper adapter for compatibility, and both builders call the same build_context_fields application function. It emits common scope/context/outputs/workspace/capability fields plus additive execution_contract v1; entry points retain only envelope/presentation/telemetry details. No general CLI reorganization.

The execution contract contains normalized intent/checksum, identity.kind (work or standalone assignment), snapshot/process summaries, selected resource IDs and digest of top-level T02 bindings, explicit scope/actions, immutable sources, outputs, capabilities, workspace grants, stable parameters, coordination and readiness. A checksum of the contract detects malformed self-consistency, while governed assignment/run capsule byte pins remain the external integrity anchor. Required fields/types and unknown versions are validated; no unknown-version fallback.

Normalization is declarative and IO-free except existing helper calls that only normalize values. It keeps the old envelope context's snapshot/assignment navigation references for compatibility but hashes only explicit immutable inputs. Scope is explicit; ownership cannot override an empty allowed_files. Actions are explicit or conservatively derived from declared paths/security mode; analysis modes always forbid product writes. Denies win. Portable path validation covers sources, scope/output paths, context artifacts and nested workspace path_ref values; no absolute resolution is serialized in this block.

Source capture: at most 128 immutable files, each at most 1 MiB, aggregate 8 MiB; no directories, globs, traversal, symlink components or special files. Root/file containment and stable read identity checked; required absence/change and supplied checksum mismatch are separate errors. Mutable context artifacts are declarations only. Lifecycle assignment/snapshot are never self-hashed as immutable input. Capability resolution uses existing registry providers, with required/optional distinction. Build reports explicit readiness blockers; worker preparation enforces required readiness. Primary lifecycle recording is distinct and may continue when worker scope is intentionally empty.

Process parameters come from pinned definition plus snapshot/task layers, not a changed live catalog. Stage parameters are a derived view from pinned definition/current assignment, excluded from intent. Standalone legacy-style assignments without run/process still produce readable assignment contexts with explicit incomplete Work readiness; no invented run. Current-stage obligations remain ProcessExecutionService's existing derivation.

Consumers: WorkResourceService validates complete intent/identity before reads when execution_contract exists; T02-only capsules remain narrowly readable via their existing proven bindings. ProcessExecutionService state exposes contract validation and transition rejects corrupted/changed complete intent before mutation, while legacy lifecycle stays compatible. existing_capsule_status uses semantic intent for complete contracts, raw checksum only for legacy history; preparation rejects unsafe legacy/incomplete execution and reports successor action. capsule-doctor reports validation. Models/reasoning/diagnostic preferences must not stale a new contract.

Immutability: both creation paths refuse replacing an existing capsule, including --force. If a recorded pin points to missing context, report explicit recovery/successor need rather than recomputing it. No migration writes or background refresh. CLI required-source/capability historical failure wording remains actionable while the shared contract carries stable reason codes.

Implementation sequence: primary common module + two builder adapters + precise consumers; bounded junior schema/docs changes only after module contract is concrete; then independent source review and disjoint parity regression author. New standalone execution-contract schema (scope refinement) embedded equivalently into capsule schema because existing validator only supports local refs. Update assignment actions schema and EN/RU contract docs. Register new smoke_work_capsule_contract_parity.

Assurance: same metadata through both entry points, empty/analysis scope, required source/capability negatives, lifecycle/preferences stable vs actual objective/scope/input changes, immutable force refusal and legacy/unknown diagnostics. Existing snapshot/parameter/specialization/override/workspace smokes plus T02 binding/multi-process/pinned transition, schema/public/checksum. T06 retains installed/actual-host qualification. No new release or infrastructure scope.
