# Почему pf.context медленный
Дата:2026-10-17. Диагностика чтения, без изменения продукта или служб.

Причина: два последовательных полных обхода накопленной истории Work. Сводка Work собирает все Run/assignments и лишь затем отбирает активные; отдельный автоматический выбор текущей Work заново строит каталог с историческими записями. Полные YAML-объекты заполняют ограниченные кэши, поэтому повторные вызовы продолжают разбирать почти все документы.

## Измеренные этапы
Фактически подключённый MCP ранее: median14.675с на5повторах. Точный installed handler воспроизведён в отдельном Python-процессе без запуска MCP server/main. Начальный bootstrap0.258с, первый полный handler13.908с. В отдельном вызове с лёгкими таймерами:

Два обхода заняли92.484% этого вызова. Время зависит от нагрузки; один разложенный вызов не заменяет прежнюю5-sample статистику. Snapshot2чтения суммарно0.003334с. Полный context service10.669с включает summary/check/readiness; вложенные значения не суммируются повторно.

## Конкретный путь
- tools/pf_runtime/mcp_server.py:144–152: service.context, затем отдельный ProcessExecutionService.state без run/assignment selectors.
- src/processforge_core/project/context.py:61: context вызывает общую work_summary.
- src/processforge_core/work/records.py:47,57,74: summary -> active_items -> items. items читает все runs и связанные assignments; фильтр active действует после сборки. Ответ active_work[:10] также ограничивается после полной работы.
- src/processforge_core/work/selection.py:21: без точной пары selector вызывается records(include_historical=True).
- src/processforge_core/work/record_catalog.py:36: каталог заново читает все run/task bodies и pending completion до выбора записи.
- src/processforge_core/documents/reader.py:22: эти пути используют полное load, не компактную проекцию полей.

Во время диагностики:580run.yaml и943физических assignment YAML. В профиле:4276вызовов полного YamlDocumentReader.load и1876load_assignment; это число вызовов, не уникальных файлов.

## Почему существующие кэши не спасают
Отдельная проверка двух обычных handler вызовов в одном процессе:

| Показатель | Первый вызов | Повторный прогретый |
| --- | ---: | ---: |
| Wall,с | 16.040936 | 16.430273 |
| Попадания общего parse cache | 4 | 4 |
| Фактические разборы | 2689 | 2689 |
| Вытеснения | 1821 | 2689 |
| Записи общего кэша после вызова | 868 | 868 |

Общий кэш достиг67093037байт из67108864(64MiB); лимит4096entries не достигнут. Request-scope cache достиг8388547из8388608байт(8MiB),665entries; его1584попадания не устранили2689разборов. Межзапросный LRU вытесняет записи практически с той же скоростью, с какой повторно заполняется. Bypasses=0: это подтверждённое вытеснение по бюджету, не отказ из-за неподдерживаемого типа.

- YAML load:2692вызова, cumulative20.891с.

Вложенные cumulative времена пересекаются и не суммируются как независимые этапы.

## Граница исправления
Объединить обнаружение Work в одну проверенную проекцию метаданных на запрос. Для стартовой сводки/выбора читать и удерживать необходимые поля идентичности,статуса,сессии,времени изавершения, без материализации всей stage_history/evidence каждого завершённого Run. Полные live bodies, capsule/gates и authority checks оставить выбранной Work.
При реализации сохранить правила выбора, historical/pending-completion recovery, ordering, payload ичестные неоднозначности; нельзя просто передать первый элемент compact active_work вместо native выбора.
Практическое направление: единый owner Work inventory/selection и компактные projections дляобщего reader, с существующей проверкой текущихбайтов. Рост лимитов кэша не устраняет два полных обхода; точное ускорение пока не измерялось, исправление этой Work не выполняется.

Доказательства:stage-times.json,cache-counters.json,profile-top-public.json; полные profile.json/handler.pstats и read-only scripts retained локально. Источники профилирования — установленный Core1.2.0(d5947ea); текущий source40581f2 имеет идентичную исполняемую основу. Actual connected MCP не перезапускался. Продуктовые файлы, история и капсулы не менялись.
