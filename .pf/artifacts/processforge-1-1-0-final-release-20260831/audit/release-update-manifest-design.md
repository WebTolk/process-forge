# Release update manifest design

Status: ready_for_review

## Boundary

The public release is `1.1.0`. Versions `1.2.0` and `1.2.1` were updater
fixtures only and must not appear as public releases. This slice changes the
release/update/documentation surface and the confirmed generic-onboarding hook
coupling; it does not introduce TUF or a new adapter/plugin architecture.

## Manifest roles

- `processforge-core.manifest.json`: archive-owned installed Core inventory.
- `processforge-1.1.0.manifest.json`: historical release sidecar generated by
  `release-pack`, never included in the ZIP whose bytes it hashes.
- `release/updates/processforge-stable.json`: mutable public discovery
  document using the existing normalized update manifest contract.

The `release/` tree is intentionally absent from `RELEASE_DIRS`, so both public
metadata files remain Git-visible while staying outside the archive.

## Publication model

1. Commit the final source surface and move local `v1.1.0` to that exact commit.
2. Build from a clean detached checkout of that tag.
3. Generate ZIP and release sidecar from the tagged source.
4. Publish ZIP and sidecar as immutable GitHub Release assets.
5. Commit the historical sidecar copy and stable-channel manifest on `dev`.
6. The stable manifest is served from the mutable raw `dev` URL and points to
   immutable `releases/download/v1.1.0/...` asset URLs.

This avoids both ZIP self-reference and Git commit self-reference. The tagged
source commit need not contain metadata generated from its own hash; the later
metadata commit records and distributes that provenance.

## Stable manifest contract

Use `schemas/normalized-update-manifest.schema.json` with one subject:
`core/processforge`. Version `1.1.0` is stable, non-prerelease, non-yanked, and
contains one ZIP artifact with immutable URL, byte size, SHA-256, and sidecar
provenance URL. Synthetic `1.1.1` discovery is exercised only with a local file
fixture.

## Required safeguards

- validate production manifest schema and URL shapes;
- reject production `example.com/processforge/*` URLs;
- assert `release/` metadata is absent from the ZIP;
- assert sidecar bytes match the ZIP and tag target;
- keep TUF explicitly future-only.
