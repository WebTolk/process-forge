# Независимое ревью PF App Server: серверное окно

Дата: 2026-10-19. Исполнитель: `pf-app-server-window-reviewer`.  
**Результат: `fail` — обнаружен один обязательный к исправлению дефект P2.**

Проверена исходная замороженная ревизия всех пяти участников. Финальный `assurance/report.md` прочитан до вынесения вердикта. Капсула, восемь поставленных входных артефактов и размеры/SHA-256 всех 17 зафиксированных файлов совпали с подготовленным входом.

## Обязательное исправление

**R1 — P2: ошибка вывода автоматического заголовка прерывает запуск сервера.**

Расположение:

- `tools/pf_runtime/console.py:42` — незащищённая запись заголовка;
- `tools/pf_runtime/console.py:45` — незащищённый `flush()`;
- `tools/pf_runtime/console.py:57` — аналогичная проблема диагностического вывода;
- `tools/pf_runtime/service.py:887` — исключение выходит до вызова `runtime.serve()` на строке 888.

Воспроизведение: вызвать настоящий `service.command_serve()` с `console=False`, `minimized=False`, подменив только `RuntimeProcess` и stdout. Поток сообщает `isatty() == True`, использует UTF-8 и выбрасывает `OSError` отдельно при `write()` либо `flush()`.

Оба варианта подтверждены независимым проверочным сценарием:

| Ошибка потока | Фактический результат | Вызовов `serve()` |
| --- | --- | --- |
| `write()` → `OSError` | Исключение выходит наружу | 0 |
| `flush()` → `OSError` | Исключение выходит наружу | 0 |

Заголовок теперь включён автоматически, поэтому дефект затрагивает обычный foreground-запуск без дополнительных флагов. Ранее при `--console=False` эта запись отсутствовала.

Проверка `tools/smoke_server_console.py:80–88` покрывает ошибки `isatty()`, но не ошибки записи и сброса буфера. Требуется защитить необязательный вывод, включая диагностику, и добавить проверки продолжения `RuntimeProcess.serve()` с сохранением его результата при ошибках `write()`/`flush()`.

## Проверки и публичная копия

Независимо выполнены успешно:

- 27 методов `smoke_server_console.py`;
- 26 Linux mock-тестов;
- schema, public-cleanliness и checksum validators публичной копии;
- сверка всех 1395 записей публичной копии по размеру, raw SHA-256 и release SHA-256;
- сверка 1076 разрешённых исходных тел с manifest; остальные 319 исходных тел вне разрешённого чтения не открывались.

Inventory совпадает с копией и manifest. Оба дополнительных исправленных checksum соответствуют телам из указанного baseline commit. Единственное объявленное исключение конфигурации в публичной копии рассмотрено; копия не доказывает исправление исторических findings рабочей среды.

Canonical operator/HTTP, autostart/MCP и singleton PASS подтверждены поставленным `primary/focused-checks-final.md` и финальным assurance-отчётом. Полные canonical запуски этим reviewer повторно не выполнялись. Ограничения ACL/liveness других workers не исправлялись изменением assertions.

## Пределы GUI-приёмки

Native Windows evidence подтверждает безопасный отказ для **невидимого неклассического HWND** с одним и двумя клиентами. Оно не подтверждает успешную минимизацию видимой classic console либо отказ именно видимой общей консоли.

Успешная минимизация настоящего Linux X11/xterm окна также не подтверждена. Реальный Scheduler-профиль не применялся. Эти открытые проверки приёмки отделены от воспроизведённого дефекта R1.

## Координация и передача

Собственные Agent Ledger check-in, heartbeat и checkout выполнены. Через PF chat переданы READ_ACK, FINDINGS с уточнёнными номерами строк и RESULT `msg_71abc194aaae469d934bf955f532ea59`.

Продукт, существующие assertions, службы и scheduled tasks reviewer не изменял; commit/push и делегирование не выполнялись.

Для принятия следующей ревизии необходимы исправление R1 владельцем, постоянные regression-проверки, обновлённые frozen hashes и отдельное независимое ревью исправления. Реальная GUI-приёмка остаётся открытой.
