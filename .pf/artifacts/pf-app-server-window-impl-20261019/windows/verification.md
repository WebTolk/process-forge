Статус реализации: ready_for_review. Результат проверки: pass_with_conditions.
Дата: 2026-10-19. Исполнитель: pf-app-server-window-windows, попытка 2.

Проверены только два принадлежащих воркеру продуктовых модуля. Использованы
Serena, существующий PF CLI и поставленная выдержка PF Python guidance.
Новые внешние источники знаний и зависимости не загружались.

Изолированные проверки: 25/25, успешный exit code 0.

- 19 проверок адаптера: отсутствие GUI-доступа при импорте; platform/TTY/None/
  закрытый stream; Windows Terminal/SSH/multiplexer; отсутствующий API/HWND;
  невидимое окно ConPTY; посторонний класс; неизвестный класс; нулевой список
  клиентов; общий/переполненный список; чужой PID; смена привязки; уже свёрнутое
  собственное окно; ошибка запроса; очередь без подтверждения; отложенное
  подтверждение; утрата владения; исключение native API.
- 6 проверок профиля: явный Python/pythonw не подменяется; разбор аргументов
  нативным CommandLineToArgvW сохраняет пробелы, Unicode и метасимволы;
  XML round trip и InteractiveToken/Hidden=false/IgnoreNew/PT0S; точное
  соответствие текущего действия; drift старого launcher/отсутствующего флага;
  preview не создаёт задачу. Scheduler заменён функциями-фикстурами.

Сценарий check_windows.py сохранён в области Windows-воркера .pf/tmp как
свидетельство. Рядом необходима его обычная фикстура:
profile with spaces & unicode-ПФ/tools/processforge.py. Это маркер наличия файла;
он никогда не запускается. Для воспроизведения запускают исходный сценарий на
месте либо сохраняют всю структуру каталога при копировании. Шесть проверок
профиля нельзя воспроизвести, скопировав только сценарий без фикстуры.

Нативные наблюдения получены отдельными краткоживущими Python-процессами с
CREATE_NEW_CONSOLE. Серверы, службы, monitor и Scheduler не запускались.

Оба процесса завершились с кодом 0. Нативно подтверждён безопасный отказ для
предоставленного невидимого неклассического HWND. Проверки истинной минимизации
видимого классического окна и отказа именно видимой общей консоли выполнены
только с mock. Реальная GUI-приёмка остаётся открытой; Task Scheduler профиль
не применялся. Свидетельства native_probe.py и native-*.json сохранены в той же
области .pf/tmp.

Первая версия подготовки profile-фикстур использовала TemporaryDirectory:
19 проверок адаптера прошли, шесть profile-проверок дали 12 ошибок подготовки/
очистки из-за ограниченных ACL временных каталогов. Обычная разрешённая фикстура
устранила зависимость, после чего все 25 проверок прошли. Шесть пустых каталогов
сохранены как свидетельство этой ошибки окружения. Попытка их не рекурсивного
удаления отклонена политикой выполнения с причиной blocked by policy; права
доступа и инфраструктура не менялись.

Продуктовый код стабилен после первоначальной реализации. Интеграция, постоянные
smoke-проверки, независимый review и task commit находятся у primary и назначенных
им исполнителей. Windows-воркер не делегировал работу и не выполнял commit/push.
