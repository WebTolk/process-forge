# Новый цикл после выпуска 1.2.0

Пользователь разрешил продолжить ООП-рефакторинг после публикации 1.2.0 в обоих
remote. Оба релиза опубликованы, точный тег и файлы проверены; каналы обновлений
работают. Исходники main в обоих remote содержат один обычный merge-коммит.
GitHub PR6 имеет статус MERGED; GitVerse PR1 сервис оставил open/merged:false,
хотя код уже слит. Этот статус не объявлять решённым и не менять в этом цикле.

Сначала выяснить фактическое состояние архитектуры и кода. Четыре native PF
shell-воркера на gpt-6.1-sol ultra исследуют непересекающиеся ответственности:
архитектура/границы монолита; прикладные библиотеки; установка/обновление;
MCP-инструменты/ресурсы. Основной агент сопоставляет аргументы и принимает решения.
Независимый ревьювер с чистым контекстом проверяет завершённую реализацию.

Цель PF: стабильная расширяемая система, работающая в простом файловом режиме и
подготовленная к будущему веб-управлению множеством рабочих мест, устройств и
самостоятельных либо связанных проектов. Классы вводить ради границ ответственности
и заменяемых зависимостей; сохранять выпущенные CLI/MCP-контракты, ошибки, форматы,
порядок и поведение. Не превращать каждую функцию в класс и не добавлять зависимости
без обоснования. Предложения пользователя и воркеров оценивать по аргументам.

Исследовательская волна читает актуальный код и документы и пишет только собственные
отчёты/временные материалы. Продуктовые изменения начнутся после согласования доменов
и архитектуры основным агентом, в новых явно ограниченных областях Work.
Сначала локальная документация и PF-знания Python; для актуальных сведений о внешних
библиотеках — официальные первичные источники. Не использовать архивные копии Python
из .pf/artifacts, .pf/dogfooding или старых временных распаковок как текущий код.

Для анализа символов использовать доступную Serena; не запускать полную индексацию
архивов. При недоступности — ограниченный rg/AST с записью ограничения. Разрешены
только read/write-artifact и собственные scratch-файлы по капсуле. Не запускать
вложенных агентов, полные релизные наборы, установку/обновление, сервисы или публикацию.
Не менять ACL и не обходить ограничения окружения. Все временные файлы — в .pf/tmp.

Предыдущие отказы удаления старых concepts/audit-каталогов и обновления checkpoint
не обходить. Основной агент отдельно убирает только разрешённые неактивные распаковки
и worktree после сохранения нужных доказательств. Чужие изменения сохраняются.
