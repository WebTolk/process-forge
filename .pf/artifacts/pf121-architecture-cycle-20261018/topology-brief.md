# Воркер 1: архитектура и границы монолита

Прочитай общий team-brief и приложенные знания Python из PF. Исследуй текущий
код после 1.2.0 и всю относящуюся к архитектуре документацию. Для управляемых корней
сначала PF work-search/work-resolve с точными селекторами; для символов — Serena.
Не сканируй архивные Python-копии. Исторические планы отличай от принятой реализации.

Отчёт должен содержать перечень архитектурных источников с оценкой актуальности,
карту фактических OOP-сервисов/адаптеров и оставшихся ответственностей монолита,
конкретные противоречия документов коду и рекомендуемые следующие три небольших
среза рефакторинга. Для каждого среза укажи файлы/символы, контракт, зависимости,
проверки эквивалентности и непересекающееся владение файлами. Сравни решения с
целью файлового режима и будущего управления несколькими рабочими местами,
устройствами и проектами. Не предлагай универсальные контейнеры ради контейнеров.

В этой волне только исследование: не изменяй продукт или существующие документы,
не запускай полные наборы, инфраструктуру или вложенных агентов. Пиши только
`.pf/artifacts/pf121-oop-topology-20261018/report.md` и собственный
`.pf/tmp/pf121-oop-topology-20261018/`. Отчёт на русском: сначала факты с путями и
символами, затем предложения и открытые вопросы. Не выдавай анализ за реализацию.
