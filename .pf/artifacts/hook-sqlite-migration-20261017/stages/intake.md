# Scope и brief

Дата: 2026-10-17. Основание: прямое поручение пользователя и последующее объяснение смысла журнала.

## Результат

1. Проектное SQLite-хранилище событий и сырых хуков с индексированным поиском ID, чтением порциями и транзакционной записью.
2. Два независимых параметра PFConfig: сохранение сырой диагностической копии хука и сохранение структурированной истории событий проекта. Глобальные defaults и проектное переопределение каждого поля; отсутствующее значение наследуется, явные true/false переопределяют. Изменение действует без рестарта. Существующее поведение по умолчанию сохраняется: оба вида записи включены.
3. Отключение истории относится ко всем её деталям, а не только к hook-derived событиям. Рабочие YAML-состояния, доставка сообщений, идентичность принятых событий и необходимые verification facts не должны зависеть от этого переключателя. Реализация должна вынести действительные служебные зависимости из необязательного журнала.
4. Временный PF-owned мигратор файлов: явный запуск, без удаления/переименования оригиналов, повторяемый перенос с отчётом о повреждениях и конфликтах. Возможность удаления мигратора после завершения перехода.
5. Удалить полные перестройки истории и всех obligations из обычного ingress. Тяжёлые действия не удерживают транзакцию журнала.

## Границы

Один проект хранит события всех его участников, различаемых по агенту/сессии/Work. Разные проекты изолированы. Один нейтральный внутренний ingress и доверенный реестр адаптеров сохраняются. Перенос всех подсистем PF в БД, новая CMS/plugin framework, UI журнала и полный новый execution engine не требуются. Переписка и существующий chat transport должны продолжать работать; структурированная история связывает сообщения и действия, сырые provider payloads остаются отдельной необязательной копией.

Установленный Runtime продолжает использовать прежний Core до отдельного управляемого переключения. Source-проверки и миграции fixtures проходят в task-specific tmp. Не выключать реальные процессы, не повторять обновление устройства 1.2.0.

## Приёмка

- Нет сканирования накопленной истории для обычной вставки/дубликата.
- Нормализованные envelopes и сообщения сохраняют смысл/ID; повторная доставка не повторяет эффекты.
- Все комбинации глобальных флагов, наследования и проектных переопределений работают независимо, включая live reload и удаление overrides.
- Отключение журналов сохраняет выполнение Work, актуальность проверок и обмен сообщениями.
- Читатели и doctors используют SQLite, не застывший NDJSON.
- Мигратор сохраняет порядок/ID/данные, не изменяет исходники и сообщает об ошибках; повтор не создаёт дубликатов.
- Шесть конкурентных источников, подтверждённые commit, восстановление и быстрый поиск проверены; любые показатели времени сопровождаются условиями измерения.
- Собственный коммит и одинаковый readback SHA обоих remotes; остаточные device-layer действия явно отделены.
