# Миграция журналов PF на SQLite

Статус: исходники реализованы, проверены и доставлены. Коммит `5e710da914e90888ca8fc8092f066e34b7388808` подтверждён в origin/dev и gitverse/dev. GitVerse использовал токен без браузерной авторизации.

Добавлены проектные SQLite-журналы событий и сырых хуков. Уникальные ID, индексы и короткие транзакции заменяют перечитывание NDJSON. Хук больше не пересобирает историю команд и стадии; неизменный такт Runtime не разбирает YAML задач и не хеширует все результаты.

PFConfig получает независимые `logging.raw_hooks` и `logging.events`, оба по умолчанию true. Глобальные значения находятся в configuration.yaml рабочей среды; проектные nullable-переопределения — в .pf/configuration.yaml. Изменения применяются при следующем обращении без перезапуска. Необходимые ID, незавершённая обработка и последние факты проверки остаются рабочим состоянием при выключенной истории. Существующие стенограммы переписки сохраняют собственного владельца.

Временный tools/migrate-hook-journals.py выполняет предварительный анализ без создания проектной БД, а с --apply потоково переносит старые события проекта и относящиеся к нему сырые записи. Исходники и ID сохраняются, повторный запуск не создаёт дублей. Повреждения требуют явного --skip-invalid; конфликты ID блокируют перенос. Незавершённая миграция закрыта для обычного чтения и записи.

Прошли проверки шести независимых источников, 100000 строк истории с индексным поиском, отката и повторной обработки, изоляции проектов, 36 сочетаний настроек, изменений конфигурации на лету, миграции с повреждениями/конфликтами/прерыванием/изменением источника, доставки сообщений и восстановления завершения Work без истории. Затронутые Runtime/CLI/Work проверки и полный набор схем, чистоты поставки и контрольных сумм прошли на отдельном дереве HEAD с собственными изменениями.

Доказательства: stages/assurance.md, stages/delivery.md, checks/*, source-manifest.json, publication-proof.json. Основной Work и отдельный Work двух шаблонов вернули run_completed. Независимое ревью не заявляется: обе capsule запрещают subagents; проверку выполнил основной агент.

Установленный Core, работающий Runtime и подключённый MCP не обновлялись; реальные журналы устройства не переносились. Снижение CPU на живом устройстве пока не измерено. Порядок управляемого переключения сохранён в device-cutover-handoff.md. Проверка PF 1.2.0 остаётся отложенной.
