# Idempotency and Replay Contract

## Статус

B1 закрывается как planning contract: ниже зафиксирован provider-neutral контракт raw identity, idempotency, duplicate delivery, replay и совместимость с текущим normalized-first поведением. Код не изменялся.

## Основание

Master prompt требует сначала определить canonical ingress API, raw envelope, storage, dedupe/idempotency, routing, replay, offline fallback, concurrency и security до расширения `codex_hooks.py` (`задания/process-forge-central-agent-event-ingress-master-prompt.md:78-91`). Raw-first инвариант: minimal validation -> durable raw append -> durable receipt -> normalization -> routing/chat/ledger/project events/projections (`задания/process-forge-central-agent-event-ingress-master-prompt.md:275-290`). Первый slice должен сохранить текущие normalized `SessionStart`/`SessionEnd`/`PostToolUse` semantics, добавить raw journal, central ingress, fallback, raw capture и replay smoke (`задания/process-forge-central-agent-event-ingress-master-prompt.md:1257-1273`).

Дизайн v2 уже задаёт цепочку provider payload -> Core ingress -> durable workplace raw append -> receipt -> derived sinks (`.pf/artifacts/central-agent-event-ingress-20260814/central-event-ingress-design-v2.md:23-36`), native envelope и receipt fields (`.pf/artifacts/central-agent-event-ingress-20260814/central-event-ingress-design-v2.md:40-77`), storage shape с `raw_event_id` (`.pf/artifacts/central-agent-event-ingress-20260814/event-storage-layout-v2.md:21-61`) и replay rule missing-only с deterministic normalized ids (`.pf/artifacts/central-agent-event-ingress-20260814/event-routing-policy-v2.md:82-92`). Review B1 верно указывает, что не хватало точного состава key/hash, duplicate receipt semantics, collision policy и deterministic chat IDs (`.pf/artifacts/central-agent-event-ingress-20260814/central-event-ingress-design-review.md:8-20`).

## 1. Canonical Raw Identity

`raw_event_id` вычисляется только в Core ingress, до raw append и до любой нормализации.

Canonical identity document:

```json
{
  "contract": "processforge.raw-identity.v1",
  "provider": "<provider>",
  "adapter": "<adapter>",
  "native_event_type": "<native_event_type>",
  "identity_mode": "native_id|payload_fallback",
  "native_id_scope": "<provider|adapter|session|project>",
  "native_event_id": "<stable provider id or null>",
  "source_session_id": "<only when native_id_scope=session or fallback>",
  "source_project_ref": "<only when native_id_scope=project or fallback>",
  "payload_version": "<payload_version>",
  "raw_payload_hash": "sha256:<canonical raw_payload hash>"
}
```

Canonical serialization rules:

- input must be a JSON object before receipt; malformed/non-object envelope is rejected before raw receipt;
- strings are normalized to Unicode NFC;
- object keys are sorted recursively;
- arrays preserve provider order;
- null values are preserved, not omitted;
- JSON is serialized as UTF-8 with no insignificant whitespace;
- `received_at`, transport name, Runtime PID/port, local filesystem paths, diagnostics and retry metadata are excluded from identity;
- `raw_payload_hash = sha256(canonical_json(raw_payload))`;
- `raw_event_id = "raw_" + sha256(canonical_json(identity_document)).hexdigest()` using the full 64 hex chars.

This keeps duplicate provider deliveries stable even when transport or receipt timestamp differs.

## 2. Native ID Priority and Fallback

Priority order:

1. Use `native_event_id` when the adapter declares it stable for the provider event type.
2. If the provider ID is scoped, include the declared scope inputs:
   - provider/global: no session/project scope in identity;
   - session-scoped: include `source_session_id`;
   - project-scoped: include validated `source_project_ref`;
   - adapter-scoped: include `adapter`.
3. If `native_event_id` is missing, blank, known unstable, or only locally generated by the adapter, use `payload_fallback`.
4. In `payload_fallback`, identity uses provider, adapter, native event type, source session/project refs when present, payload version, and `raw_payload_hash`.

A provider-native ID must not be invented from current Codex pre-normalized `event_id`. The current Codex string `codex:{hook}:{session_id}:{turn_id}:{tool_use_id}` is a legacy normalized key, not a raw native ID.

## 3. Duplicate Raw Receipt

Raw receipt fields stay compatible with design v2:

```text
raw_event_id
accepted
deduplicated
raw_location
normalized_event_ids
chat_message_ids
routing_status
diagnostics
```

Semantics:

- first valid raw identity:
  - `accepted=true`
  - `deduplicated=false`
  - append exactly one complete NDJSON raw line or no line on failure
  - write/update raw id index
  - route derived effects
- repeated delivery with same `raw_event_id`, same identity hash and same `raw_payload_hash`:
  - `accepted=true`
  - `deduplicated=true`
  - do not append a second raw line
  - return the original `raw_location`
  - run missing-only derived repair for that `raw_event_id`
  - never duplicate project events, Ledger effects or chat messages
- duplicate receipt may complete derived effects missing after a crash between raw append and routing.

This matches routing requirements: dedupe must prevent duplicate project events, Ledger activity and chat messages (`.pf/artifacts/central-agent-event-ingress-20260814/event-routing-policy-v2.md:56-67`) while replay after raw append must complete derived routing without duplicates (`.pf/artifacts/central-agent-event-ingress-20260814/event-routing-policy-v2.md:108-120`).

## 4. Collision and Poisoned Events

Collision checks are mandatory in the raw id index. Index record stores:

```text
raw_event_id
identity_hash
raw_payload_hash
shard
line_or_offset
received_at
routing_status
```

Policies:

- same `raw_event_id` + same `identity_hash` + same `raw_payload_hash`: valid duplicate.
- same stable native identity but different `raw_payload_hash`: poisoned duplicate. Do not overwrite the original raw record, do not route derived effects, store the conflicting payload under private `runtime/agent-events/errors/poisoned/`, return `routing_status=quarantined`, diagnostic `native_id_payload_conflict`.
- same `raw_event_id` but different `identity_hash`: hash collision. Do not route derived effects, store under private `runtime/agent-events/errors/collisions/`, return `routing_status=quarantined`, diagnostic `raw_event_id_hash_collision`.
- malformed envelope or oversized payload beyond configured limits: reject before receipt; no raw id is assigned.
- normalization failure after raw append is not data loss; raw remains replayable, as required by design v2 (`.pf/artifacts/central-agent-event-ingress-20260814/central-event-ingress-design-v2.md:112-120`).

## 5. Derived IDs and Idempotency Keys

Every derived effect has a deterministic idempotency key derived from `raw_event_id`, normalizer/router identity, version and semantic target.

Base derived key document:

```json
{
  "contract": "processforge.derived-id.v1",
  "raw_event_id": "<raw_event_id>",
  "derived_kind": "<normalized_project_event|ledger_effect|chat_message|chat_event>",
  "processor_id": "<normalizer-or-router-id>",
  "processor_version": "<version>",
  "semantic_target": "<stable sink-specific target>"
}
```

### Normalized Project Events

Default:

```text
normalized_event_id = "evt_" + sha256(canonical_json(derived_key)).hexdigest()
project_event_id = normalized_event_id
project_event_idempotency_key = "project-event:" + project_id + ":" + normalized_event_id
```

For the first Codex compatibility slice, supported legacy Codex mappings must preserve current event IDs:

- current adapter builds `event_id = codex:{hook}:{session_id}:{turn_id}:{tool_use_id}` (`tools/pf_runtime/codex_hooks.py:46-70`);
- current host `stable_event_id(raw)` hashes that value to `evt_<sha256(raw)[:32]>` unless it already starts with `evt_` (`tools/pf_runtime/host.py:364-370`);
- first implementation must compute the same legacy normalized event ID for `SessionStart`, `SessionEnd` and `PostToolUse` so existing dedupe and smoke expectations do not regress.

The new derived key index must still store the mapping:

```text
raw_event_id -> legacy_normalized_event_id
```

Future non-legacy mappings use the default full derived hash ID.

### Ledger Effects

Ledger effects are derived effects, not raw identity. Idempotency key:

```text
ledger_effect_key =
  "ledger:" + effect_kind + ":" + project_id + ":" + session_id + ":" + normalized_event_id
```

`effect_kind` examples:

```text
check_in
heartbeat
checkout
```

A repeated delivery or replay may re-evaluate Ledger routing, but it must skip the effect when `ledger_effect_key` is already recorded as applied. Current host executes Ledger before appending the process event only when duplicate is false (`tools/pf_runtime/host.py:589-593`); the new Core path must preserve that externally visible no-duplicate behavior while moving the duplicate decision to raw/derived idempotency.

### Chat Records

Manual `chat-record` behavior is preserved: current writer creates `message_id = msg_<uuid>` (`tools/processforge.py:10525-10548`) and emits `chat.message.recorded` metadata with `content_ref`/`content_hash` and private privacy (`tools/processforge.py:10569-10597`).

Automatic provider chat capture must not use random UUIDs. It must use:

```text
chat_message_id =
  "msg_" + sha256(canonical_json({
    "contract": "processforge.chat-message-id.v1",
    "raw_event_id": raw_event_id,
    "processor_id": chat_router_id,
    "processor_version": chat_router_version,
    "session_id": session_id,
    "message_role": message_role,
    "provider_message_id": provider_message_id_or_null,
    "content_hash": content_hash
  })).hexdigest()[0:32]
```

Chat idempotency key:

```text
chat_message_key = "chat-message:" + project_id + ":" + session_id + ":" + chat_message_id
chat_event_key = "chat-event:" + project_id + ":" + chat_message_id
```

Transcript append must first check `chat_message_key` or existing transcript `message_id`. Repeated provider delivery returns the same `chat_message_id` and must not append a second transcript line. The existing ChatService/transcript model remains the only chat sink; no `ChatLog` entity is introduced (`.pf/artifacts/central-agent-event-ingress-20260814/central-event-ingress-design-v2.md:122-142`).

## 6. Replay and Checkpoints

Replay uses raw journal as source of truth. It never rewrites raw records.

For each replayed raw record:

1. Load raw by shard/line/index.
2. Recompute expected derived plan for the selected normalizer/router version.
3. Compute deterministic IDs and idempotency keys for every expected project event, Ledger effect and chat message.
4. Check existing sinks and derived indexes.
5. Append/apply only missing derived effects.
6. If an existing derived ID has different content hash than the recomputed effect, quarantine as `derived_id_content_conflict`; do not overwrite.
7. Advance checkpoint only after every expected effect is present, skipped as unsupported/deferred, or quarantined.

Checkpoint files follow the existing layout (`runtime/agent-events/checkpoints/...`) and include `last_raw_event_id`, shard/offset, normalizer version and completion time (`.pf/artifacts/central-agent-event-ingress-20260814/event-storage-layout-v2.md:112-132`). Replay must support session, project, provider, time range and raw event id range (`.pf/artifacts/central-agent-event-ingress-20260814/event-storage-layout-v2.md:132`).

If project/session cannot be safely resolved, raw remains accepted and replay status is `pending/unsupported_mapping`; later replay after Ledger resolution may route only still-missing derived effects (`.pf/artifacts/central-agent-event-ingress-20260814/event-routing-policy-v2.md:71-92`).

## 7. Runtime-Up / Direct-Fallback Equivalence

Runtime `/event` and direct fallback are transport adapters only. Both must call the same Core ingress with the same `NativeAgentEvent` identity inputs.

Equivalence requirement:

```text
same provider payload
+ same provider/adapter/native_event_type/native_event_id/payload_version
= same raw_event_id
= same derived ids
= same idempotency keys
= same routing decisions
```

Transport-specific fields may be stored in provenance/diagnostics, but must be excluded from canonical identity. This fixes the current split where Codex dispatch prefers `service.runtime_request(..., "/event", event)` and falls back to `host.ingest_event(event, None, core)` (`tools/pf_runtime/codex_hooks.py:87-107`), while design v2 requires both paths to delegate to one Core ingress and not change idempotency, raw storage, routing or Ledger semantics (`.pf/artifacts/central-agent-event-ingress-20260814/central-event-ingress-design-v2.md:156-168`).

## 8. Existing Behavior to Preserve

First implementation must preserve:

- `SessionStart/startup -> agent.session.started`;
- `SessionStart/resume -> agent.session.resumed`;
- `SessionStart/compact -> agent.session.compacted` without inventing Ledger check-in;
- `SessionEnd -> agent.session.ended`;
- `PostToolUse` with `tool_name == Bash` or empty/default -> `agent.command.completed`;
- `PostToolUse` with `tool_name != Bash` -> `agent.tool.completed`;
- current project routing and mismatch denial;
- current duplicate observable behavior for supported normalized events;
- current private chat transcript layout and `chat.message.recorded` metadata event;
- current manual `chat-record` UUID message IDs.

The mapping is confirmed in `codex_hooks.py` (`tools/pf_runtime/codex_hooks.py:21-24`, `tools/pf_runtime/codex_hooks.py:46-70`) and in design v2 preservation rules (`.pf/artifacts/central-agent-event-ingress-20260814/central-event-ingress-design-v2.md:103-110`). Current host duplicate check is normalized-event based (`tools/pf_runtime/host.py:589-598`); first implementation must preserve outcome while relocating the contract to raw/derived idempotency.

## 9. First Implementation Changes Required

1. Add Core raw ingress API accepting `NativeAgentEvent`.
2. Implement canonical JSON serialization and `raw_event_id` derivation as `processforge.raw-identity.v1`.
3. Add workplace raw journal writer with interprocess shard lock or equivalent atomic append; current `threading.RLock` is process-local only (`tools/pf_runtime/host.py:23-31`, `.pf/artifacts/central-agent-event-ingress-20260814/event-storage-layout-v2.md:134-142`).
4. Add raw id index with identity hash, payload hash, shard/offset and conflict detection.
5. Make duplicate receipt return original `raw_location` and run missing-only derived repair.
6. Move Runtime `/event` and direct fallback to the same Core ingress.
7. Change Codex adapter from pre-normalized event dispatch to raw native envelope dispatch, while preserving legacy normalized event IDs for supported mappings.
8. Add deterministic derived id/key helpers for project events, Ledger effects and automatic chat messages.
9. Extend ChatService append path to accept deterministic `message_id`/event id for automatic capture, while leaving manual `chat-record` UUID default intact.
10. Add replay planner/checkpoint processing that routes only missing derived effects.
11. Add focused tests required by routing policy: duplicate delivery, Runtime-up/down equivalence, crash-after-raw replay, unknown raw capture, cross-project mismatch, and raw/chat privacy (`.pf/artifacts/central-agent-event-ingress-20260814/event-routing-policy-v2.md:108-120`).

## Decision

Implementation may proceed after this contract is copied into the planning artifact. The blocker condition is resolved at design level: raw identity is deterministic, duplicate raw receipts are defined, collisions/poisoned events are quarantined, all derived sinks have deterministic idempotency keys, replay is missing-only, Runtime-up/down paths are equivalent, and current `stable_event_id` plus UUID manual chat behavior have explicit compatibility rules.
