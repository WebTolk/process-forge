# Central Event Ingress Design

## Статус

Планировочный дизайн без реализации. Кодовые изменения запрещены. Дизайн нейтрален к провайдерам и требует независимого архитектурного ревью до начала первого среза.

Ограничение: в capsule не переданы тексты трех audit artifacts и master prompt; подтверждение их приемки не проверялось.

## Цель

Ввести центральный Core ingress для событий агентов, который принимает события из разных runtime/adapters, нормализует их, сохраняет, маршрутизирует, устраняет дубли, поддерживает replay и не содержит hardcode конкретных доменов или провайдеров.

## Core API

Минимальный публичный Core API:

```text
EventIngressService.submit(raw_event, ingress_context) -> IngressResult
EventIngressService.submit_batch(raw_events, ingress_context) -> BatchIngressResult
EventQueryService.get_event(event_id) -> EventRecord
EventQueryService.list_events(filter, cursor) -> EventPage
EventReplayService.plan_replay(filter, options) -> ReplayPlan
EventReplayService.execute_replay(replay_id) -> ReplayResult
EventRoutingService.resolve_routes(event_record) -> RouteDecision[]
EventDedupeService.compute_key(event_record) -> DedupeKey
```

Core принимает только provider-neutral структуры:

```text
RawIngressEvent:
  source_type
  source_id
  observed_at
  event_type
  subject_ref
  payload
  headers
  trace

IngressContext:
  run_id
  assignment_id
  actor_ref
  adapter_ref
  trust_level
  received_at
```

Запрещено в Core:
- GitHub/GitLab/Joomla/WebTolk/etc. specific branches.
- provider-specific payload assumptions outside adapter normalization.
- routing by private local paths.
- direct filesystem writes outside storage abstraction.

## Event Model

Canonical event:

```text
EventRecord:
  event_id
  canonical_version
  source:
    type
    id
    adapter
  subject:
    kind
    ref
  type
  lifecycle_state
  payload
  metadata
  trace:
    correlation_id
    causation_id
    parent_event_id
  timing:
    observed_at
    received_at
    persisted_at
  integrity:
    payload_hash
    dedupe_key
    signature_status
```

`event_id` should be generated by Core after normalization. Provider IDs remain metadata, never primary identity.

## Storage Layout

Logical stores:

```text
events/
  by-id/{event_id}.json
  by-run/{run_id}/{event_id}.ref
  by-assignment/{assignment_id}/{event_id}.ref
  by-type/{event_type}/{event_id}.ref

indexes/
  dedupe/{dedupe_key}.json
  correlation/{correlation_id}/{event_id}.ref
  replay/{replay_id}.json

dead-letter/
  rejected/{event_id-or-hash}.json
  poison/{event_id}.json

audit/
  ingress-decisions.ndjson
  routing-decisions.ndjson
  replay-decisions.ndjson
```

Storage contract requirements:
- append-first for accepted events;
- immutable canonical record after persistence;
- corrections emitted as new events;
- index rebuild possible from canonical records;
- dead-letter records must preserve rejection reason and raw hash.

## Routing Policy

Routing is rule-driven configuration, not code branches.

Route decision inputs:
- event type;
- subject kind/ref;
- run/assignment context;
- source trust level;
- lifecycle state;
- metadata tags;
- explicit project/resource routing configuration.

Route decision output:

```text
RouteDecision:
  route_id
  target_kind
  target_ref
  action
  priority
  reason
  delivery_mode
```

Default policies:
- unknown event type: persist + dead-letter route for review, no destructive action;
- missing assignment/run context: persist with degraded metadata, route only to audit;
- untrusted source: persist as quarantined unless explicitly allowed;
- duplicate event: link to original, do not re-route side effects by default.

## Dedupe

Dedupe key should be deterministic:

```text
dedupe_key = hash(
  source.type,
  source.id,
  adapter_ref,
  event_type,
  subject.kind,
  subject.ref,
  normalized_payload_hash,
  observed_at_bucket_or_provider_event_id
)
```

Rules:
- if provider event id exists, include it as strongest source identity;
- if absent, fall back to normalized payload hash plus time bucket;
- dedupe detects exact duplicates, not semantic equivalence;
- duplicate handling emits an ingress decision with `duplicate_of`.

## Replay

Replay must never mutate historical records.

Replay flow:
1. Select immutable event set by filter.
2. Create `ReplayPlan` with frozen event IDs and route policy version.
3. Dry-run route decisions.
4. Execute only if approved by caller policy.
5. Emit replay audit records and replay-result events.

Replay options:
- `dry_run`
- `from_event_id`
- `limit`
- `route_policy_version`
- `skip_duplicates`
- `quarantine_on_error`

Replay safety:
- side effects disabled by default;
- replay must mark causation as replay-derived;
- poison events stop current replay segment, not the whole store.

## Security

Ingress boundary requirements:
- validate schema before persistence;
- cap payload size;
- reject or quarantine executable content where not expected;
- hash raw and canonical payloads;
- record actor/source trust level;
- never persist private workspace access paths into public artifacts;
- redact configured secret fields before routing or reporting;
- keep raw provider payload isolated from normalized public reports.

Authorization:
- adapters may submit only under declared `adapter_ref`;
- replay requires explicit permission separate from submit;
- route execution requires target-specific permission;
- audit reads may be broader than payload reads.

## Minimal First Slice

First implement only:

1. Canonical event schema and validation.
2. `EventIngressService.submit`.
3. Append-only local storage abstraction.
4. Dedupe index with exact duplicate detection.
5. Audit log for accepted/rejected/duplicate decisions.
6. Static routing policy with audit-only target.
7. Read API by `event_id`.
8. Replay dry-run planner without side effects.

Out of first slice:
- external provider adapters;
- live hook loading;
- side-effect delivery;
- semantic dedupe;
- UI;
- migration of existing historical logs.

## Acceptance Gates

Before implementation:
- independent architecture review completed;
- audit artifacts acceptance confirmed by orchestrator;
- storage and routing artifacts aligned with this design;
- first-slice API names and schema versions approved.

For first implementation slice:
- schema validation tests;
- duplicate submit test;
- rejected malformed event test;
- persisted record immutability test;
- route audit-only decision test;
- replay dry-run does not create side effects.

## Risks

- Capsule does not include audit artifacts, so this report cannot verify prior acceptance.
- No allowed read files were granted, so project-local naming and existing runtime code were not inspected.
- Storage path layout is architectural, not confirmed against existing `.pf` implementation.
