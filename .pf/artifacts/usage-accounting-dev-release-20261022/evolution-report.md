# Release/install experience

The accepted source feature needed only a refreshed shipped checksum inventory.
A sparse clean candidate avoided importing unrelated refactor work. Initial sparse
preparation omitted the required hooks projection; schema/release checks caught
that omission before packaging, and it was restored from the same committed tree.
No product workaround or checksum exemption was added.

PF supplied current Work/context, Python/practices/packaging knowledge, Core/OOP
placement boundaries and project QA policy. Direct native CLI/source inspection
supplied release/updater and installed behavior evidence. Device memory helped
locate the earlier update order; all current statuses and hashes were verified.

Source, archive, installed CLI, new App Server and existing connected MCP hosts
were treated as distinct evidence. Same-byte source quality evidence was retained,
clean-source tests and archive checks repeated, then installed read/replay and
driver capture tested. Synthetic probe data used an isolated workplace.

One native apply sufficed. The updater preserved configuration and common data,
created nine preimages and left nothing to repair. Do not reinstall this same
archive to address the separate lifetime of a preexisting MCP host process.
No further task is started after delivery and native lifecycle completion.
