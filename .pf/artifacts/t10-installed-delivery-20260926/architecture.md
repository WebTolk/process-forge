# Delivery architecture and plan

1. Capture source payload, capsule/snapshot/config and old installed manifest hashes; verify old owned hashes and nine-path delta against previous clean delivery. Create a new detached worktree from that commit under the declared scratch root, copy only reviewed source delta, commit candidate locally. Preserve main checkout and prior worktree.
2. Run checksum/public/schema and monitor/runtime focused checks in clean candidate. Use official release-pack and release-archive-test quick. Inspect extracted manifest and run monitor against extracted payload. Retain candidate/archive/extracted as durable local evidence.
3. Review official core-update plan with explicit Core/Workplace roots. Reject blockers, conflicts, removals or unexpected changes/migration. Capture old manifest and relevant runtime/config evidence.
4. In release-delivery only, use installed official core-update apply --confirm. If Runtime must reload, inspect its current command line and reliable activity evidence, stop only through runtime stop, apply once, verify backup and installed ownership, then runtime start with original options. No manual copy fallback. If activity cannot be established, deliver files without disrupting the running owner and record reload boundary truthfully.
5. Verify status, all installed file hashes, monitor --json/--once, focused installed smokes, Workplace doctor, protected-byte preservation and task doctor. Record exact update/candidate/archive/backup identities. Existing archive qualification covers unchanged T01-T06 payload; new tests focus on nine-file delta. Browser not_applicable: terminal CLI and package only, no browser UI changes.

Rollback is an operator recovery boundary, not automatic. On failure use core-update repair read-only classification and retained backup/control manifests; do not retry or hand-copy. User authorization covers this update and necessary ordinary correction, not unrelated data deletion or configuration removal.
