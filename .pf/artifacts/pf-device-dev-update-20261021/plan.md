# Обновление устройства до текущей dev-сборки

Основание: прямое поручение пользователя обновить текущее устройство и запустить
PF monitor для проверки. Один исполнитель; завершённая Work uptime не открывается.

1. Проверить установленные Core/Workplace/Runtime и отсутствие незавершённого
   обновления. Проверить принятую ветку dev и доказательства uptime.
2. Собрать точный dev-архив из отдельного чистого Git-снимка. Использовать
   прежнюю полную квалификацию неизменённых исходников; выполнить штатный plan.
3. Сохранить локальные настройки и штатные резервные копии; применить Core и
   объявленную миграцию Workplace один раз с подтверждением оператора.
4. Проверить манифест, хеши, отсутствие incomplete update и doctor-workplace.
   При необходимости безопасно перезагрузить существующий Runtime для нового
   build; наблюдать готовность, здоровье и полноту статистики отдельно.
5. Запустить установленный монитор в видимом интерактивном терминале и проверить
   формат uptime, а также отдельный JSON-снимок. Текущий MCP-хост не завершать.
6. Закрыть PF Work, зафиксировать только её артефакты и отправить один коммит в
   оба dev remote; GitVerse через существующий токен. Проверить SHA и остановиться.

Публичная капсула содержит только относительные проектные пути. Обновление
устройства выполняется явно разрешёнными операторскими командами PF с их
собственными проверками и ownership manifest. Локальные пути, сырые журналы,
резервные копии настроек и снимки окна остаются в приватных материалах задачи.
Исходники проекта, опубликованная alpha1 и несвязанные dirty/staged данные
сохраняются. Широкая проверка ZIP, разработка продукта и новые задачи не входят.
