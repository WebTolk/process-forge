# Выводы после операторского обновления

История worker-запусков исчерпывает наблюдательный бюджет и не должна
определять доступность текущей работы. Постоянная архитектурная задача уже
сохранена как pf-database-layer-and-journals-20261021: оперативный учёт
отдельно от истории, общее хранилище/модели, драйверы и PFConfig, проверка
роста до 400 000 запусков. Новая реализация здесь не начиналась.

Для текущего окна: неполное наблюдение не равно нулю. Нужно сохранять точную
причину budget и отдельное полное наблюдение; обход guard выполняется только
по явному решению пользователя. Разрешение получено и отнесено к одному
согласованному stop/apply/start, а не к изменению политики будущих остановок.

Версия архива, установленного manifest, встроенная CLI-константа, Runtime
protocol label и реально загруженная сборка MCP требуют раздельного учёта.
Константа CLI 1.2.0 при архиве 1.3.0-alpha1 сохранена как наблюдение для
улучшения процесса обновления; совпадение установленных файлов проверено
по всем 1460 записям. Runtime новый; старые MCP-процессы требуют reconnect.

Нативный backup старого manifest сохраняет модель JSON, меняя сериализацию.
Это нужно отличать от точного побайтового backup. До apply дополнительно
сохранены исходные байты manifest и затронутых файлов; native preimages
9/9 совпадают побайтово.

Часть ранних авторских текстовых записей имела повреждённую кириллицу.
Исходные записи сохранены; итоговые отчёты подготовлены в UTF-8 по нативным
receipts. Для записи русского текста использованы файлы UTF-8, а не
передача через несовместимую кодировку PowerShell.

Терминальные Work не возобновлять. Альтернативная кодовая Work отменена
штатно по выбранному пользователем операторскому варианту. Следующий шаг
после доставки отчёта — остановиться; последующую проверку MCP выполнять
после реального перезапуска хоста оператором в актуальном контексте.
