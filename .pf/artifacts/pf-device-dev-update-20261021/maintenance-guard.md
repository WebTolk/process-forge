# Окно обслуживания Runtime

Первоначальный `server stop` без force получил 409
`runtime_busy_or_activity_unknown`. Проверка обхода остановилась на 513-й
записи каталогов при лимите 512, после 44 чтений за 0,0631 секунды;
остальные лимиты тогда не были исчерпаны. Это неполнота наблюдения,
а не доказательство текущей занятости.

Последняя полная проверка перед остановкой использовала установленный
нативный observer, не меняя параметры работающей службы: два проекта,
333 чтения файлов, включая cache, 4596 записей каталогов, running=0,
coverage=complete, ошибок нет, около 0,93 секунды. Свежая статистика
аренд: held=0, coverage=complete.

На прямой вопрос о `server stop --force`, подготовленном dev-обновлении и
мониторе пользователь ответил «Да, разрешаю». Каноническая остановка
завершилась успешно. Принудительное завершение процессов не применялось;
MCP-хост не останавливался. После одной установки запущен новый Runtime.

Force обошёл busy guard только для согласованного окна обслуживания.
Общие бюджеты и код guard сохранены. Будущее устранение зависимости
текущей работы от истории зарегистрировано отдельно; эта установка
не заявляет масштабирование наблюдения до 400 000 записей.
