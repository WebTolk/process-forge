# Проверки обновления dev на устройстве

1. Источник — точный принятый dev-коммит с чистым Git provenance. Поставляемые
   исходники совпадают с уже полностью квалифицированным uptime-кандидатом.
2. Нативный Core plan: нет incomplete update, блокировок, локальных конфликтов
   и незаявленных миграций Workplace. Хеш архива фиксируется до apply.
3. Одна попытка apply; резервные копии старых затронутых файлов и манифеста
   должны существовать и совпадать с исходными байтами. Неопределённый исход
   исследуется по status/journal, без повторной установки.
4. После установки: версия, source commit, все управляемые файлы по SHA-256,
   отсутствие incomplete update, `doctor-workplace`, сохранение конфигурации.
5. Нативный запуск Runtime из установленного Core, подтверждение процесса,
   readiness, health, интервала и свежести scheduler/metrics. Неполнота
   статистики фиксируется отдельно от здоровья службы.
6. Установленный `monitor --once` и JSON: uptime в календарном формате
   `гг/мм/дд/чч/мм`, числовой uptime_seconds сохранён. Видимый интерактивный
   монитор остаётся работающим и обновляет наблюдение.
7. Реальный подключённый MCP не приравнивается к свежему CLI или Runtime;
   его уже загруженная версия указывается отдельно. Контекст не обновляется
   только ради расхождения версий.
8. PF Work, контекст и обязательные артефакты проверяются штатными doctors.
   Новый код продукта отсутствует: применимы прежние полные PF-тесты и Python
   QA неизменённых исходников, плюс новые проверки установленного устройства.
9. Коммит содержит только собственные артефакты этой Work; несвязанный index
   сохраняется. Оба dev remote проверяются после push по точному SHA.
