# Поисковая база отделена от основной SQL-базы PF

2026-10-24. Требование оператора принято; продуктовая реализация не начата.
Связано с `pf-database-layer-and-journals-20261021` и уточняет
[предыдущую ревизию](../storage-topology-20261024/requirements.md).

## Принятая топология

1. Одна основная SQL-база рабочего места для бухгалтерии и оперативных данных
   PF, с отдельными таблицами предметных областей. Текущий backend — SQLite.
2. По одной основной базе внутри `.pf` каждого проекта для проектных нужд.
3. Поисковый индекс знаний находится в отдельной базе, независимо от основной
   бухгалтерской/оперативной SQL-базы. Объединение поисковых таблиц с основной
   базой PF не допускается. Это явно согласованная граница нагрузки и хранения,
   а не разрешение создавать самостоятельную базу на каждую подсистему.

Статус «размещение поиска не выбрано» из предыдущей ревизии заменён этим
решением. Нынешний FTS5 уже хранится в отдельном производном файле; его
перестроение и жизненный цикл не должны затрагивать бухгалтерские данные.
Конкретные будущие backend/пути и дальнейшая консолидация основных данных
требуют отдельного исполнения, без автоматического переноса или удаления.

## Адаптеры SQL — отдельный незавершённый результат

Бухгалтерия остаётся SQL-потребителем. Требование будущего переключения
SQLite на MariaDB и другие согласованные SQL-backends сохраняется, но
готовых переключаемых адаптеров в текущем Core нет. Существуют конкретные
SQLite-репозитории и общие SQLite-хелперы; они не являются готовым DAL.
`ResourceIndexBackend` относится к поиску и не является SQL-драйвером.

Для будущего переключения нужны backend-neutral контракт репозиториев,
конкретные SQL-адаптеры и их выбор при композиции/через конфигурацию, управление
схемой/транзакциями и явная миграция данных. Переключение профиля не переносит
существующие данные автоматически. Идемпотентность, типы, ошибки, целостность,
backup/restore и conformance каждого backend должны быть проверены отдельно.
Конкретная SQL-библиотека, схема профиля и реализация драйверов не выбраны.

Будущий RAG и его retrieval backend развиваются отдельно от SQL бухгалтерии.
Ни vector DB, ни embeddings, ни RAG pipeline этой ревизией не реализуются.
Права на проекты/ресурсы, file-only и действующие CLI/MCP сохраняются.
Планировщик запуска агентов не относится к этому уточнению.

Проверенное состояние адаптеров: [adapter-readiness.json](adapter-readiness.json).
Полный отчёт и границы проверки: [report.md](report.md).
