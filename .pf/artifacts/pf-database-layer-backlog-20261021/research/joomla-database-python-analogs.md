# Python-аналоги Joomla Framework Database

Дата: 2026-10-21. Документальное сравнение по уточнению пользователя:
общий доступ к БД нужен не только внутренним журналам PF, но и процессам.
Требуются драйверы, конструктор запросов, типы и выполнение без обязательного ORM.
Конкретная библиотека не выбрана и не установлена.

## Что сравнивалось

Локально проверены DatabaseFactory, DatabaseInterface, QueryInterface,
PreparableInterface и ParameterType пакета Joomla Database из справочного Core.
В официальном API Framework проверены фабрика, builder и интерфейс БД.
Это самостоятельный уровень доступа к БД; для его аналога не требуется
воспроизводить MVC Joomla.
[DatabaseFactory](https://api.joomla.org/framework-3/classes/Joomla-Database-DatabaseFactory.html),
[QueryInterface](https://api.joomla.org/framework-4/classes/Joomla-Database-QueryInterface.html),
[DatabaseInterface](https://api.joomla.org/framework-4/classes/Joomla-Database-DatabaseInterface.html).

## SQLAlchemy Core

По набору функций это близкий аналог: SQL-конструктор, описание таблиц и типов,
диалекты СУБД, привязка параметров, соединения, выполнение и транзакции.
Core можно использовать без ORM. Он входит в дистрибутив SQLAlchemy, поэтому
внешняя зависимость SQLAlchemy при таком выборе сохраняется.
[Core](https://docs.sqlalchemy.org/en/21/core/index.html),
[соединения и транзакции](https://docs.sqlalchemy.org/en/21/core/connections.html).

| Joomla Database | Соответствие в SQLAlchemy Core |
| --- | --- |
| Фабрика драйвера и параметры подключения | create_engine, Engine, диалект и выбранный DB-API клиент |
| DatabaseQuery / QueryInterface | select, insert, update, delete и композиция SQL-выражений |
| Типы параметров и bind | Типизированный bindparam и система SQL-типов |
| Описание таблиц и полей | Table, Column, MetaData и типы столбцов |
| Выполнение и получение строк | Connection.execute, Result, mappings/scalars |
| Начало/commit/rollback транзакции | Engine.begin / Connection.begin и контекст операции |

Типы Integer, String, Boolean, DateTime, Numeric и другие участвуют в описании
схемы и обработке значений. Тип bind-параметра может выполнять преобразование
перед передачей значения драйверу.
[Типы](https://docs.sqlalchemy.org/en/21/core/type_basics.html),
[bindparam](https://docs.sqlalchemy.org/en/21/core/sqlelement.html#sqlalchemy.sql.expression.bindparam).

## PyDAL

Ещё один прямой кандидат — самостоятельный Database Abstraction Layer,
первоначально выделенный из web2py и используемый py4web. Предлагает DAL,
Table/Field, запросы, адаптеры, диалекты и преобразование значений; записи
представляются объектами со словарным интерфейсом. Фреймворк web2py подключать
не требуется. PyDAL остаётся отдельной внешней зависимостью; серверной БД нужен
соответствующий клиент.
[Проект](https://github.com/web2py/pydal),
[назначение пакета](https://github.com/web2py/pydal/blob/master/pyproject.toml),
[DAL py4web](https://py4web.com/_documentation/static/en/chapter-07.html).

Есть типы Field и средства миграции. При работе с существующими таблицами
документация требует migrate=False. Для PF включение миграций должно быть
явным действием обслуживания, отдельно от обычного доступа процесса к данным.
[Типы и миграции](https://py4web.com/_documentation/static/en/chapter-07.html#legacy-databases-and-keyed-tables).

## PyPika

Это более узкий кандидат: конструктор SQL-выражений. Он не заменяет весь
комплект подключения, выполнения и транзакций Joomla Database. При его выборе
остальной слой придётся собирать отдельно.
[Официальное описание](https://pypika.readthedocs.io/en/latest/).

## Два смысла типизации

Типы столбцов, bind-параметров и преобразование DB-значений в Python — одна
задача. Статические Python-аннотации, проверка структуры входа и типизированный
результат прикладной операции — другая. Наличие SQL-типа не обещает проверки
всех правил прикладной модели или полной статической проверки произвольного SQL.
В будущем сравнении нужно проверять оба требования отдельно.

## Уточнённое направление для PF

Вывод исследования: повторное использование доступа к БД в Core и процессах
не обязывает PF писать собственный SQL-конструктор и систему SQL-типов.
Можно выбрать готовый DAL/SQL toolkit и дать ему небольшой интеграционный слой PF.

- Общая инфраструктура БД доступна разным потребителям, включая процессы.
  Модели журналов являются одним из её клиентов.
- PFConfig содержит именованные локальные и удалённые подключения. Прикладной
  код получает выбранное подключение через общий сервис; секреты разрешаются
  на границе интеграции, не публикуются в описании процесса.
- Выбранная библиотека отвечает за SQL-выражения, типы, параметры и диалекты;
  PF — за конфигурацию, жизненный цикл подключения, границы использования
  ресурса и прикладные операции.
- Полное повторение API выбранной библиотеки собственным конструктором PF
  не является обязательным. Это отдельная стоимость, которую следует
  обосновывать требованиями, а не самим наличием нескольких потребителей.
- Для процесса, работающего с уже существующей БД, чтение описания таблиц
  и выполнение запроса не должны автоматически менять её схему.
- Совместимость драйверов, типы дат/чисел/JSON, особенности ключей,
  транзакции и миграции квалифицируются отдельно. Наличие общего API
  не устраняет ограничений конкретного backend.
- Требование 400 000 завершённых запусков и независимости оперативного
  учёта от истории сохраняется независимо от выбора библиотеки.

Первоочередные кандидаты для прикладного сравнения — SQLAlchemy Core и PyDAL.
Для выбора нужны небольшие отдельные пробы точных операций PF и процесса,
оценка поставки зависимостей и contract tests. Данное сравнение не заменяет
эти проверки и не подтверждает готовность миграции.
