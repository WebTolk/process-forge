# T07: доменная модель исходящих данных

Статус: proposed design, не действующий API. Область — передача из доверенного локального контура PF определённому получателю. Access authorization и disclosure authorization — независимые условия; успешное чтение ресурса не разрешает отправить его модели.

## Сущности и границы

| Сущность | Смысл |
|---|---|
| Source record | Неизменённые локальные bytes и закреплённые provenance/authorization; snapshot, capsule и prepared input остаются первичными |
| Data unit | Целиком проверяемая единица передачи: поле envelope, текст/файл, tool result, argv/env value, output/export field; имя/путь/идентификатор тоже являются данными |
| Classification | Базовый уровень плюс независимые теги, происхождение разметки и evidence детектора; отсутствие совпадения не означает public |
| Recipient | Запись доверенной конфигурации: principal/endpoint alias, remote/local, purpose, разрешённые классы, capabilities; значение из prompt не создаёт доверие |
| Policy binding | Закреплённые правила/версии детекторов и требования контроля в security intent successor Work; действующие запреты дополнительно проверяются перед каждым раскрытием |
| Disclosure decision | allow/redact/block плюс причина, область контроля, recipient/policy/input/output identity и локальная receipt |
| Outbound view | Производное представление с новым hash, безопасными псевдонимами и broker references; не новая capsule и не расширение прав |
| Enforcement capability | Проверяемая гарантия конкретного driver/adapter route: payload_only, mediated_session или isolated_local; декларация сама по себе недостаточна |
| Dispatch receipt | Обязательный локальный факт разрешённой попытки отправки и её результата; отличается от optional diagnostics и от результата выполнения Work |

Граница A: локальные original state/material/credentials, policy resolver, classifier и audit. Граница B: trusted launch/transport adapter и broker, выпускающие только approved view. Граница C: исполнитель, его инструменты, плагины и дочерние процессы. Граница D: внешний endpoint/получатель опубликованного артефакта. Remote SDK/CLI может быть локальным процессом по месту запуска, но получателем данных остаётся внешний endpoint.

## Классификация

Предлагаемые уровни: public, internal, restricted, secret, unknown. public требует явного основания (доверенная декларация/проверенный материал); неизвестное не понижается до public по отсутствию regex-срабатывания. confidential source, персональные данные и организационная политика задаются явно, а не угадываются из расширения файла.

Теги независимы от уровня: credential, personal_data, operational_path, project_identity, source_code, untrusted_instruction, opaque_payload. У одного поля может быть несколько тегов. Имена файлов, slug Work, команды, URL query, source hashes и ошибки подлежат той же оценке, что содержимое. Декларация источника может повысить строгость; противоречие с более строгой policy или достоверным detector finding не снимается input-разметкой.

secret/credential не передаются модели как значения. Для операции, требующей credential, отдельный разрешённый локальный инструмент получает credential через доверенный канал, не через model envelope, argv или возвращаемую диагностику. Это не право модели получить сам credential. Для restricted/personal_data допустим только явно описанный purpose/recipient и проверенное преобразование либо локальная обработка. Для unknown/unsupported unit строгая передача блокируется, даже если часть prefix прошла проверку.

## Правила решения

1. Проверить Work/context/attempt/stage, scope, текущую авторизацию, source integrity и достоверный recipient. Любой отказ здесь окончателен для операции; redact не даёт доступа к запрещённому источнику.
2. Получить эффективные ограничения как пересечение pinned policy и текущей policy. Current deny и locked restrictions побеждают. Ослабление требует нового security intent; смена endpoint/purpose/route требует новой подготовки попытки с разрешённым binding.
3. Проверить достаточность enforcement capability. Если запрошен контроль всей сессии, payload_only route блокируется. local_trusted — декларация доверия к получателю; isolated_local требует отдельно проверенного запрета внешнего обмена и ограничений файлов/процессов.
4. Разобрать ограниченную целую unit по поддерживаемому формату, классифицировать все поля/ссылки/метаданные. Не отправлять непроверенный хвост после достижения budget. Opaque/неподдерживаемый формат получает unknown и отказ в strict режиме.
5. allow выпускает только разрешённые bytes. redact выпускает новую производную с явной меткой преобразования; она повторно проверяется и получает свой hash. Если преобразование удаляет обязательный смысл objective/инструкции/контракта задачи, возвращается block: required_semantics_lost. Не обещать модели выполнить изменённую задачу как исходную.
6. Результат зависит от максимальной строгости единиц: обязательная заблокированная unit блокирует envelope; необязательная может быть исключена только по заранее разрешённому правилу с записью omission. Решение не выбирается голосованием детекторов.
7. До выпуска bytes сохранить обязательную dispatch receipt. Отказ журнала блокирует отправку; отказ optional diagnostics не меняет решение. Факт передачи не является подтверждением выполнения задачи или разрешением следующего чтения.

Ложное срабатывание снимается доказуемой узкой декларацией по конкретному detector/rule/material hash/recipient/purpose, с владельцем и сроком. Она не снимает scope denial, явный secret или locked запрет и не является глобальным disable. Решение оператора — отдельный policy факт, а не текст в запросе модели. Ни одна такая декларация сейчас не создаётся этой Work.

## Неизменность и аудит

Исходные capsule/intent/prepared bytes и collection receipts не редактируются. Производная ссылается на источник через локальную private map; внешнее представление получает непрозрачные per-attempt id. Прямые raw-content hashes, локальные пути и идентификаторы, в которых есть чувствительный текст, наружу по умолчанию не включаются. Hash производной подтверждает только bytes производной, не равен hash источника.

Audit хранит локальные Work/attempt/recipient alias/policy version, категории, rule ids, причину, размер, статус sent/denied/delivery_unknown, связь input/view hashes. В записи отказа нет найденного секрета или исходного фрагмента. Optional логгер может показывать краткое operational состояние; его off не отключает обязательный audit. Повторяющийся export не меняет исторический факт, что оригинальный doctor нашёл private path.

Передача на architecture: определить versioned binding и типы views, trusted broker/adapter enforcement, совместимость со старыми contracts, lifetime/лимиты и контракт ошибок; отдельно оценить что нельзя доказать из текущего API.
