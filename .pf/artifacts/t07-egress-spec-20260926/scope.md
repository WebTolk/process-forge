# T07: цель и критерии

Результат этой Work — проверяемая спецификация provider-neutral фильтрации данных при их передаче из локального доверенного контура получателю. Карточка: .pf/artifacts/vision-alignment-plan-20260925/tasks.md, T07; зависимости T01/T05 выполнены, T06 уже принята. Пользователь поручил продолжить план. Приоритет карточки P3 не меняется.

Вход: действующие prepared-input, Work/context/resource/provider contracts; фактические generic-shell/Codex launch paths; chat/diagnostic export; незакрытый случай локального пути в immutable delivery objective.

Обязательные результаты:

- R01: классификация данных, независимые признаки чувствительности и явная неопределённость.
- R02: получатель local/remote, уровень доверия, доступный способ ограничения исполнения; local не равнозначен offline.
- R03: определённая политика allow/redact/block, приоритет запретов, судьба обязательных данных и ложных срабатываний.
- R04: initial input и последующие file/tool/MCP reads, runtime environment, child process/network и возвращаемые/публикуемые артефакты.
- R05: неизменность исходного контекста и точная связь преобразованного представления с Work/attempt/policy/recipient без утечки исходных значений через audit.
- R06: границы общего Core и адаптеров, альтернативы, способ встраивания и честные уровни обеспечиваемого контроля.
- R07: конкретные проверочные сценарии для секретов, персональных данных, обходов, ложных срабатываний, всех драйверов и отказов.
- R08: отдельный implementation-plan с объёмом, зависимостями, допущениями и входными решениями до реализации.
- R09: связь с историческим metadata finding: санитизированная производная не переписывает capsule и не превращает её doctor FAIL в PASS.

Допустимые изменения: только объявленные T07 документы/доказательства/лог/передача и штатный lifecycle этой Work. Анализ существующего поведения подкрепляется точками исходного кода и хешами. Для будущей архитектуры используется явное обозначение proposed; вымышленные команды не выдаются за CLI.

Не входят: работающий privacy engine, обучение/подключение локальной модели, устранение старого doctor изменением истории, T10/терминальный монитор, удалённый веб, установка/перезапуск/публикация, повтор удаления сохранённых T06 каталогов.

Критерий готовности: документы отвечают R01–R09, нет противоречащих друг другу решений или заявлений о несуществующем контроле, схема примеров и ссылки проверены, источники/старые артефакты не изменены. Runtime smoke для ещё не написанного privacy engine и browser checks: not_applicable. Отдельно будут перечислены обязательные будущие runtime tests; документальная проверка их не заменяет.

Передача на investigation: изучить цепочки передачи и существующие меры защиты; не считать очистку chat/diagnostics защитой произвольного исполнения.
