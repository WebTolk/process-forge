# Порядок подготовки неизменяемого кандидата

Полный source suite выполняется на отдельном чистом Git worktree. Состав продукта зафиксирован commitc4d6649; source identity, LF и отсутствие tracked changes проверены повторно. Собрать предварительный канонический ZIP можно независимо от результата ещё выполняющегося source suite: release-pack сам проверяет layout/cleanliness/checksums и требует clean provenance. Кандидат не объявляется прошедшим квалификацию до завершения всех gates.

Для полезной проверки promotion metadata и прежнего клиента упаковка кандидата выполняется сейчас; source и consumer full suites остаются последовательными, supervisor-stress выполняется после source full. После упаковки повторно проверяются source identity и полная parity ZIP/source. Если исходники либо archive identity изменятся, все dependent metadata/results теряют применимость.

Это изменение порядка вспомогательной подготовки, без изменения scope, исходников или обязательных проверок. Публикационный порядок maintainer contract не выполняется заранее: публичного тега/assets/channel нет. Перед будущей публикацией tag должен указывать на этот точный commit; штатная сборка с него обязана воспроизвести проверенные байты либо новая фактическая SHA требует пересчёта метаданных и повторной квалификации.
