# ProcessForge 1.2.0

Промежуточная точка продолжающегося рефакторинга Core с накопленными исправлениями надёжности, хранения и производительности. Границы CLI/MCP и управляемой Work сохраняются; полное завершение программы ООП не объявляется.

- События проекта и нативные хуки хранятся в отдельных локальных базах SQLite с транзакционным приёмом и индексированным воспроизведением. Для прежней истории нужен явный контролируемый перенос; установка Core сама её не импортирует и не удаляет.
- Безопасный разбор неизменившегося YAML повторно используется в ограниченной памяти процесса. Чтение Work/context использует общие компактные метаданные, сохраняя актуальные проверки полномочий, закреплённые версии процессов и полную проверку выбранной Work.
- Работоспособность Runtime определяется выполнением планировщика; ошибки исполнителей и восстановления сбора остаются видимыми как результаты задач. Неполные метрики сохраняют сведения о покрытии и неизвестные значения.
- Автоматические Garage hooks включаются явно. Forge сохраняет обязательное управление; допущенные штатные хуки жизненного цикла выполняют регистрацию и завершение сессии.
- При ошибке публикации удаляется только собственный временный файл; прежний файл назначения и исходная ошибка сохраняются. Ранее зафиксированный результат и устойчивый отказ collect останавливают автоматическое повторение, сохраняя явное восстановление.
- Вход в проект использует корневой AGENTS.md и текущий контекст PF; существующие START-файлы, исторические версии процессов и капсулы сохраняются.

Перед обновлением прочитайте [порядок перехода](https://github.com/WebTolk/process-forge/blob/v1.2.0/docs/releases/1.2.0-migration.md) и [границы квалификации](https://github.com/WebTolk/process-forge/blob/v1.2.0/docs/releases/1.2.0.md). Сохраните резервные копии журналов и раздельно проверьте Core, Runtime и фактически подключённый MCP.

Проверки Windows не подтверждают Linux/macOS и все сочетания версий Python. Большая история может увеличивать нагрузку планировщика и стоимость приёма; замеры устройства относятся к его нагрузке.

Защищённая остановка может быть отклонена, если ограниченный наблюдатель не подтвердил полный простой по сохранённой истории исполнителей. Такой отказ сохраняется до полной проверки штатного состояния по операторскому порядку; неполные метрики не означают нулевые значения.

ZIP и отдельный манифест будут содержать точную привязку к исходному коммиту и окончательному SHA256. Канал stable обновляется после проверки неизменяемых файлов релиза. Обнаружение новой версии не разрешает установку: применение требует явного подтверждения.
