# Оценка версии 1.3.0-alpha1

Оператор выбрал `1.3.0-alpha1` 2026-10-20. Имя сохраняется именно в этом виде.
Это имя будущего альфа-кандидата; уже собранный контрольный dev ZIP содержит
прежнюю продуктовую версию 1.2.0 и не переименовывается в alpha без изменения
действительной release identity и новой упаковки.

## Решение по SemVer

`1.3.0` обоснован для накопленного цикла: публичные CLI/MCP контракты сохраняются,
есть совместимые улучшения функционала и значительный внутренний рефакторинг.
SemVer 2.0.0, пункты 7 и 9, допускает minor для существенных внутренних улучшений
и предварительный суффикс `alpha1`. Механический перенос классов сам по себе
не требует увеличивать minor; несовместимые изменения публичного API потребовали
бы отдельного решения о major. Источник: https://semver.org/.

Версии продукта, схем, startup contract и закреплённых процессов независимы:
выбор 1.3.0-alpha1 не разрешает массово менять исторические process pins/capsules.
Предварительный выпуск не должен заменять стабильный канал.

## Конкретная проблема механизма обновления

Проверен код принятого исходного коммита
`526c5d13e42e96693802760cce35fe896e208708`:
`src/processforge_core/resources/versioning.py: ResourceVersionPolicy.key`
принимает строку с суффиксом, но возвращает только три числовые компоненты.
`maintenance/versions.py: UpdateVersionSelectionPolicy.select` использует
именно эту политику при выборе более новой версии.

Исполненный read-only probe на чистом Git checkout дал:

| Сравнение | Фактический is_newer | Ожидание SemVer |
| --- | --- | --- |
| 1.3.0-alpha1 после 1.2.0 | true | true |
| 1.3.0-alpha2 после 1.3.0-alpha1 | false | true |
| 1.3.0 после 1.3.0-alpha1 | false | true |

Все три ключа 1.3.0-alpha1/alpha2/final равны `(0, (1, 3, 0))`.
Это отдельный существующий дефект выбора обновлений, а не результат исправления
контекста. Он не исправляется путём изменения VERSION или названия ZIP.
Чтобы альфа-пользователь штатно получал следующую альфу и final, до публикации
нужно ограниченное исправление сравнения предварительных версий с проверкой
stable/prerelease/build metadata, выбором каналов и сохранением остальных правил
ресурсного версионирования. Область текущей immutable Work этого файла не разрешает;
продуктовый код вне принятого context fix здесь не менялся.

## Источники и пределы

Сначала разрешён и изучен локальный `docs.python-packaging:root`, разделы
`version-specifiers.md` о prerelease spelling и Semantic versioning.
Уточняющая нормативная проверка выполнена по официальному SemVer 2.0.0.
Python packaging normalization не подменяет продуктовую версию и политику PF.

Здесь нет утверждения о публикации, alpha tag/assets, установленном Core или
принятии реальным подключённым MCP. Итог суммарных исходных проверок и решение
о выпуске будут записаны в delivery.md.
