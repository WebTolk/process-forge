# T07 implementation scope and acceptance

Implement the engine described by the existing T07 design, with qualification
of one bounded backend/OS scope and explicit unsupported routes. Deliver code,
schemas, CLI/API integration, EN/RU documentation, reproducible tests and an
installed Core package through official core-update. Native CLI isolation,
external providers or local models receive no guarantee without measured proof.

Required behavior: v2 successor security intent without mutating v1; v1 normal
compatibility and strict-egress rejection; explicit classification with allow,
redact, block, unknown, required semantics and narrow exceptions; immutable
views/opaque references; current-deny/identity reauthorization; durable pre-send
audit, nonce/budget reservation and delivery_unknown; file/tool mediation with
credential separation; derivative export with private provenance and unchanged
original doctor result; retention/ACL and adversarial acceptance A01-A28 with
source/archive/installed/connected-route evidence clearly separated.

Baseline/scope patterns: baseline.json. Product boundaries are new Core egress
modules, existing intent/context/prepared-resource/execution adapters and CLI,
their schemas/tests and targeted documentation/checksums. Any additional shared
file needs an explicit impact addendum before editing. Private evidence/logs,
handoffs and fixtures use this artifact directory and .pf/tmp. No global rule,
unrelated project, historical capsule/process definition or real diagnostic
profile modification. Existing T10/journal changes remain preserved.

I01 is a real feasibility gate before capability claims. If an enforcement mode
cannot close file/env/home/plugins/child/network bypass, record unsupported and
do not downgrade a strict request. The primary can choose a bounded broker route
whose execution model excludes independent native access; that decision still
needs adversarial route/OS evidence. Fake recipient proof is not proof that an
unrelated connected host or external executor is controlled.

Release criterion is implemented, tested behavior and precise limits, not a
design document or an empty schema. No estimate is an SLA. Real external model
traffic and publication are unnecessary; use synthetic fixtures. Ordinary
authorization to implement/install persists across this Work; no repeat user
approval is required for the standard qualified Core update.
