# T02 material binding implementation

Implemented the disjoint module `src/processforge_core/work_resource_material.py`.

- Public API: `MaterialError(code)`, `MaterialBudget`, `DEFAULT_LIMITS`, `canonical_fingerprint(value)`, `metadata_descriptor(row, reference)`, and `capture_material(row, root, reference, *, include_content=False, budget=None)`.
- `MaterialBudget.limits` returns a fresh plain mapping for the fixed request/per-resource ceilings. Budget counters accumulate across calls; material errors expose stable codes and no path-bearing message.
- `metadata_descriptor` validates explicit normalized policy (it rejects unspecified legacy fulltext defaults), hashes only canonical declaration fields and portable reference. Its canonical fingerprint uses UTF-8 JSON with sorted keys, `ensure_ascii=False`, and compact separators, matching the shared execution fingerprint format.
- `capture_material` returns an available binding with metadata/material fingerprints, declared generation fallback, portable reference, normalized indexing and sorted manifest. Metadata mode checks declared roots/sources but does not read body files; fulltext mode reads only declared matched text files, hashes the bytes read, enforces size/count/visited budgets and returns content only when requested. None mode emits no docs. Binding fingerprints are independent of `include_content`.
- Source paths/patterns are constrained relative to the trusted root; traversal rejects symlinks and escapes before file open. Unreadable, missing, racing/changed and over-budget cases are explicit. Duplicate fulltext paths are deduplicated; fulltext docs take precedence over metadata docs for a same relative path.

Verification: `python -B` AST/import and isolated temporary-directory checks passed for metadata/fulltext binding equality with and without returned content, metadata stability after body mutation, fulltext digest change after body mutation, canonical metadata fingerprint parity, source-relative include matching, invalid source rejection, budget rejection, empty declared fingerprint fallback and single-file roots. Before each open, components are re-resolved and rechecked for symlink/containment/canonical-path changes, then file identity is checked through the open descriptor before reading. No repository test suite, integrations, source files outside the owned module, checksums, PF transitions or main Work were touched by this worker.

Primary integration imports require no changes: `MaterialBudget().limits` supplies fixed limit metadata, and `metadata_fingerprint` equals `canonical_fingerprint(metadata_descriptor(row, reference))`. `capture_material(..., include_content=False)` and `include_content=True` yield identical bindings for both metadata and fulltext policies.
