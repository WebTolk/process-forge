# T02 architecture, implementation plan and decisions

Additive contract: new governed capsules receive top-level resource_bindings {schema_version:1, resources:[...], limits:{...}}. This is the resource component for T03's later shared execution_contract builder, not a claim that all T03 scope/capability fields are complete. Pin id/generation/metadata_fingerprint/material_fingerprint/material_kind/reference/indexing/manifest/status/reason. Existing v1 capsules remain byte-identical; no read-time reconstruction from current material. New Work startup records unavailable binding diagnostics instead of silently dropping a grant; the new read surface blocks it. T03 owns complete execution preparation obligations.

One application service in src/processforge_core/work_resources.py requires explicit run_id, assignment_id and context_id. It loads exact contained files, checks task membership/run identity, immutable capsule identity and recorded checksum, snapshot equality and pinned process definition/fingerprint, then derives the current stage subset. Never use latest-record selection. Current project freshness and current authorization are checked before reading material. All selectors and duplicate/malformed binding/subset cases fail closed. Read-only payloads use kind pf.work.search/pf.work.resolve, scope work_context, status ready/blocked, stable reason and identity/provenance. CLI exit nonzero on blocked; MCP returns the same structured domain result and retains existing session/project transport validation.

Pure material operations live in new src/processforge_core/work_resource_material.py (scope refinement: same bounded resource feature, disjoint junior ownership). Public API:
- MaterialError(code), with no private paths in its message.
- MaterialBudget with cumulative resources/files/bytes/visited counts and fixed limits.
- capture_material(row, root, reference, *, include_content=False, budget=None) -> (binding, documents). Row has canonical id and declared metadata/policy; root is a trusted caller-resolved Path; reference is a portable path_ref. Binding stores no absolute paths/content. Documents are ephemeral dictionaries {relative_path,title,content,mode,sha256}; content only when include_content=True. Caller resolves current authorization before passing roots.
- metadata_descriptor(row, reference) supplies canonical metadata/policy identity without filesystem reads, letting the service reject changed generations/policies before content access.

Reuse local_resource_search.normalize_indexing_policy and suffix/include matching contract. Implement bounded traversal rather than its forgiving generator, because exact binding cannot silently omit unreadable/oversize declared files. Fixed default ceilings per request: 64 resources, 2048 files, 32 MiB total bytes, 20000 visited entries; per file <=1000000 bytes, per resource <=256 files/8 MiB. Refuse invalid sources/escapes and symlink traversal; canonical containment checked before open. Read bytes once, hash those bytes, decode bounded text for ephemeral search; no persistent corpus copy. Metadata only hashes descriptor and checks declared root/source availability. None has no documents. Manifest sorted by relative path, with byte size/digest, deduplicated sources. Detailed unsupported/over-budget states remain explicit. Root relocation is permitted only through the same authorized portable reference with identical declared metadata and material.

Work search creates a bounded SQLite FTS5 :memory: table from verified documents and uses the existing quoted phrase/pagination rules. It never reads shared cached text by resource id alone. Resolve returns a portable manifest, material kind and authorized private local_root, with metadata navigation labeled as such. Both return resource_provenance suitable for attaching to artifact evidence; no mandatory journal writes on reads. T09 logs only request outcome/reason/identity metadata.

ProcessExecutionService._write_capsule calls the shared binding builder for newly created capsules. Source work.start/state add context identity/checksum for callers; selectors do not alter existing project APIs. New CLI work-search/work-resolve use --run, --assignment, --context-id and standard query/pagination/resource arguments. New MCP pf.work.search/pf.work.resolve declare equivalent required selectors. MCP configured/requested session conflict and project binding still run before service access.

Project navigation gets explicit scope project_context plus authorized_coverage independent of existing index readiness/counts. A read-only coverage helper counts current grant ids/documents in the shared physical index without widening grants or rebuilding project material into the Workplace catalogue. Existing search/resolve behavior remains compatible.

Schema/docs: resource-bindings.schema.json plus additive context-capsule reference and stage.resource_subset in process-definition schema; concise EN/RU Work-resource guide and links/status update. No process version edit or old capsule migration. Primary owns work_resources.py, integration files and coverage helper; junior initially owns only work_resource_material.py plus its private implementation report. Separate junior docs/schema task can follow. Review and test responsibilities begin after implementation.

Assurance: A/B and two simultaneous Work generations, revoke, content/metadata/version/root/source mutation/deletion, symlink/escape, explicit empty/invalid/expanded subset, malformed selector/capsule/hash/process pin, legacy/unknown version; unchanged capsule and read-only state, continuation; CLI/MCP parity and session denial; evidence retains generation/fingerprint; metadata source does not hash mutable output body; project readiness/coverage distinction; bounded large material and no cross-Work cache reads. Existing resource narrowing, indexing policy, shared index, multi-process capsule, pinned-process and MCP JSON-RPC smokes. Independent review, full schema/public/checksum gates and exact local delivery handoff.

Rollback is local source reversal only; earlier dirty files/accepted evidence stay intact. No installed update, runtime restart, shared registry repair, public package or publication. T06 handles integrated live acceptance. Domain decisions are primary acceptance under AFK authorization.
