# Пути Work, сборка команды и чтение каталогов

Реализация и focused assurance завершены. Итоговые 19 продуктовых файлов
заморожены для независимого ревью. Baseline:
`585e1ec20e63339a0433dc5a53871cf567d98b3b`.

Четыре собранных native-вклада создали конкретных владельцев:

- `WorkPaths`: девять прежних алгоритмов путей Run/Assignment, артефактов,
  handoff, prompts и worker attempt. Сохранены повторные дефисы generated Run ID
  и отдельная нормализация agent/task/assignment.
- `WorkerCommandBuilder`: прежние sandbox и build; используются готовые
  политики путей, выходов, окружения, драйверов и нормализации контекста.
  Проверка output paths предшествует переменным и env, prepared wrapper и argv
  сохраняют прежние поля, порядок и отказы.
- `PlatformContractReader`: семь алгоритмов актуального seed/project/workplace
  каталога с прежними overlay, aliases, fallback, unknown fields и ссылками.
- `UpdateDocumentReader`: 13 алгоритмов путей реестров, YAML/JSON, doctor checks,
  manifest paths, index и file URL. Различия soft YAML, doctor и index сохранены.

Конструкторы не читают файлы и не захватывают текущую Work/project. Повторно
использованы готовые `WorkspacePathReferenceReader`, YAML, schema, metadata,
driver, context, output и environment owners; их байты не изменены. Обратного
импорта монолита и новых правил нет. Все модули сохраняют future annotations.

Основной исполнитель удалил 33 определения монолита: 31 алгоритм и две
устаревшие обёртки model/reasoning. Весь AST монолита, включая 851 оставшееся
определение и прочие узлы, отличается только предусмотренными импортами,
конкретной композицией и заменами вызовов. Все действующие внешние вызовы
в 11 модулях переведены на канонических владельцев: egress, prepared inputs,
компилятор контекста, Host и семь smoke-файлов. Их полный AST совпадает после
нормализации ожидаемых изменений. Terminal-admission spy перенесён на
`WorkerCommandBuilder.build`, все прежние assertions сохранены.

Вклады содержат полное сравнение AST/сигнатур 31 алгоритма, аннотаций и короткие
синтетические случаи; raw hashes связаны с итоговыми файлами. Основной
исполнитель выполнил 68/68 проверок реальной композиции: 31 annotation map,
пути, команда и native отказы, overlay/alias/fallback, изменение каталога при
прежних размере/mtime и удаление, различные режимы YAML, дубликаты manifest
paths и прямой/скопированный Core без CLI/Host. Для env использовались только
синтетические значения; реальное окружение не сохранялось в доказательства.

Пройдены девять существующих профильных smoke-скриптов и существующая функция
`terminal_worker_admission` из recovery smoke. Проверены generated Run ID,
worker governance, continuation, десять egress cases с изолированным loopback
broker, onboard platform selection, схемы/поиск обновлений, документация и
prepared execution. Остальные recovery/runtime scheduler проверки не
запускались: изменённые пути покрыты AST, прямой композицией и профильными
сценариями. Изолированный broker не является приёмкой реально подключённого хоста.

Первый скрипт интеграции встретил повторный текст импорта во вложенном fixture.
Восстановлены только 12 собственных primary-файлов по точным preimages, затем
выбран top-level Import AST и интеграция завершена. Четыре Core-вклада и docs
не менялись; итоговое сравнение выполнено после завершения caller closure.
Первое успешное library-наблюдение сохранено локально как частичное.

Egress smoke вернул exit 0 и `PASS 10 Work egress checks`; collector ожидал
двоеточие. Успех признан по сохранённому stdout, продолжены только оставшиеся
проверки. Повторных успешных fixture-прогонов не было; исходный receipt сохранён,
причина и его hash находятся в `collector-resolution.json`.

EN/RU справка соответствует владельцам и остаточным legacy-зависимостям.
Inventory изменил 14 строк и добавил четыре, сохранив 1326 строк и три известных
посторонних расхождения. `product-manifest.json` фиксирует все 19 raw hashes.
Реальный запуск процессов, lifecycle, locks/journals/recovery и остальные
неперенесённые зависимости egress/prepared сохраняют прежних владельцев.

Приёмка ограничена исходниками на внешнем контракте 1.2.0. Архив, install,
Runtime и подключённый хост отдельно не квалифицированы; OOP-эпики открыты.
Проверки ZIP и широкие релизные прогоны исключены. После ревью требуется
коммит точных путей, push одного SHA в оба remote, readback, завершение шести
native Work и root doctor. GitVerse — только GITVERSE_TOKEN с отключённым helper.
