# Перезапуск Runtime и CPU: результат

После двух отказов обычного restart и явного разрешения пользователя выполнен штатный server restart --force. Старый PID 13540 и его launcher PID 9308 завершились. Новый владелец — PID 16976, instance 7e99504388824711a0e0c38b5fa400cf, запуск 2026-10-17T06:18:26Z. Проверены runtime.lock, service.json, фактический процесс и readyz=true. Готовность ready, здоровье остаётся degraded.

За 30 секунд до попытки: средняя загрузка Runtime 21,8876% общего CPU, медиана 24,4085%, максимум 30,2675%. В устройстве четыре логических процессора; измерялось приращение процессорного времени процесса, делённое на фактическое время и число процессоров. Сопутствующий launcher PID 9308 — 0%; подключённый MCP PID 5284 — 4,0754% среднего CPU на фоне управляющих запросов. Исходные отсчёты: before-cpu.json.

Защита завершения проверяет занятость за 0,5 секунды и получает неполное покрытие: running=null, observed running=0, issues budget/coverage. Видимых процессов PF-исполнителей не найдено, но это не заменяет отсутствующие данные защиты. Дополнительное чтение с увеличенным бюджетом также не восстановило полноту регистрации. Состояние сервиса не исправлялось.

Пользователь ответил «да, разрешаю» на конкретный вопрос о server restart --force. Существующий операторский CLI завершился с кодом 0. Принудительное завершение ОС, ручное снятие блокировок и изменение продукта не применялись.

Это наблюдения фоновой работы, а не контролируемый нагрузочный тест. Разница среднего до/после — около 1,15 процентного пункта; устойчивое потребление порядка 20–25% осталось.

После замера сервис остаётся ready/degraded. Последняя записанная ошибка scheduler: project scheduler pass failed with status 1 для этого проекта; director/inspector/projection и metrics сообщают failed, ledger — ok. Эти ошибки не исправлялись в задаче перезапуска.

Установленный Core имеет VERSION 1.2.0, но его journal/service модули отличаются от доставленных исходников SQLite. Простой перезапуск загрузит текущую установленную версию. Установка исправлений и перенос настоящих журналов остаются отдельной операцией.
