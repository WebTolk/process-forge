# ParameterMergePolicy — приёмка исходников

Результат: accepted_source_only. Независимое ревью завершено без блокирующих
замечаний; исправления перед приёмкой не требуются. Исходная точка:
`d2f8a856565e77b5f1a6d3026369e861800ccffb`.

Слиянием параметров и записью provenance владеет обычный stateless-объект
`configuration.parameters.ParameterMergePolicy`. Пять старых реализаций удалены
из монолита. Оба найденных потребителя используют прямой импорт нового владельца.
Полный компилятор контекста сохраняет остальные legacy-зависимости; этот срез
не объявляется завершением OOP-01–05.

Изменены шесть продуктовых файлов; точный состав и хеши — в
`product-manifest.json`, описание — в `implementation.md`. Сохранены алгоритмы,
порядок, ошибки, копирование, provenance и существующие особенности ID-списков.
Изменений внешних CLI/MCP-команд, аргументов, схем и форматов нет.

Проверено:

- 250 сравнений с замороженной исходной реализацией, включая 21 случай native
  exception; расхождений нет.
- Четыре независимых контракта копирования, provenance, ID и отсутствия состояния.
- Два изолированных импорта: прямой и из отдельной копии Core, без CLI/Host.
- Три неизменённых штатных parameter smoke: cascade resolution, assignment capsule,
  freshness; все прошли основным исполнителем за семь секунд.
- Независимое ревью реального кода, двух потребителей, документации и checksum rows.

У native QA создание fixtures было заблокировано окружением до проверок продукта.
Его первоначальный отчёт сохранён. `qa-resolution.json` подтверждает, что основной
процесс выполнил те же smoke на точно тех же байтах исходников; права, зависимости
и тесты не менялись. Итоговое независимое ревью подтвердило устранение этого пробела.
Сводная квитанция: `verification.json`; отчёт ревью: `../review/report.md`.

В текущих EN/RU справочниках обновлена карта владения. В checksum inventory сделаны
четыре замены и одно добавление; остальные 1312 строк сохранены. Три прежних
расхождения вне среза оставлены без изменений. Подробности — `../docs/report.md`.

Поставка: отдельный коммит dev, push одного SHA в origin/dev и gitverse/dev с
полным readback. Фактическая квитанция записывается в `delivery/parameters.json`
после push. GitVerse использует существующий токен через окружение процесса;
учётные данные в артефакты не записываются. Диагностические трассы со сведениями
окружения остаются локально; публикуются переносимые доказательства.

Release notes этого dev-среза: существующее слияние параметров перенесено в Core,
поведение и версия 1.2.0 не изменены. Migration notes: изменений схем и данных нет;
внутренние consumers уже переведены на канонический импорт. Отдельная упаковка,
новый релиз, установка и qualification Runtime/подключённого хоста не требуются.
Delivery/build profile: not_applicable — source-only перенос на выпущенной основе
1.2.0 с целевыми проверками и ревью. Проверки содержимого ZIP после упаковки
временно исключены по прямому указанию пользователя.

Выводы исполнения и предложения следующего цикла — в `evolution.md`. После
завершения native lifecycle основной агент перечитывает исходную архитектуру и
продолжает согласованные переносы до 09:00 по времени устройства.
