# T05 architecture and decisions

Accepted implementation boundary: a source application service `prepared_input.py` derives a private per-attempt manifest from the validated T03 contract and pinned snapshot. The CLI owns lifecycle locks, driver selection and persistence; executors consume that manifest without starting another Work. T02 material capture and grant normalization remain the resource authority primitives. Do not infer authority from registry existence or driver configuration.

The manifest carries version, project/run/task/attempt, capsule byte hash, contract and intent hashes, snapshot identity, stage, scope/actions, outputs, source references/excerpts and explicit resource grants. Inline source text is bounded to 64 KiB per file and 256 KiB total; larger/binary files retain checksum and truncation metadata. JSON is limited to 4 MiB. Full material verification uses existing T02 budgets; no entire corpus is copied. Metadata-only grants never become directory body grants. Requested but unmatched, unavailable, drifted or revoked resources cause preparation failure.

Store `attempts/<attempt>/prepared-input.json` exclusively, then record its path and SHA256 in command/status. Reserve `PF_PREPARED_INPUT_FILE` and `PF_PREPARED_INPUT_SHA256`; expose `{prepared_input_path}` and `{attempt}`. Validate persisted integrity and current source/authorization before launch. Generic-shell preserves its existing target argv and receives a provider-neutral lifecycle wrapper through an explicit built-in driver capability. Custom drivers retain their existing exit-proof requirements. Codex consumes the same manifest, preserving direct ungoverned CLI compatibility without widening prepared metadata grants to external directory access.

Collection holds the lifecycle lock through validation and completion. Preparation records output baselines; collection requires current-attempt evidence, pins output bytes in an immutable receipt, and uses deterministic completion/collection event IDs. Repeated collection returns the same receipt; changed bytes fail. Durable receipt plus stable IDs permits repair after interruption without duplicating lifecycle effects. Ordinary primary stage transitions remain independent.

Decisions: keep this a focused service and CLI seam, not a command rewrite; use local immutable inputs and explicit references, not worker MCP bootstrap; retain custom driver behavior through opt-in wrapper capability; fail closed on missing grants; keep model/driver preferences outside semantic authority; document PF permission declarations separately from OS sandbox enforcement. No installed update in T05.

Implementation order: shared preparation/validation and bounded material, CLI persistence/prompt/launch, neutral wrapper and Codex consumption, receipt collection, schema/docs, focused and compatibility checks. Main agent owns shared service and CLI; isolated wrapper/schema/docs may be delegated after their interfaces are fixed. Independent reviewer and regression writer start after implementation.

Acceptance: deterministic generic-shell fake executor succeeds with no MCP/network dependency; identical scope/context across drivers; denied grants and drift fail before launch; bounded large inputs and metadata-only resources; durable restart/attempt identity; repeat collection has one completion and rejects mutated result. Existing worker, T02/T03/T04, schemas, public cleanliness and checksum checks must pass. Archive/install/public release are not applicable here; integrated acceptance continues in T06.
