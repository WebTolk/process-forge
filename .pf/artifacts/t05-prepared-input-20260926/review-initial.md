# T05 independent prepared-input review

Review scope: `prepared_input.py`, `prepared_resources.py`, `tools/prepared_executor.py`, worker preparation/start/collection and task completion in `tools/processforge.py`, and prepared consumption in `tools/codex_exec_worker.py`. Reviewed the accepted T05 domain/architecture and developer proof as context. This is source-only; I did not run tests, mutate project state, or inspect installed Runtime.

## Blocking findings

1. **Governed worker collection performs compatibility task completion.** In `_collect_worker_run_locked`, after capturing and pinning the report, collection always calls `command_task_complete` (`tools/processforge.py:19318-19324`). That command sets the assignment to `done`, updates its run task, and emits `task.completed`/`assignment.completed` (`:21004-21016`). A T03 governed assignment has a pinned `process_execution`; completing it here bypasses the normal stage outcome/evidence transition. The T05 domain says primary governed stage transitions remain distinct from compatibility worker task completion. Repro: collect a report for a governed process assignment and inspect assignment/run state; it is marked done before `pf.work.transition`. Keep receipt/capture for governed Work and reserve `task-complete` for legacy compatibility tasks.

2. **Attempt path symlink can write private manifest outside private runtime.** `prepared_input.local_file` rejects only the final path symlink and paths resolving outside the project (`prepared_input.py:33-37`). Preparation checks this helper, then `write_once` opens the original lexical `prepared_path` (`:121-127`, caller `tools/processforge.py:19039-19045`). Repro: make `attempts/<next-number>` a directory symlink/junction to an in-project public artifacts directory before prepare. Resolution stays within the project, so the check passes, but exclusive creation follows the link and writes the private manifest (including absolute `project_root` and resolved resource paths) into the public directory. Validate the prepared/receipt destination beneath the exact canonical attempts directory and reject symlink/junction components.

3. **A crash during receipt write can strand collection permanently.** `collection_receipt` writes `collection-receipt.json` directly with `write_once` (`prepared_input.py:160-176`), which opens the final path with `xb` and writes bytes in place. If the process or filesystem fails mid-write, retry sees the partial file at `:167-169`, fails JSON parsing or equality, and cannot finish; no completion effects have run yet. Use atomic exclusive publication or a narrowly safe recovery for an invalid partial receipt with no completion marker/effects.

## Reviewed fixes

The ready/manual start path now reuses the saved attempt and checks saved command/state prepared references and attempt before launch; changed launch preferences require explicit preparation (`tools/processforge.py:19099-19123`). Collection now validates report size and UTF-8 before persisting its receipt, then checks the exact raw report checksum (`:19288-19298`), avoiding a durable receipt for a report it cannot capture. Prepared resource authorization checks current freshness, snapshot identity, pinned selection, stage subset, current grants, and material fingerprints (`prepared_resources.py:90-316`). Prepared loading revalidates T03 intent/sources and current resource access (`prepared_input.py:128-157`).

I did not independently run the supplied developer proof or smokes. The three blockers above remain source findings unless fixed after this review snapshot.
