# T05 investigation and impact

Actual before fixture (reproduce-before.json): a task requests a nonexistent knowledge resource, yet manual prepare succeeds with an empty grants list; the generated prompt then requires MCP and a new pf.work.start. No prepared input manifest exists. Repeated collection creates two worker.run.collected and two task.completed events for the same attempt. The fixture is isolated and preserves original Work bytes.

The shared preparation path already validates T03 ready context, source hashes/capabilities and immutable intent. It then resolves workspace refs independently, generates a prompt, selects driver and increments attempt. Material authorization/readiness and a bounded delivered input are absent. Existing workspace resolution silently drops unmatched knowledge refs and resolves nonknowledge registry refs without comparing pinned/current project selection. T02 WorkResourceService enforces resource material/current access, but its selector assumes governed run/assignment pins; legacy batch worker contexts need the same material verification without pretending they have a governed stage pin.

worker-driver-map.md maps additive transport seams. Driver/model preferences do not alter the capsule. Add a prepared-input file placeholder and reserved PF environment pointer; keep current generic-shell argv compatible. The wrapper already records start/end and reconciles durable exit; retry means deliberate new prepare/attempt, not automatic retries. Attempt placeholder is missing from the validation allowlist despite being used internally.

Collection validates current task/output paths and T04 report provenance, but it lacks a prepared-context/output receipt and holds its lock only during observation. It can repeat lifecycle effects. Introduce an attempt-bound durable receipt and hold lifecycle lock through validation/collection; stable event IDs and completion replay must avoid duplicate effects after a crash.

T05 should preserve T02 metadata/body distinction: an indexed metadata declaration does not grant whole directory body access. Prepared sources are bounded inline chunks plus verified file references; material refs retain current grant and pinned provenance. Codex must consume the same prepared input and avoid automatically widening to a whole external root. File-only and generic-shell remain usable offline. This is an application contract, not an OS network/filesystem sandbox claim.
