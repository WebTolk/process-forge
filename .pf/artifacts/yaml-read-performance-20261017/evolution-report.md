# Итоги и оставшиеся вопросы

Текущая задача устранила повторный разбор неизменившихся YAML и копирование растущих историй при поиске Run. Исходный код, чистый dev-архив, установленный Core и фактический Runtime проверены отдельно. Прежнее обновление SQLite и миграция журналов повторно не выполнялись.

После остановки для уточнения пользователь подтвердил продолжение с пониманием, что кэш хранится в ОЗУ каждого процесса и очищается LRU/завершением процесса. Код и настройки кэша после паузы не менялись. При продолжении прежняя Work остаётся valid/ready на этапе evolve; Runtime сохранил PID18280 и тот же instance. Контекст свежий, блокирующих результатов нет.

Ограничения сохраняются: чтение/хеширование исходных байтов и обход каталога остаются линейными по объёму. Первичный разбор, изменённые файлы и значения за пределами удерживаемого кэша требуют работы. Оценка лимита кэша не является пределом RSS; отдельные процессы удерживают независимые экземпляры.

Основной следующий источник нагрузки локализован: Host читает и переписывает37,8МБ state.json при проходах scheduler. В новом профиле это980 из1280 GIL-выборок,76,56%; CPU службы остаётся15,44%. Следующий отдельный ограниченный этап должен определить владельцев растущего состояния, исключить ненужную перезапись и сохранить согласованность нескольких процессов. Выбор раздельного хранения/индекса/транзакционного обновления требует исследования фактических данных и контрактов; перенос JSON в SQL или ещё один кэш автоматически не добавляются этой задачей.

При дальнейшем росте числа Run потребуется отдельное решение для поиска метаданных без обхода всех YAML, с явной обработкой правок вне PF. Прежние degraded scheduler и закрытый фактически подключённый MCP также не объявлены исправленными. Общая приёмка1.2.0 отложена по указанию пользователя. Новые задачи и работы этим отчётом не запускаются; глобальные правила и память пользователя не изменяются.

Доказательства текущей задачи сохранены в собственном каталоге артефактов; архив, замороженный набор и чистый checkout удерживаются в собственном временном каталоге для воспроизведения. При дальнейшем обслуживании не повторять уже завершённое обновление и миграцию. Точные идентификаторы и ограничения переданы в `.pf/handoffs/yaml-read-performance-20261017.md`.
