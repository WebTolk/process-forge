# Учёт токенов и времени агентов

Реализована одна долговечная SQLite-база учёта для всех проектов workplace PF.
Факты разделяются по project_id, run, assignment, attempt, агенту и модели.
Сохраняются происхождение, revisions, неизвестные значения и полнота источника.
Время агентов и объединённое занятое время проекта считаются раздельно.

Домен и чистые правила отделены от хранилища, общего AccountingService,
провайдерных адаптеров, композиции workplace и CLI. Этот же сервис рассчитан на
будущие TUI/Control Center, плагин и REST без создания отдельных копий логики.
Финансовых полей, тарифов и денежных расчётов нет.

Автоматически собираются structured receipts и время управляемых Codex shell
workers. Ошибка учёта сохраняет exit/report-контракт и raw evidence для replay.
Kimi поддержан через явный импорт квалифицированной современной схемы; native
автосбор Kimi и полный сбор всех сессий устройства не заявлены.

Команды: `pf usage summary`, `projects`, `task`, `run`, `attempt`, `details`,
`collect/import/replay` с явным `--project-root`; результат JSON. Например:

```sh
python bin/pf.py usage summary --project-root . --json
python bin/pf.py usage task --project-root . --task <assignment> --json
```

Итог QA: 68 тестов и 36 подтестов, Ruff lint/format, scoped mypy и три существующие
smoke-проверки прошли. Два замечания первого независимого ревью исправлены;
отдельное повторное ревью — PASS. Два настоящих запуска подтвердили сбор и
повторный импорт без увеличения итогов. Подробности: assurance-report.md.

Все исполнители и ревьюеры использовали разрешённые знания PF по Python и ООП;
READ_ACK и хеши находятся в их отчётах. Опыт и ограничения: evolution-report.md.
Доставка и точные Git SHA фиксируются отдельно в delivery-report.md.
