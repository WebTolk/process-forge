# R02: приёмка исследовательской волны

Дата: 2026-10-24. Исследование завершено; продуктовая реализация и QA ещё не выполнены.

Нативные PF shell-воркеры W1–W4, модель gpt-6.1-sol, reasoning high,
завершили попытку 2 с exit code 0. Их report.md и implementation-map.json
сохранены в соседних каталогах w1-domain, w2-driver, w3-runtime, w4-migration.
Оркестратор прочитал все четыре отчёта. Пустой stdout.log не был доказательством
отсутствия работы: фактический поток Codex находится в usage-attempt-N/codex.jsonl.
Предыдущая ошибка диагностики исправлена в diagnostic-correction.md.

## Подтверждённое влияние

- Основные пути активности/остановки читают накопленную историю worker status.
  Подмена только одного счётчика не устранит зависимость остальных потребителей.
- Есть окно между Popen и публикацией worker state; signal/cancel не доказывает
  физического завершения. Новый owner должен различать процесс и collection.
- application_id, user_version и одинаковые legacy metadata table names
  препятствуют простому объединению существующих SQLite-файлов.
- Существующие ConfigStore, backup API, journal maintenance и updater сохраняются
  владельцами своих функций. Общий SQL API пока не реализован.
- Первым переносится project-owned worker execution state/history. Canonical
  Work YAML, immutable capsules и содержательные артефакты пока сохраняются.
- Поиск остаётся отдельным производным хранилищем. Workplace-проекция не
  становится каноническим владельцем проекта и не доказывает отсутствие активности.

## Принятая граница

Продолжить согласование минимального SQL API/SQLite driver и одного основного
проектного store, operational rows отдельно от historical rows внутри него.
Обновляемые публичные CLI/MCP остаются совместимыми. Старый проект сохраняет
действующий storage route до явного детерминированного перехода.
Транзитное наличие прежних hooks/events/accounting не объявляется завершённой
консолидацией. Будущие драйверы, RAG, общий scheduler и глобальный updater не
реализуются в этом срезе. Поддержанная миграция не требует LLM.
Живые данные и установленный Core этого рабочего места сейчас не мигрируются.

## Незакрытые архитектурные швы

Отчёты расходятся в названиях пакетов, ownership файлов и границах первых
адаптеров. Требуется единый freeze точных interfaces, schema envelope, readiness,
migration/cutover и admission fence до выдачи implementation Work.
Это нормальный результат исследования, не доказательство готовой реализации.
W1 получил отдельное artifact-only назначение pf-r02-w1-contract-20261024:
свести все четыре карты и выдать непересекающиеся ownership lists.
Независимый reviewer приступит после реализации.

## Проверки и ограничения

Каждый исследователь проверил свой JSON и source fingerprints; продуктовые
pytest/Ruff/mypy, 400k benchmark и runtime acceptance не выполнялись.
Нативная коллекция сохранила отчёты, но не заменяет READ_ACK.
В первой волне собственные READ_ACK/RESULT_READY не были отправлены:
исполнители сочли разрешение записи координационных артефактов недостаточно
явным. Это ограничение сохранено, подтверждения от их имени не создавались.
В новой выдаче собственные нативные chat-record/heartbeat прямо оговорены.
Продуктовые изменения, коммиты и доставка исследовательским исполнителям не
поручались; они будут сериализованы назначенным native executor после сведения.
