# Принято: единая база учёта PF

2026-10-22. После сравнения вариантов оператор подтвердил: «Ок, хорошо. Пусть будет общая база на весь PF».

**Решение принято: одна общая локальная база учёта PF для всех его проектов, с разделением по устойчивому `project_id`.** Размещение — в долговечных данных рабочего окружения PF, вне отдельных checkout и установочных файлов. При нескольких устройствах локальная база каждого PF может позднее опционально передавать факты в удалённый Control Center.

Это утверждает ранее предложенный вариант в scope-amendment.md. Формулировка того документа о рекомендации для обсуждения теперь заменяется данным принятым решением. Граница ответственности остаётся: данные исполнения, время, токены и статистика; финансовые функции исключены.

Проектных БД нормализованного usage и отдельной общей БД только для отчётов не создаём. Существующие проектные журналы/артефакты сохраняют свои назначения; сводки строятся из общей базы. Общий query service обслуживает CLI, будущий TUI и плагин; опциональная REST-синхронизация использует те же уникальные факты.

Это решение по плану, не запуск реализации. Исходная карточка остаётся open/planning_only; окончание данного документационного цикла не создаёт БД и не меняет инфраструктуру.
