# Представление процессов, каталог драйверов и правила выбора

Статус: реализация завершена, итоговая проверка перед независимым ревью.

Четыре шелл-воркера перенесли существующие обязанности в непересекающихся
продуктовых файлах. Presentation выполнялся с medium, drivers/candidates/updates
с high. Основной агент интегрировал монолит, единственного внешнего потребителя
в MCP, документацию EN/RU и inventory. Новые функции продукта не добавлены.

`ProcessAuthoringDefinitionBuilder` дополнен `from_definition`; старые методы
и конструктор сохранены побайтно. `ProcessAuthoringRenderer` оформляет прежние
четыре текста. Небольшая общая функция coordination имеет канонического владельца
и остаётся функцией. `RuntimeDriverCatalogReader` читает текущие реестры и документы
через конкретные классы Core, без хранения разобранных данных. Политика knowledge
candidates владеет прежними target/routing/promotion-проекциями и проверками.
Выбор версий и оформление update assessment перенесены в maintenance.

Удалены 31 определение монолита и перенесены четыре константы. Все найденные
потребители используют канонические классы и функцию. MCP сохраняет проверку
driver ID перед отложенным импортом, root передаётся как значение, project/workplace
и отображение ошибок не менялись. Остальные байты MCP-файла сохранены.

Временное сравнение дало 247/247 совпадений, включая 27 исходных исключений:
40 случаев presentation, 122 candidate targeting, 45 выбора версий и assessment,
34 проверки файлового каталога, четыре MCP-привязки и два прямого/скопированного
Core. Проверены ссылки вложенных данных, порядок/тексты, чтение после изменения
с прежними размером и mtime, удаления и некорректного YAML. Существующие парсеры
Core переиспользованы; отдельная переквалификация зависимостей не выполнялась.

До ревью проверка модульной семантики обнаружила отсутствие исходного
`future annotations` в candidates. Основной агент восстановил директиву в том же
действительном Work после сбора воркера, без параллельного writer. Сравнение
31 набора аннотаций с исходными функциями прошло. Первоначальные успешные
parity/smoke receipts сохранены локально; после этого единственного изменения
ограниченные проверки повторены на итоговых байтах. Прежний отчёт candidates
сохранён, изменение его исходного hash объяснено в `annotation-correction.json`.

Выбраны десять существующих smoke: authoring materialization parity и evolve
questions, runtime driver registry, MCP action tools, candidate schema/targeting
schema/narrowest scope/export, update discovery и notifications. Итоговые receipts,
AST-проверка оставшихся определений, точные hashes и изменения inventory находятся
в `verification.json`, `parity-results.json`, `smoke-results.json`,
`inventory-changes.json` и `product-manifest.json`.

Граница приёмки — исходники 1.2.0. Полная authoring validation/publication,
исполнение Runtime, полный sanitizer/export lifecycle, получение и применение
обновлений сохраняют прежних владельцев. Новые MCP-ресурсы не реализуются.
OOP-эпики остаются открытыми. ZIP-content, общие release/archive/install suites,
инфраструктурные действия и фактический подключённый хост не квалифицируются.

Независимый reviewer проверит окончательный исходный код, доказательства и hashes.
Затем один commit будет отправлен в оба dev remote с точным readback; GitVerse
использует существующий токен без credential helper. После native завершения
будет повторно прочитана исходная архитектура.
