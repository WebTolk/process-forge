1. Capture public payload baseline and exact originals of the declared existing files. Preserve current full journal prefix as a .bin backup in durable private scratch; record invalid range, line, raw bytes, error/hash and valid-event count in private evidence.
2. In append_process_event, serialize JSON first, then use registry_file_lock(events_path) for read/dedup and a binary whole-record append plus flush/fsync. Catch lock SystemExit as explicit RuntimeError to keep service request handling alive; preserve hook dispatch outside the lock. Do not change event identity or dispatch semantics.
3. Add an isolated actual multi-process regression: unique large Unicode events, simultaneous duplicate ids, parse/count/uniqueness, existing content preserved, hook dispatch after lock, lock failure surfaced. Reuse existing registry lock regression for ownership mechanics; no new lock implementation.
4. Implement the private reviewed repair utility with default read-only plan. Apply only with exact known fragment hash and expected single bad record, backed-up original bytes, same open file identity, prefix comparison and fixed-length offset write; preserve newline and file length, fsync, verify all original valid bytes and later suffix. Test it with invalid middle line plus a concurrent appender before using the same routine on live journal. A replacement/truncation or unexpected record aborts, never falls back to wholesale rewrite.
5. Run concurrency smoke plus central ingress/replay and relevant event/runtime regression, actual full checkout schemas/checksum/cleanliness/diff. Record code assurance then apply the already tested repair in delivery stage, revalidate full journal and schema results, append explicit audit event, record source fix pending next official Core update with remaining T10. Browser not_applicable: journal/library/CLI behavior only. Recovery preserves original bytes and raw evidence; no automatic data rollback over concurrent events.
