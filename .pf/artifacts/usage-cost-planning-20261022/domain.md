# Домен учёта: время, токены, стоимость

Предлагаемое имя модуля: `accounting`. Нейтральные правила измерений и оценки не зависят от Codex/Kimi, Runtime, TUI или REST. Это небольшая подсистема внутри PF, не новый процесс управления задачами. Исследование: [source-map.md](source-map.md), существенное уточнение Kimi: [kimi-source-addendum.md](kimi-source-addendum.md).

## Минимальные сущности

| Сущность | Назначение и основные данные |
| --- | --- |
| UsageRecord | Единственный вклад ограниченной единицы выполнения: origin/source/session, agent instance, native unit/request/turn или стабильная journal occurrence; provider/model, нормализованные счётчики, наблюдаемое время, версия адаптера, качество, ссылка/hash источника. Версия записи может уточнять тот же вклад. |
| ActivityInterval | Наблюдаемый интервал выполнения agent instance: start/end, известная длительность, тип измерения, полнота, binding. Открытый интервал не считается завершённым. |
| RateCard | Версионированный тариф: provider/model/billing mode/tier/currency, дата действия/источник, ставки за известные категории. |
| Valuation | Сообщённая провайдером денежная величина либо расчёт PF по точной версии UsageRecord/RateCard/алгоритма; amount Decimal, currency, вид и полнота. |

Project/Work/attempt — ссылки на существующие сущности PF, не новые lifecycle aggregates. Source cursor/capabilities и project mapping — технические метаданные хранилища. Отдельный namespace origin и schema version нужны уже локально для replay и будущей синхронизации.

## Правила идентичности и привязки

R01. Различать harness/driver (`codex-exec`, Kimi hooks), billing provider, фактическую модель и requested model/alias. Имя агента не определяет модель/тариф. Один agent_id может иметь несколько параллельных agent instance/session.

R02. Использовать точные project/run/assignment/native attempt из проверенного binding. Интерактивный turn не выдавать за native worker attempt. Если подтверждён только проект — отдельная группа «без задачи»; неизвестен проект — карантин/непривязанный источник вне проектных итогов. Не выбирать последнюю/новейшую задачу.

R03. Локальная регистрация проекта связывается с устойчивым accounting project UUID. Совпадение названия, каталога или repository URL само по себе не разрешает объединение двух проектов. При клонировании/переносе явное mapping; origin источника сохраняется при relay/import. Path/host/user детали — приватная инфраструктура.

R04. Один наблюдаемый расход имеет один contribution key. Он не меняется от транспорта, повторного collect, переподключения, индексации или импорта. Известный upstream request/event ID предпочтителен; без него нужна доказанная идентичность journal generation + occurrence, а не hash текста как единственный ключ: два одинаковых настоящих запроса могут стоить денег дважды. Две доставки одного источника через разные адаптеры связываются с тем же canonical source/key либо объявляются альтернативными потоками, не суммируются вслепую.

## Токены и доставка

R05. Нормальная форма: `input_total`, `output_total`, `input_cache_read`, `input_cache_write`, `output_reasoning`, `reported_total`, nullable целые >=0; версии семантики/измерения. Cache — подмножество input_total, reasoning — подмножество output_total только при подтверждённом контракте. Тогда total=input_total+output_total; подкатегории повторно не добавлять. Если источник даёт disjoint input_other/cache-read/cache-write — адаптер сначала складывает их в input_total. Неподтверждённые категории/суммы остаются null. Не заполнять отсутствие поля нулём по умолчанию модели SDK.

R06. `token_count` контекста, percent/quota, prompt length, оценки по символам и фраза агента в отчёте — не actual usage. Отдельная диагностическая оценка возможна позднее; в измеренные токены/расход она не входит. Поддержка reasoning зависит от источника, а не от наличия reasoning mode.

R07. Адаптер объявляет измерительную единицу и семантику delta/snapshot/cumulative для конкретной версии. Внутри accounting каждый ограниченный unit имеет абсолютный вклад; delta получает собственный устойчивый unit key. Snapshot того же unit заменяет вклад по доказанному source revision/explicit supersedes, а не прибавляется. Запоздавший snapshot не должен затирать новый по порядку доставки. Если порядок/идентичность нельзя доказать — conflict/partial, без догадки.

R08. У session cumulative допускается разность только при известном baseline, порядке, counter epoch и непротиворечивой привязке. Неизвестный baseline/reset/переключение задач — partial/unassigned, без отрицательного расхода и без отнесения всей истории к новой задаче. Scope `session` не является синонимом cumulative; современный Kimi usage.record проверяется отдельно.

R09. Одинаковая запись/key/revision/hash повторно — no-op; тот же key/revision с другим содержимым — конфликт. Новая валидная revision уточняет вклад с сохранением истории; инвалидирование — явное событие, не отрицательные «токены». Приём факта и обновление source cursor атомарны. Ошибка/падение до commit допускают безопасный replay. Поток не смешивает request receipts, turn summary и session total для одного coverage domain. Родительское зеркало и исходный child receipt не два расхода.

R10. Учитывать измеренный расход всех попыток, в том числе ошибок, прерываний, compaction, вспомогательных вызовов и subagents. Если usage на оборванном запросе не получен — unknown/partial, а не 0. Достоверная частичная запись сохраняет вклад; успешный финальный отчёт не доказывает полноту.

## Время

R11. Основная метрика `agent_execution_ms`: сумма измеренного времени выполнения по agent instance без двойного учёта вложенных worker/turn/request интервалов. Worker elapsed включает инструменты/сеть; это не CPU и не чистое время генерации. Turn elapsed и worker elapsed сохраняют вид измерения и сравниваются с оговоркой. Session presence и жизнь карточки не дают исполнения.

R12. `project_occupied_ms`: объединение временных интервалов всех агентов проекта. Два агента одновременно 10 минут: 20 агент-минут и 10 минут занятости проекта. Ожидание человека/approval показывать отдельно, когда источник позволяет; неизвестное ожидание не вычитать произвольным таймаутом. Между интерактивными turns время не накапливается.

R13. Для duration предпочтителен monotonic clock процесса, для календарных срезов UTC timestamps. Отрицательная/противоречивая длительность отклоняется. При аварии неизвестный хвост не продлевать до текущего момента; показывать подтверждённую нижнюю границу/partial. Различия часов устройств ограничивают точность occupied time после sync; качество источника сохраняется.

## Деньги, полнота и отчёты

R14. Разделять `provider_reported` и `tariff_estimate`; это альтернативные оценки одного покрытия, не две статьи расхода. Сумма по API-тарифу не становится фактическим списанием по подписке. Неизвестная скрытая модель/тариф/категория — непросчитанная часть. Подписку не распределять по проектам автоматически.

R15. Денежная арифметика Decimal/целые scale units; валюта обязательна. Версия тарифа/дата действия/единица/источник/алгоритм закрепляются в valuation, прошлые результаты не пересчитываются молча. Новый тариф/backfill — явная новая valuation. Валюты выводятся отдельно; FX, налоги, фиксированные накладные расходы и биллинг-квоты вне первой версии. Дискретные категории тарифа оплачиваются один раз; cached/reasoning-inclusive объёмы не оплачиваются повторно.

R16. Результат содержит observed subtotal, missing/unsupported/partial counts, collection freshness/as_of и attribution coverage. null не преобразуется в0. «Полный итог» допустим лишь относительно известного перечня источников/исполнений, а не всех возможных агентов на устройстве. Project tokens = task-bound tokens + project-unassigned; общий итог не складывает перекрывающиеся parent/child scopes.

R17. Календарный фильтр отсекает интервалы времени по границам; токены/стоимость относятся к timestamp зафиксированного receipt/unit, а не равномерно распределяются по часам. Длинные units обозначают ограничение временного разрешения. При поздней записи обновляется as_of, а не скрывается изменение.

R18. По умолчанию хранятся нормализованные факты и приватные ссылки/hash на уже существующие логи, не промпты/ответы/credentials. Доступ к task usage не даёт просмотр остальных проектов. Для будущего sync явный project allowlist и минимальный DTO без локальных путей/сырых payloads; idempotency сохраняется.
