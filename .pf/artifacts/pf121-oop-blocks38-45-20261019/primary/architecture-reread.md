# Сверка после реализации блоков 38–45

Основной агент повторно прочитал все девять исходных документов, закреплённых
в текущих Work: контракт переноса, progressive decision, clarification, ADR,
domain, direction и OOP-02/03/05. Это общая сверка завершённой реализации основного
агента, включая отдельные области consumers, support и init-caller. Четыре
исполнителя зафиксировали собственные чтения в своих proof/report.

Перенесены существующие обязанности: шаблоны проекта и рабочего места, выбор
официальных пакетов, обнаружение проекта, конфигурация, запись событий и чата,
выполнение существующих hooks, правила манифеста и план команд выпуска.
Новые возможности из будущих задач не реализуются.

| Решения | Сверка с фактическим кодом |
| --- | --- |
| D01/D02 | Main и существующие потребители обращаются к конкретным владельцам Core. В принятых новых владельцах нет обратного импорта или вызова Main; прочие legacy-обязанности не объявляются перенесёнными. |
| D03/D04 | Сборка остаётся явной. Конструкторы новых служб сохраняют холодное поведение; Kernel, контейнер и система providers не добавляются. |
| D05 | Корни дистрибутива передаются только нуждающимся в них владельцам. Текущие project/Work передаются операциям. Сохраняется прежний общий ConfigurationResolver, включая его существующую семантику последней корректной конфигурации; новый кэш не вводится. |
| D06/D07 | Порядок защитных проверок и запись обязательных журналов сохранены. Существующие проверки source CLI/MCP, отказов записи и completion/continuation recovery прошли. |
| D08/D09/D10 | Обычные пакеты и явные импорты Python, без динамического загрузчика, новой подсистемы расширений или REST. Отказ существующих command hooks сохранён. |
| D11 | Каждая область имеет отдельную Work и прямые pins девяти документов. Доказательства относятся к исходникам; общие эпики OOP и другие уровни поставки остаются открытыми. |

| Инварианты | Доказательства и граница |
| --- | --- |
| R01–R05 | Алгоритмы identity, pinned process, permissions и capsule не менялись. Потребители получают только явные зависимости генерации и записи событий; guards MCP остаются перед прикладными вызовами. |
| R06 | Чтения и существующая конфигурационная семантика сохранены; проверены живые изменения classifier/configuration. Это не отдельная квалификация всех возможных кэшей PF. |
| R07 | Проверены обязательная ошибка журнала, оба момента сбоя dispatch и исходная матрица восстановления completion. Ошибки не скрыты необязательной диагностикой. |
| R08/R09 | Сохранены trusted ingress, допуск и привязка. Чтение/генерация Core не требует запуска служб; исходные проверки не равны приёмке подключённого хоста. |
| R10 | Четыре исполнителя владеют непересекающимися файлами; Main и дополнительные потребители закреплены за основным агентом в отдельных областях. Капсулы и прежние утверждённые материалы не переписывались. |
| R11 | Исходные отказные и повторные сценарии сохранили проверки и управляемые ошибки. Подмены методов учитывают связывание self; отсутствие emitter у прежних подставных объектов сохранено. |
| R12 | Публичные сводки используют относительные пути. Полные выводы проверок с путями устройства сохранены только во временных закрытых материалах. |

Применены знания Python из закреплённого `python-knowledge.md`: явные импорты,
связывание методов, сохранение подставных зависимостей и управляемых часов,
холодная сборка и отсутствие фиктивных корней. Состав полей dataclass,
конструкторы, сопоставление, repr и равенство существующих координаторов
сохранены; необязательный recorder передаётся на этапе композиции.

Все 17 выбранных групп существующих проверок прошли. Две первоначальные ошибки
указывали на оставшиеся подмены `Main.dispatch_hooks`; они перенесены на
`RuntimeHookDispatcher.dispatch_hooks` с теми же ошибками и утверждениями.
Повторялись только эти две группы; остальные 15 успешных результатов сохранены.
Независимая приёмка и доставка ещё требуют отдельных подтверждений.
