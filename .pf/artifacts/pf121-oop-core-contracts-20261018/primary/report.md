# Контракты Work, coordination, privacy и источников обновлений

Статус: реализация и ограниченная проверка завершены; независимое ревью и поставка ожидаются.

Четыре шелл-воркера работали в непересекающихся продуктовых областях. Work,
privacy и updates использовали high, coordination — medium. Все назначения
подготовлены до запуска воркеров; результаты собраны перед интеграцией.

Существующий `ContextContractInputs` расширен восемью операциями полей и путей
Work; все 20 прежних методов, поля и frozen-конструктор сохранены. Две уже
канонические операции переиспользованы, старые обёртки монолита удалены.
Компилятор контекста вызывает проекцию coordination напрямую.

`ProjectCoordinationReader` владеет прежними defaults, нормализацией и чтением
project/workplace config через конкретных читателей Core, без кэша документов
и сохранения Work. Общие privacy-предикаты и шаблоны находятся в `common.privacy`;
`AnswersDocumentReader` использует их с неизменённым классом. Прежние findings,
redaction и рекурсивное преобразование принадлежат `EvolvePrivacyPolicy`.
`UpdateSourceContractPolicy` владеет прежними trust/URL/env/source проверками,
валидацией реестра и стабильной сортировкой.

Удалены 28 определений монолита, включая две обёртки; девять определений данных
перенесены из монолита и answers. Все найденные потребители обновлены. Host
сохраняет порядок: automatic-content/metadata фильтры, затем отложенный импорт
и secret-проверка с прежним отказом. Остальные байты Host и компилятора
сохранены за исключением явных замен и необходимого импорта.

Временная проверка дала 231/231 совпадение, включая 29 исходных исключений,
28 наборов аннотаций, live-read coordination при прежних размере и mtime,
удаление, неизвестные поля/ссылки, три сценария короткого замыкания Host и
прямой/скопированный Core без CLI/Host. Первая попытка harness не передала
обязательный provider_key; исправлен только harness, исходная диагностика
сохранена локально. Продуктовых исправлений после запуска checks не было.

Все десять существующих smoke завершились успешно: Work start scope,
authenticated report content, project coordination modes, два privacy sanitizer,
candidate schema, update sites schema/discovery, authoring materialization и
Work capsule contract parity. Последняя содержит 19 встроенных проверок
контракта. Symlink containment пропущен из-за OSError хоста; эта возможность
не квалифицирована. Последний smoke выдаёт JSON `status: PASS`, а не строку
`PASS:`. Распознавание сохранённого вывода исправлено без повторного запуска;
первоначальный receipt сохранён локально.

Сравнение AST 903 оставшихся определений монолита подтвердило только ожидаемые
замены вызовов. Сохранены все прежние методы и конструктор ContextContractInputs,
класс AnswersDocumentReader, модульные аннотации и фактические байты остальных
участков Host/compiler. Изменены 14 продуктовых файлов; inventory: девять
обновлённых и четыре новые строки, 1323 прежние сохранены. Три известных
посторонних расхождения не менялись.

Доказательства: `verification.json`, `parity-results.json`, `smoke-results.json`,
`collector-resolution.json`, `inventory-changes.json`, `product-manifest.json`
и четыре отчёта исполнителей. Независимый reviewer проверит окончательные
исходники и зафиксирует hashes до поставки.

Это срез исходников 1.2.0. Правила доступа/admission/lifecycle, оставшаяся сборка
контекста, effective coordination/Director, schema-based validators и реальные
update-операции сохраняют прежних владельцев. Новые функции, MCP-ресурсы и
правила privacy/trust не добавлены. OOP-эпики открыты; archive/install/Runtime/
connected-host и ZIP-content проверки в этот срез не входят.

После ревью будет один commit и push одинакового SHA в оба dev remote с точным
readback; GitVerse использует существующий токен с отключённым credential helper.
Native завершение и перечитывание архитектуры предшествуют следующему срезу.
