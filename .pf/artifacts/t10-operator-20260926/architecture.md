# Architecture, decisions and implementation plan

1. Add provider-neutral src/processforge_core/runtime_metrics.py and a public JSON schema. Groups: registrations, sessions (online/stale/offline), workers (reported running), work (in_progress/blocked records), leases (held/expired/inactive). Use bounded directory traversal including visited-entry count, maximum depth and containment/symlink checks; bounded reads, regular-file checks and per-group file/byte/elapsed budgets (independent groups prevent starvation). Reject malformed/future timestamps and wrong types; prefer canonical presence records over legacy duplicates. No actual-record mutation. Snapshot exposes only fixed keys/counts/times/codes; fields lacking a real contract stay unknown.
2. Runtime caches only registration counts/known-root coverage from its existing host-cache read. On a bounded slower cadence (about 10 seconds), collect outside state_lock, then publish the compact instance-bound snapshot inside existing atomically written service.json and a metrics job result. Separate sample time/freshness (about 45 seconds) from state updated_at. Any failure is a small unknown/failed observation, not a daemon crash or stale data relabeled fresh. The monitor's normal 1 MiB state cap comfortably includes this snapshot; no new endpoint/database/journal is required.
3. Monitor validates/allowlists nested snapshot and current owner/readiness, prefers its small registration summary over the oversized historical cache, renders defined counters/partial coverage and separate age. Keep old-state fallback, terminal bounds and no-write/protocol guarantees. Existing monitor smoke must still pass; new tests cover forged types/owner, missing/stale/future/oversize snapshots and actual end-to-end publication.
4. Add server alias and bin/pf-server launchers using existing runtime lifecycle. New server status uses the bounded read-only monitor projection, start/run reuse existing singleton. Run --console may show a small ASCII foreground banner only on a real TTY. New server stop/restart request guarded shutdown: capability negotiation + expected owner, current bounded worker observation, and in-flight request count; HTTP refusal leaves Runtime ready. Force is explicit. Keep legacy runtime commands compatible for existing scripts/updater. New requests are refused once stop commits. No native executable/tray or host-owned MCP process manipulation.
5. Add diagnostics-configure CLI with optional exact Work or session target, profile and bounded duration, default read-only plan and explicit --apply. Update existing v1 JSON using pure T09 validation/lock enforcement, preserve unrelated fields/scopes, ensure <=64 KiB, and perform serialized atomic write. Reject invalid/symlink input, forbidden locked changes, malformed/oversized output and invalid durations before mutation. Detailed profiles get actual short UTC expiry; normal/off clear temporary detail through policy. Show effective precedence/locks; never auto-change the live project's config. Bypass optional operation logging for inspection/planning so these flows remain read-only.
6. Focused tests: independent metrics semantics/limits/legacy dedup/unknown/privacy, actual Runtime publisher to monitor, server CLI/launcher JSON and singleton compatibility, real guarded HTTP refusal/force/in-flight behavior including old server negotiation, diagnostics dry-run/no-write/atomicity/scopes/locks/expiry/errors and unchanged mandatory-event behavior. Existing journal concurrency function AST is protected and its smoke reruns for integration. Run relevant Runtime/T09/host-owned/docs smokes, source schemas/checksums/cleanliness, PTY if rendering changes require it. Review before delivery.
7. Build a new clean detached candidate from delivered 40c98942 under own .pf/tmp, overlay exact qualified public delta including the journal fix, commit locally without changing main checkout. Official release-pack/archive-test and extracted feature tests, then installed core-update plan/apply/status only. Preserve config/unowned files and automatic backup; stop/start only verified idle named Runtime through official commands with original launch settings. Verify all installed hashes, new commands and live compact metrics. Report source/archive/installed/connected-host boundaries honestly. No publication or global rule changes.

Browser verification not_applicable: terminal and local CLI only. Native POSIX execution is a separate capability boundary; do not claim it from Windows fixtures.
