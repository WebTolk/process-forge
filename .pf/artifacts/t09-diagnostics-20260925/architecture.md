# T09 architecture and implementation plan

Decisions fixed before product edits, based on accepted T01 and reproduced hook failure.

1. New stdlib-only src/processforge_core/diagnostics.py owns canonical logger, no-op, redactor, layered config, private bounded JSONL/stderr sinks, ContextVar operation binding, health and export. No Runtime/CLI/provider imports. Python logging interoperability is explicit numeric mapping, not global registration/root reconfiguration.
2. Independent optional config .pf/diagnostics.json (version 1) avoids snapshot churn. It contains project fields and scoped Work/session overrides keyed by exact identity. PF_DIAGNOSTICS JSON plus CLI invocation options are final overrides. Public schema schemas/diagnostics.schema.json describes configuration. Security/storage settings only tighten default ceilings; locked lower fields remain locked. Invalid config yields safe fallback health, not a business failure; inspection surfaces errors.
3. Logger scope owns effective config and correlation. Factory uses validated project flow root, obtains build/source hashes without recursive scans, caches only bounded logger/config state. ContextVar binding inherited by service calls; parallel requests isolated. CLI/MCP bind at request boundaries, Runtime at authorized project ingress, worker preparation emits selected metadata. Existing mandatory telemetry/event write path is untouched.
4. Hook error: route diagnostics to shared safe stderr logger; known Stop/SubagentStop returns {} on observed failure, malformed input emits no protocol output. PF_CODEX_HOOK_DEBUG compatibility selects temporary diagnostic stderr profile. No raw payload/result dump.
5. Freshness instrumentation at common project_context_check_result or Garage check path logs selected status/reasons/snapshot/source only; CLI/MCP can trace request to reason. ProcessExecutionService._emit may add metadata diagnostic after the required event succeeds; optional sink never catches mandatory write errors.
6. JSONL uses one named log family and bounded interprocess lock; rotation/retention/quota operate only that family, never arbitrary runtime files. Failed lock/sink/serializer increments counters; serious loss emits a rate-limited fixed stderr message. No recursive logging. Private state creation only under existing .pf; export checks symlinks/containment and refuses overwrite of an existing destination.
7. CLI diagnostics-status and diagnostics-export expose effective config/health and filtered safe bundle; add global --diagnostic-profile/threshold/components/sink switches. Export is local explicit output, read-only checks only, no archive upload. MCP uses same config via project or PF_DIAGNOSTICS, keeping tool schemas stable in T09. Bundle JSON format keeps manifest and sanitized records/status in one bounded artifact.

## Numeric budgets

Hard default ceilings, overridable only downward: record 16 KiB UTF-8, string 2048 characters, depth 6, items 32 per container, stack 8 frames, spans 32 per operation; config input 64 KiB. Log file 1 MiB, aggregate 8 MiB, retention 7 days, at most 8 rotations/files. Export <=4 MiB input/output records and <=2000 records; output includes truncation counts. Detailed diagnostic/trace collection requires absolute expiry <=15 minutes and <=10000 detail records; no persistent unbounded detail. Explicit CLI detail can default to 10 minutes, recorded in effective config. Lower settings must remain internally valid (file and record fit total quota).

Lock wait <=50 ms; optional fallback warning <=1 per logger per 60 seconds. Low-severity disabled calls must not invoke lazy context. Measured acceptance on current Windows host: 100000 disabled debug calls <=0.5 s median of 3 warmed trials and <=5 microseconds/call; 10000 bounded enabled in-memory records <=5 s; 10000 JSONL records <=20 s, disk size never exceeds configured quota after any write. These are local acceptance budgets, not cross-machine performance promises. Long load uses >=10000 records with reduced quota to exercise repeated rotation and detail expiry. Failure injection covers ENOSPC/read-only/broken serializer and lock failure; all preserve original result.
