No per-new-module packaging manifest was found in the inspected path. The release-test command table is explicit, and its checksum command is at `6939`; update checksum data when source files change. `RELEASE_REQUIRED_PATHS` asserts the `src/processforge_core`, `tools`, and `schemas` directories (`6287-6294`), not individual new module paths.

## Compatibility pitfalls

- Optional `off`/sink failure must not suppress `emit_process_event`, raw ingress receipts, worker completion/attempt state or explicit caller errors.
- Process event `warn` and its narrow schema are durable public compatibility; diagnostic `warning`/other severities should stay in the new logging layer and map explicitly at export boundaries.
- MCP stdout is protocol; Codex hook stdout may be protocol for specific hook types. Worker driver stdout/stderr files are task execution output, not automatically safe diagnostic sinks.
- Existing telemetry append has no rotation/quota or bounded arbitrary-object serialization; changing its JSON shape/event enum could break schema consumers. Separate diagnostic records or use an explicit versioned migration.
- Redaction currently covers recursive dict/list string values, not record-size/depth limits or all arbitrary object conversions. Sanitize before every diagnostic sink/export and bound conversion before serialization.
