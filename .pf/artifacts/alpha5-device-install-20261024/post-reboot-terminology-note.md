# Уточнение scheduler_alive в отчёте приёмки

По замечанию оператора: слова «работающий планировщик» в сообщении о проверках
обозначали только диагностическое поле существующего PF Runtime
`scheduler_alive=true`. Проверено, что жив уже существующий служебный поток
Runtime; новый общий механизм планирования здесь не внедрялся.

Это продолжение не добавляло продуктовый код, глобальный планировщик задач,
расписания, событийные триггеры или запуск агентов по ним. Общую задачу запуска
агентов по расписанию/событию оператор ещё не ставил. Она не регистрируется,
не проектируется и не реализуется в данной Work.

Уточнение относится к post-reboot-report.md, post-reboot-test-report.md и raw
полю scheduler_alive в evidence. Уже записанные фактические значения и
неизменяемые lifecycle receipts сохраняются. Предмет завершённой приёмки —
совпадение установленной/загруженной alpha5, фактические Runtime/MCP процессы,
готовность, доступ и сохранность данных.
