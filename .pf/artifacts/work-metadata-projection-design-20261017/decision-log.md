# Журнал решений

- D1: YAML остаётся источником истины; проекция производная и хранится в ОЗУ.
- D2: Один явный read pass для summary и catalog; между запросами повторно используются только компактные parse results существующего bounded cache.
- D3: Актуальность устанавливается текущим чтением и содержимым, без доверия mtime/size, TTL или доставке уведомлений.
- D4: Read pass не переживает write; произвольный request_scope не становится неявной транзакцией Work.
- D5: Разные правила активности/пустых данных сохраняются у текущих policy owners. Общая метадата не означает общий алгоритм выбора.
- D6: Completion-journal existence проверяется у каждого Run, включая terminal; валидность проверяет прежний owner по полным текущим входам.
- D7: Exact canonical selection сохраняет короткий путь, final live reads и native guards.
- D8: Не вводить второй generic cache, новый обязательный файл индекса, Runtime dependency, новые public errors или writer protocol.
- D9: Холодный парсинг и линейная проверка файлов остаются; численная скорость и footprint устанавливаются только реализацией и измерениями.
- D10: Рабочий набор компактной проекции должен реально помещаться в текущий cache budget; изменение квот обсуждается по измерениям, а не предполагается как уже решённая скорость.
- D11: Внешняя конкурентная запись не превращается в атомарную файловую транзакцию; snapshot содержит наблюдённые факты, authority проверяется отдельно.
- D12: Текущая доставка содержит документы и review сценариев. Продуктовая реализация, сборка и установка не выполняются.
