# Настройка записи событий устройства

Дата: 2026-10-17 17:13:59 UTC. Прямое дополнительное поручение пользователя во время проектирования: глобально на устройстве отключить запись сырых событий, сохранить сообщения и предложить понятные термины. Это отдельное операторское изменение существующей настройки, не реализация архитектуры проекции.

Выполнено существующей установленной PF CLI через typed configuration CRUD. Сначала проверен фактический workplace manifest/root; каталог установленного кода не использован как хранилище настроек. Device configuration отсутствовала, действовали defaults raw_hooks=true/events=true. Выполнены native create и revision-checked update только logging.raw_hooks=false. Остальные настройки сохранены: logging.events=true, runtime.garage_hooks=false, metrics.interval_seconds=10.0.

Device revision после записи и повторного чтения: sha256:8eb64975e50035d2e3e5a3e636e03eaaeb067ff8fabf91822443d7f1c4d786ad.

Повторное installed-CLI чтение подтвердило raw_hooks=false/events=true как device default. Текущий проект не имеет configuration override и наследует именно эти значения. Публичный артефакт не содержит частный абсолютный путь к workplace. Изменён только частный workplace configuration.yaml и native lock; продуктовые файлы и проектные overrides не менялись.

Три разных потока по docs/concepts/hooks-events.md и authoring/workplace-configuration.md:

| Рекомендуемый термин | Содержимое | Состояние |
| --- | --- | --- |
| Сырые хуки | Исходные payload от провайдера; отдельная optional raw history | История новых сырых хуков выключена |
| События PF | Нормализованные события проекта: session/tool/process/Work и metadata chat.message.recorded | История оставлена включённой |
| Переписка | Тексты сообщений оператора и агентов у существующего transcript owner | Не отключалась |

Альтернативы терминов: «сырые события / события проекта / сообщения чата» — ближе к внутренним именам; «сырьё / журнал PF / диалоги» — короче, но менее точно. Рекомендован первый набор из таблицы.

logging.events=false выключило бы историю нормализованных событий без отключения переписки, но пользователь такого изменения пока явно не поручал. После вопроса о различиях дано объяснение; сохранён events=true.

Изменение читается resolver на следующем ingress без Runtime restart. По коду host._ingest_event флаги независимы, а conversation path продолжает работать после admission. Проверка выполнена чтением settings и текущих owners; синтетические сообщения, hooks, внешние рассылки и перезапуски не выполнялись. Фактический новый live ingress не выдаётся за уже проверенный.

Флаг выключает optional историю, сохраняет обязательные минимальные admissions/hash/dedup и незавершённую доставку. Pending raw payload может временно храниться до finish, затем pending_record очищается. Старые записи не удалялись. Проектные явные overrides поддерживаются существующим контрактом; device setting является наследуемым default, не новым принудительным запретом во всех произвольных конфигурациях.
