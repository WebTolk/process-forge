# Проверки результатов, выбор драйвера и правила контрактов

Реализация и профильные проверки завершены. Для независимого ревью зафиксированы
18 продуктовых файлов на базе `eef4f953d935294d31d9579bc1d9eeb0d572fb94`.

`WorkOutputPolicy` дополнен проверкой обязательных результатов и вычислением
отпечатка верификации. Прежние пять методов, поля и замороженный конструктор
сохранены. Проверки используют прежний порядок путей, исключений и чтения файлов;
псевдонимы waiver, необязательные результаты и повторное чтение отчёта не изменены.

`RuntimeDriverSelectionService` выбирает драйвер по текущей задаче или сохранённой
команде работника через существующие Core-каталоги. Сохраняются приоритеты,
копирование прямой ссылки и цепочка причины ошибки. `ProjectMetadataReader`
дополнен локальным чтением workplace manifest; более широкий поиск workplace
остаётся прежним. `common.json_io.json_read` — единственный владелец прежнего
JSON-примитива, включая фактические типы возвращаемых значений и нативные ошибки.

`PlatformContractPolicy` содержит девять прежних проекций контрактов с конкретным
каталогом для идентичности платформ. `ProcessAuthoringValidationService` владеет
проверками логики, сопутствующих файлов и их путей; сюда же перенесены три набора
констант. Общая privacy-функция использует существующее правило публичных путей.
Прежние поля, методы и данные metadata/privacy сохранены.

`ProcessExecutionService` получил две независимые необязательные зависимости:
`output_checks` и `verification_fingerprint`. Это аргументы только по имени;
обычные значения по умолчанию — методы Core, явный `None` означает недоступность.
Три позиционных аргумента, frozen, repr/compare прежних полей сохранены. Изменены
только четыре связи фабрики автоматики. Прочие возможности legacy core остаются
прежними и ленивыми. Существующие фикстуры передают свои возможности явно,
сохраняя все утверждения и сравнение с классом до рефакторинга.

Из монолита удалены 19 определений и три объявления констант. Полный AST,
включая 832 оставшихся определения, отличается только предусмотренными
импортами, композициями и вызовами. Семь изменённых модулей потребителей,
включая приложение, Host, сервис и проверки, содержат только заявленные замены.
Неизменённая ловушка `smoke_session_identity_roundtrip.py` продолжает доказывать,
что чтение присутствия не обращается к монолитному JSON. Spy допуска терминального
работника перенесён на действительного владельца выбора драйвера; утверждения
сохранены. В сервисе сохраняется вычисление `self.core` до ленивого импорта.

Четыре native-вклада содержат полное сравнение AST, сигнатур и аннотаций всех
19 алгоритмов/примитивов и констант на точных текущих байтах. Основной исполнитель
получил 63 успешных сравнения, включая 19 карт аннотаций и шесть нативных
исключений. Проверены обычная композиция без legacy callbacks, явный `None`,
независимость проверок, свежий fingerprint, содержимое и metadata при прежних
размере/mtime, реальные ссылки драйвера, companion files и прямой/скопированный
Core без импорта транспорта. Runtime при этом не запускался.

Пройдены девять существующих профильных скриптов и существующая функция
`terminal_worker_admission`: автоматика (20 сравнений с прежним классом), границы
отчёта, пакет задач, состояние Work (24 теста, один исторический baseline-тест
пропущен), идентичность сессии, реестр драйверов, материализация авторинга,
выбор платформы и соответствие документации. Допуск терминального работника —
71/71. Полные recovery/scheduler/release/archive/installed/connected-host проверки
и проверки ZIP не выполнялись. Создание symlink недоступно; эта ветвь не принята.

Профильная проверка обнаружила пропущенный префикс существующего импорта
`_ProjectMetadataReader` у шести новых вызовов. Исправлены только эти вызовы;
упавшая проверка границ отчёта после исправления прошла. Успешное сравнение
автоматики на неизменённых зависимостях сохранено. Вывод `unittest` в stderr
признан по сохранённому `OK` с exit 0, без повторного запуска. В частной проверке
порядка bootstrap исправлен путь фикстуры; продукт не менялся.
