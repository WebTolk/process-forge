# PF monitor: формат uptime

Выполнена одна продуктовая задача —
`pf-monitor-uptime-format-20261019`. Uptime отображается как
годы/месяцы/дни/часы/минуты: например, `00/00/02/03/15` для двух дней,
трёх часов и пятнадцати минут. Легенда `[y/mo/d/h/min]` различает месяцы
и минуты; неизвестное значение остаётся `unknown`.

Используются стандартные `datetime`, `timedelta` и `calendar.monthrange`.
Полные календарные месяцы отсчитываются от исходных дня и времени в UTC;
день при необходимости ограничивается последним днём целевого месяца.
Двенадцать полных месяцев образуют год, остаток выводится в днях, часах
и полных минутах. Числовая метрика и JSON сохраняют прежний формат.

Изменены монитор, новый файл из 36 тестов, английская и русская документация
монитора и соответствующие контрольные суммы. Для штатной проверки инвентаря
также удалены две лишние записи о метаданных `release/`, которые не входят
в его публичный набор файлов. Сами файлы опубликованной alpha1 не менялись.
Ruff отформатировал владельца и потребовал заменить три локальные лямбды
эквивалентными функциями; AST-сравнение подтвердило сохранение остальной
логики. Все прежние импорты сохранены, добавлены только два стандартных.

Все тесты завершились успешно: PF 274/274, публичные проверки 3/3,
supervisor-stress 6/6, pytest 142 теста и 42 подтеста. Один pytest-тест
пропущен из-за прав Windows на символические ссылки. Ruff, форматирование,
mypy четырёх изменённых функций и проверка новой docstring прошли.
Полный mypy владельца сохраняет девять прежних ошибок; новых нет.
Подробности и границы проверки: [test report](test-report.md),
[code quality](code-quality-report.md), [review](review-findings.md).

Работа выполнена одним исполнителем по закреплённому процессу
`software-feature-development@1.2.1`, Work
`garage-pf-monitor-uptime-execution-20261020-implement-the-explicitly-aut`.
Исходная плановая карточка закрывается штатным `task-complete`, без расширения
её старого planning-only scope. Другие реализации не входят в этот результат.

Доставка — отдельный коммит только дельты задачи в `dev`, push в `origin`
и `gitverse` и чтение SHA обеих веток. Для GitVerse используется существующий
токен через askpass при отключённом credential helper. Фактический SHA и
результаты доставки сохраняются в приватной квитанции `git-delivery.json`
этой задачи и сообщаются пользователю после чтения обоих remote. После
этой доставки работа останавливается по последнему поручению пользователя.
