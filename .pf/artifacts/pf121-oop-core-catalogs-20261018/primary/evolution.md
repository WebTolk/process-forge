# Выводы девятого этапа

Подготовленный вход shell-исполнителя должен явно перечислять обязательные
архитектурные документы, знания и конкретные реализации зависимостей. Одного
широкого read scope и упоминания девяти документов недостаточно для закрытого
prepared input. Файловый PF CLI является рабочим интерфейсом этого source checkout;
устаревший подключённый MCP не используется и не исправляется в рамках рефакторинга.

Три остановленных назначения заменены после штатной отмены на преемники с теми же
правами продуктов, но полными обязательными входами. Старые капсулы и отчёты
не изменялись. Для новых ролей введены отдельные пути квитанций lifecycle;
один подтверждённый переход восстановлен из сохранённого ответа без повторения.

Прежний механизм путей переиспользован, а различия двух представлений записи
сохранены явным сопоставлением полей в Core. Это сохраняет модель и aliases,
не создаёт копию правил или универсальную фабрику. Различия project last-wins
и workplace search first-wins сохранены как отдельные действующие контракты.

Точечная проверка должна подтверждать, что вход действительно доходит до нужной
ветви. Для зависимостей используется `dependencies.blocked_by` с явными False/True,
изменением статуса и ошибкой YAML. Успех существующего скрипта с префиксом WROTE
и последующим PASS JSON определяется по сохранённому выводу, без повторного запуска.

Существующие процессы, правила, пакеты знаний, разрешения, инфраструктура и
extension-механизмы не меняются. OOP-эпики остаются открыты. Следующий перенос
выбирается после двойной доставки и перечитывания исходной архитектуры.
