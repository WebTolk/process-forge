# Run Plan: Ближайшая задача: понятное окно PF app server или системный трей Windows

Objective: Приоритет: ближайшая задача для следующей сессии. Сейчас зарегистрировать задачу, реализацию не начинать.

Проблема со слов пользователя: при запуске pf app server появляется пустая консоль Python, которая выглядит зависшей. Брендированный PF monitor пользователь запускает отдельно. Непонятное окно вызывает вопросы; пользователь может просто закрыть его, не понимая последствий для работающего сервера. Воспроизведение и точный способ запуска уточнить при исследовании.

На этапе проектирования выбрать подходящий вариант:
1. Сделать консоль информативной: показать брендинг/логотип PF, версию, PID и полезные сведения о работающем сервере из PF monitor; пояснить назначение окна и способ отдельно открыть монитор.
2. Запускать сервер свёрнутым в системный трей ОС. Для Windows продумать оформление приложения: иконку, контекстное меню, доступ к состоянию и отдельному запуску монитора, а также поведение при сворачивании, закрытии окна и явной остановке сервера.

Вариант пока не выбран; не считать оба варианта обязательными к реализации. PF monitor остаётся доступен для отдельного запуска пользователем, автоматический запуск монитора не согласован.

Критерии результата: пользователь понимает, что PF app server работает, может узнать версию и PID; интерфейс не выглядит пустой зависшей консолью; для выбранного варианта однозначно определены закрытие/сворачивание/остановка и доступ к монитору. Если выбран трей, согласовать Windows-иконку, состав меню и жизненный цикл приложения до реализации.

Границы текущего поручения: только запись ближайшей задачи и передача следующей сессии. Не запускать/не перезапускать PF app server, Runtime, MCP или monitor, не менять продуктовый код. Сначала отдельное исследование и выбор решения; текущие изменения монолита и завершённые OOP-задачи не переоткрывать.
