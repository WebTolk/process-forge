# ProcessForge 1.3.0-alpha1

This first alpha freezes the accepted development checkpoint after 1.2.0.
Public CLI/MCP contracts and file-only use are retained. Product, process,
schema and startup-contract versions remain independent.

The checkpoint includes the accepted Core separation, portable shared Python
QA and assurance requirements, native Codex hook setup during Forge
initialization, consistent CLI/MCP context checks across LF/CRLF text, and
the qualified Windows App Server launch and disconnected-client handling.
Update selection now orders prereleases and final releases correctly;
build metadata does not create a newer update, and resource constraints keep
their existing rules.

The alpha is published separately from stable 1.2.0. Further Core refactoring,
complete Core typing and systematic unit coverage remain future work.
Release publication does not update an existing device or reload its Runtime/MCP.

Use the existing [installation guide](../getting-started/installation.md) and
[Core update contract](../concepts/core-update-manifest.md) for an explicitly
planned installation. Preserve existing project state and update backups.
