# ProcessForge 1.3.0-alpha4

This cumulative prerelease separates project context work from workplace search
indexing. It includes the previously qualified alpha3 changes.

Project initialization, context refresh, repair, context reads and search observe
the existing index. They do not build, queue or wait for documentation indexing.
Context freshness and required-resource checks remain independent from missing,
stale, building or failed search state. Resource changes mark derived search state
stale for a later explicit maintenance pass.

Run workplace indexing explicitly in an authorized workplace scope:

```bash
python bin/pf.py search-index-maintain --workplace <workplace> --apply --json
```

The CLI and cold future-scheduler job call the same Core component. Existing
project-scoped `search-index refresh`, `rebuild` and `tick` retain their options
and selected-resource scope while sharing writer coordination and recovery.
The future PF scheduler can invoke the cold job; periodic execution is deferred.

`knowledge-add-batch --workplace <workplace> --package <package> --batch-file
batch.yaml --apply --json` adds YAML records through existing per-item
transactions. It reports individual failures and indexes only successful resource
IDs once at the end, retaining unrelated documents. Dry-run is read-only. An
indexing failure preserves additions and produces a nonzero exit. A targeted pass
clears only known pending changes covered by its successful IDs; old failures and
unknown/unselected changes remain pending. Full index reconciliation
remains the separate explicit workplace command.

The default backend remains SQLite FTS5 at
`<workplace>/runtime/search/local-resource-search.sqlite`. A narrow backend
contract separates indexing from storage. Additional SQL/vector backends and a
RAG pipeline remain separate work using the planned common DB infrastructure.
Public CLI/MCP query filters and current project/Work access remain enforced.

Manual maintenance serializes writers with an OS-owned lock, records durable
running/terminal state and supports an explicit retry after interruption. Readers
open existing SQLite databases without creating them or waiting for the default
busy timeout. Unknown diagnostics are bounded and private paths are redacted.

This is an opt-in alpha channel. Stable 1.2.0 remains the stable release. Exact
source/archive qualification, native review and published asset hashes accompany
the delivery evidence; this release does not itself update an installed device.

An existing derived cache may need one explicit full maintenance pass to establish
the new root/metadata identities. Context refresh never performs that migration.
