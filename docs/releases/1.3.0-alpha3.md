# ProcessForge 1.3.0-alpha3

This cumulative alpha includes the accepted changes after alpha1, including
the alpha2 development archives, and adds explicit SQLite journal maintenance.

The `journal-maintenance` CLI provides backup, verify, restore, inspect and
import operations. Backups use SQLite's backup API, include committed WAL data
and carry a manifest, hashes and an integrity check. Restore creates a new
destination and refuses an existing destination. Each database is backed up
independently.

Legacy journal inspection reports corruption before import. Applying an import
preserves the original journals and quarantines exact invalid bytes with source
line, byte offset, length and SHA256 provenance. Skipping invalid rows requires
explicit `--skip-invalid`. Migration retains the existing journal identities,
deduplication and interruption barriers, verifies stored records and supports
repeat execution. The original `tools/migrate-hook-journals.py` entrypoint remains
available. See the [maintenance guide](../concepts/sqlite-journal-maintenance.md)
for commands and recovery steps.

Other accepted changes since alpha1 include Kimi native ingress compatibility,
calendar uptime in the monitor, evidence guidance in Work responses, advisory
artifact authoring diagnostics, and shared accounting for available token usage
and execution time. Accounting coverage remains explicit for providers or
attempts that do not report complete usage.

The maintenance implementation uses small Core services, injected operation
ports and the existing journal repositories. Public CLI/MCP contracts and
file-only operation remain supported. Further Core refactoring is separate work.

This is a prerelease on the opt-in alpha channel. Stable 1.2.0 remains available.
Publication alone does not update an installed device or reload Runtime/MCP.
Use the [installation guide](../getting-started/installation.md) and preserve
existing state and update backups when planning an installation.
