# ProcessForge 1.3.1

## Codex workers

The `codex-exec` driver reads the model catalogue and supported reasoning levels
from the configured Codex CLI. Use `pf runtime-driver describe --driver codex-exec
--catalog --project-root .` to inspect them. Launches without explicit choices
use the agent's configuration. [Driver guide](../concepts/runtime-drivers.md)
[PR #167](https://github.com/WebTolk/process-forge/pull/167)

## Storage and updates

- Migrate the event journal of a registered project while a compatible Runtime
  is running. The explicit `--project-events` operation verifies a backup and
  can resume an interrupted migration.
  [Journal maintenance](../concepts/sqlite-journal-maintenance.md)
  [PR #144](https://github.com/WebTolk/process-forge/pull/144)
- Select an eligible version from the update plan and roll back an applied
  package even after candidate refresh or when the upstream source is unavailable.
  [Update lifecycle](../concepts/update-lifecycle.md)
  [PR #166](https://github.com/WebTolk/process-forge/pull/166)
  [PR #140](https://github.com/WebTolk/process-forge/pull/140)

## Upgrading from 1.3.0

Confirm the Core file update. Projects with ready storage need no data migration
for this patch. If a project already reported `storage_migration_required` on
1.3.0, complete its existing migration before resuming writes. The `--project-events`
option is for servicing one project’s event journal when needed. [Update and recovery](../concepts/update-lifecycle.md) · [Storage migration](../concepts/sqlite-journal-maintenance.md)
