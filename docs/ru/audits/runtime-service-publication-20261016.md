# Публикация служебного состояния Runtime, 16 октября 2026

Статус: исправление исходников независимо принято. На устройстве остаётся
прежний dev 75 до отдельного чистого накопленного архива и обновления.
CPU Runtime, подключённый хост и публичная 1.2.0 здесь не квалифицируются.

Нативное восстановление завершилось Windows error 5 при замене service.json.
Созданный PID завершился; после подтверждения stale и отсутствия живого
владельца выполнено одно контролируемое восстановление. Независимые проверки
удерживаемого destination-reader воспроизводят прежний механизм 5/5, но не
устанавливают исторического держателя. ACL, ОС, регистрация служб и прежние
временные файлы не менялись.

Существующая публикация передана конкретному Core RuntimeServiceStateWriter;
функция service делегирует ему. Подготовка, UTF8 и нативные окончания строк,
сортированный JSON с отступами, один уникальный tmp и атомарная замена сохранены.
Только замена в Windows при кодах 5/32/33 допускает повтор после первого отказа:
частное окно 50мс, не более пяти повторов, ожидания в пределах остатка времени.
Это не ограничение длительности непрерываемого OS call или планирования потока.
Успешная замена сохраняет успех после медленного вызова.

Неизвестные, non-Windows и preparation ошибки остаются немедленными; постоянный
подходящий отказ возвращает исходную ошибку. Destination не удаляется; нет
неатомарного fallback, повтора подготовки, кэша или новой публичной настройки.
Остальные lifecycle, singleton, authorization и первоначальные assertions и
таймауты smoke сохраняют AST. Core импортируется без CLI, Host и transport.

Прошли 26контролей исполнителя и 41независимый контроль. Первый review отклонил
новый наблюдатель теста R1: подготовка ошибочно входила в окно повторов. Поправка
фиксирует первый отказ замены и порядок conflict/release; настоящий успех,
один tmp и точные байты сохраняются. Проба с 60мс подготовки отклоняет прежний
assertion и проходит с исправлением; два production-файла не менялись.
Исходный unwrapped singleton/orphan smoke primary прошёл за 2,101651с после R1,
без подмены allocator, PID probe или таймаутов. Sandbox-отказы tasklist до и
после изменения также сохранены.

Исходники, архив, установленные байты, восстановленный Runtime и фактически
подключённый хост проверяются отдельно. Высокий CPU и стоимость журнала/каталога
требуют своих измеренных исправлений. Перед публичной 1.2.0 нужны полная
накопленная квалификация, подробный отчёт и отдельное одобрение пользователя.
