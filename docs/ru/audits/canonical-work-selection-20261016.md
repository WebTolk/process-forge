# Канонический Выбор Work — 2026-10-16

По прямому решению пользователя проверенная полная пара Run+Assignment теперь
выбирается без исторического каталога. Существующий Core-валидатор подтверждает
объявленные ID, владельца, единственное членство и совместимость процессов.
Четыре актуальных чтения сохраняют финальное перечитывание. Остальные запросы
и недоказанная начальная пара используют прежний каталог. Ошибки выбранных
reader не подавляются; отказ финального доказательства даёт
`work_identity_mismatch`. Приоритет над чужими alias и независимость от ошибок
посторонней истории изменены явно; полный паритет со старым алгоритмом не заявлен.

Владелец — существующий `WorkSelectionService`. Новых портов, подсистем,
постоянного индекса и кеша между запросами нет. Context/access/intent, Run lock,
process pins и completion recovery остаются в прежних владельцах. ООП-программа
этим срезом не завершена.

Primary независимо принял четыре запечатанных файла нативного executor.
Семь исходных focused scripts прошли повторно без его allocator-обвязки.
Три необязательных historical baseline skips остаются явными. Матрица содержит
85 исходов и отдельный next-request контроль, с разделением сохранённых
и намеренно изменённых исходов. Все 60 финальных образцов, шесть медиан и числа
чтений пересчитаны из замороженных доказательств.

Пять чередующихся direct CLI-пар на настоящем выбранном Work дали одинаковые
ответы при неизменных документах: прежнее установленное ядро — медиана 6,351549 с,
проверенные исходники — 1,349780 с, включая одинаковый запуск одного Python/CLI.
Старый owned Runtime работал, оба shell-провайдера завершились. В отдельном
cProfile общий каталог присутствует только до исправления; времена профиля
не входят в медианы. На синтетическом каталоге 400 Run/800 Assignment число
чтений сократилось с 1202 до четырёх, выбор — примерно с 3,2 с до 5–6 мс.
Это ограниченные source-результаты; новое установленное ядро, Runtime,
подключённый хост и универсальный SLA ими не квалифицированы.

Четыре чтения не атомарны. Положительный binding lookup заменён портом стенда;
полный continuation/transition lifecycle и filesystem aliases селектора не
квалифицированы заново. Отсутствие PyYAML проверено для import/fallback селектора,
не всего reader stack. Неудачное начальное доказательство добавляет два чтения
перед старым каталогом. Общий diagnostics smoke остаётся отдельной неуспешной
проверкой; условия и бюджеты не ослаблялись.

Накопленный dev-архив, обновление устройства и профиль после него подтверждаются
отдельно. До стабильного 1.2.0 обязательны подробный отчёт готового кандидата
и отдельное одобрение пользователя на публичные теги, файлы и канал обновлений.
