# SQL-снимки фаз перед 1.3.0

SQL-хранилище исполнений уже выбирает точную попытку через индексированный head. Перед публикацией подготовки или сборки результата дополнительно снимается файловый снимок. Раньше он перечислял каталоги всех попыток и сохранял содержимое исторических файлов подготовки, retry, процессов и scratch. Публикация повторно читала эти файлы под существующими admission и task locks.

SQL-путь теперь выбирает ноль или один каталог по авторитетному head. Для него сохраняется весь прежний набор файлов, включая terminal head при сборке результата. По-прежнему проверяются корневые observations, assignment, capsule, конфигурация, prompt, ссылка prepared input и явные ссылки команды на output. Действующая ссылка может вести в предыдущую попытку, пока заменяются projections.

Перед решением об отсутствии проверяется приватный путь выбранного каталога. Ошибка SQL routing, небезопасный путь или недоступное состояние приводят к отказу. Отсутствующий head не позволяет выбрать попытку по status.json. Legacy retry publication сохраняет прежний полный снимок.

Изменение сужает набор файлов, изменения которых отменяют SQL-публикацию: посторонний архивный sidecar больше её не блокирует. Проверки текущих файлов, allocation, SQL finalization CAS, reservation запуска, collection, callbacks и порядок блокировок сохраняют владельцев. SQL-транзакция не охватывает capture, создание процесса или ожидание. При отказе подготовки могут сохраняться planned allocation и материалы восстановления.

## Проверка

Поддерживаемый lifecycle suite проверяет публичную подготовку, автоматическую подготовку при start, синхронное завершение и collection, повторную подготовку и prepare-skipped при реальном работающем child. Дополнительные случаи проверяют конфликты текущих файлов, изменения постороннего архива, отсутствие head, существующие и небезопасные каталоги, broken binding и сохранение legacy file conflicts.

Suite запускается через настроенные Windows и Linux repository jobs:

    python -m pytest -q tests/executions/test_lifecycle.py

Масштабная проверка сохраняет одинаковое текущее состояние и увеличивает terminal SQL history до 10 000, 100 000 и 400 000 записей. Выбранные файлы, фактическая SQL-работа, query plans, warm percentiles и fresh-process observations учитываются отдельно от наполнения fixture. Ограниченный набор файлов не ограничивает размер каждого текущего файла.

Этот срез не закрывает issue17 и общую миграцию/readiness. Cancellation discovery, legacy retry discovery и обходы Work catalog/pending journals остаются отдельными причинами задержек. Существующие SQL-хранилища сохраняются; консолидация и дополнительные backends не входят в это исправление.
