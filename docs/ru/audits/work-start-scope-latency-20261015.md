# Задержка проверки областей при создании Work — 15 октября 2026 года

Измеренное узкое место — алгоритм проверки пересечений областей записи.
Профилированное создание Work заняло 608,553 секунды, из них 590,723 секунды
(97,07%) — проверка областей. Другая задача до исправления создавалась 291,740
секунды. Области различались; эти наблюдения не образуют повторный сравнительный
тест.

Сравнения при создании Work, в supervisor tick и при проверке плана оркестратора
теперь выполняет `ScopeConflictService`. Разные обязательные буквальные префиксы
доказывают, что маски не пересекаются. Для таких пар, точных путей и одинаковых
масок список файлов не требуется. Неоднозначные пары используют один отложенно
построенный и нормализованный список на операцию. Записи assignment по-прежнему
читаются заново при каждой проверке. Между операциями кеша нет.

Поля, причины и порядок конфликтов, приоритет запретов, зависимости, проверенная
передача владения предшественником и прежний состав учитываемых файлов сохранены.
Общий существующий файл по-прежнему даёт `glob_matches_same_file` до перехода к
консервативному `possible_glob_overlap`. Блокировки, восстановление, публичные
контракты CLI/MCP и разрешённые политикой исключения сохранены.

## Измерения

Для каждого сценария выполнено по пять повторов до и после исправления на одном
дереве из 2 004 файлов с одинаковыми упорядоченными областями. Время включает
построение списка и сравнение, исключая запуск и импорт интерпретатора. Хеши
результатов совпали.

| Сценарий | Медиана до | Медиана после |
| --- | ---: | ---: |
| 240 пар непересекающихся масок | 3,052751 с | 0,001154 с |
| Общие буквальные префиксы | 0,300242 с | 0,196319 с |
| Пустые буквальные префиксы | 0,270876 с | 0,247330 с |
| Точные пути и маски | 0,143903 с | 0,000068 с |

Пять проверок текущей задачи без изменения состояния на настоящем каталоге из
855 записей assignment заняли 1,628–3,287 секунды, медиана — 1,782 секунды.
Отдельный запуск cProfile не обнаружил вызова построения списка файлов. Измерена
проверка областей; полное создание Work и установленное ядро измеряются отдельно.

## Границы приёмки

Существующий smoke областей расширен: 484 сравнения с прежним поведением, точные
причины и порядок, отсутствие лишнего обхода, один список на операцию, изменения
файлов и assignment между операциями, запреты, зависимости, завершённые и
повреждённые записи. Сохранены нативные проверки CLI, передачи владения и повторов.
Если хост не позволяет создать символическую ссылку на каталог, соответствующая
проверка пропускается. Результаты направленных проверок исходников и точного
архива фиксируются в отчёте управляемой задачи.

Неоднозначные маски всё ещё могут потребовать обхода дерева. Загрузка каталога и
YAML остаётся отдельным источником задержек. Универсальное создание Work быстрее
секунды и приёмка установленного Core, Runtime и подключённого хоста не заявляются.
Проверка устройства следует отдельным управляемым дев-релизом.
