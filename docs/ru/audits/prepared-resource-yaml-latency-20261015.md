# Разбор ограниченных YAML-снимков prepared resources — 15 октября 2026

Ограниченный читатель prepared snapshot теперь использует существующий безопасный
загрузчик Core: CSafeLoader при наличии и прежний Python SafeLoader как fallback.
Новой зависимости или кеша нет.

Сохранены порядок и причины отказов для symlink, containment, размера, чтения
актуальных байтов, UTF-8, типа mapping и хеша исходных байтов. Native collection
по-прежнему проверяет prepared-input, источники, ресурсы, текущие права, stage,
принадлежность output, locks и recovery.

## Сопоставимые измерения

По пять чередующихся native collect-engine вызовов на одной неизменной governed
фикстуре существующего recovery smoke. Первый native collect уже создал receipt;
повторные вызовы выполняли настоящую валидацию. Эталонный читатель извлечён без
изменений из Git-коммита `9b81359252c340fd45fb519ed361a32412b84a38`; второй —
действительно изменённый исходник. Setup, импорт и запуск интерпретатора вне
измерения. Общий установленный Runtime продолжал работать: это прогретый сценарий
при фоновой нагрузке.

| Операция | Медиана до | Медиана после |
| --- | ---: | ---: |
| Native collect engine | 0,719005 с | 0,643369 с |

Совпали все хеши результатов и полная опись байтов фикстуры с первоначальным
эталоном. Отдельный подсчёт сохранил 395 разборов: 387 C / 8 Python до и
389 C / 6 Python после. Подсчёт и cProfile не входили в пять обычных замеров.
Выигрыш в этой фикстуре около 11%; ускорение живого Runtime и полного создания
Work этим измерением не установлено.
Одна пара оказалась на 7,84% медленнее; пять пар не устанавливают стабильную
гарантию скорости или статистическую значимость.

Ранее изолированно проверен существующий operation cache: число разборов
снизилось с 395 до 64, но медиана выросла с 0,687107 до 0,859389 с. Эксперимент
отвергнут, в продукт он не попадал. Меньшее число разборов само по себе не
доказало ускорения.

## Проверки и оставшаяся работа

Совпали 38 упорядоченных случаев ограниченного читателя: 15 настоящих файлов
текущих/исторических снимков с 14 различными raw-хешами, типы opaque-полей, aliases/cycles, BOM, malformed/unsafe
YAML, неверный UTF-8, non-mapping root, отказы путей/размеров, fallback, изоляция
мутаций, изменения при прежних size/mtime и удаление. Обычный Core-only import
не загрузил legacy CLI. Symlink проверен здесь инертным контролем. Физические
symlink/junction этого helper не проверялись; соответствующий recovery-контроль
относится к другой границе private-path.

Существующие source-проверки прошли с прежними native-лимитами: prepared context
59,58/360 с, recovery 32,41/240 с, request scope 0,59/180 с. Новых smoke entry и
увеличения timeout нет. Независимое ревью и точные квитанции поставки сохраняются
отдельно в материалах governed Work. Независимый ревьюер принял source-изменение
с оговорками и без блокирующих замечаний: воспроизвёл 38 строк, заново хешировал
162 файла native-фикстуры и пересчитал распределения. Native collect и три полных
smoke он не повторял.

С PyYAML 6.0.3 подтверждено различие backend-синтаксиса: внутренний tab в plain
scalar, создаваемый native emitter, либо tab после двоеточия C принимает, Python
отклоняет. Рукописный escape непарного surrogate даёт обратный результат на этой
границе. Потеря уже успешно создававшегося native preparation не показана.
Паритет ограничен сохранённым корпусом; универсальная эквивалентность SafeLoader
не установлена.

Разбор передан существующему владельцу Core. Legacy callbacks авторизации
prepared resources ещё не перенесены; все пять ООП-эпиков открыты. Выбор каталога
и повторное построение context остаются отдельными затратами. Source, archive,
установленный Core, настоящий Runtime и подключённый MCP приложения требуют
разных доказательств. Этот source-результат не означает готовности стабильной
1.2.0 и не разрешает её публикацию.
