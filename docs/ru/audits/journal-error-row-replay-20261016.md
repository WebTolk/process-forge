# Повторный разбор повреждённых строк журнала, 16 октября 2026

Статус: исходники независимо приняты. Нужны отдельные накопленный частный
dev-архив, установка и профиль фактического Runtime. Публичная 1.2.0 требует
подробного отчёта и отдельного одобрения пользователя.

Существующий Core ProcessEventJournal хранит один ограниченный кэш первых
позиций ID и упорядоченных повреждённых/пустых строк только в памяти. Каждый
поиск читает и хеширует весь текущий журнал. Изменение байтов, неизвестные
parser/reader, более глубокий вызывающий стек, отсутствие ID и предел 16 МиБ
сохраняют обычный разбор. Ранний дубликат при холодном поиске не создаёт
неполного индекса. Повреждённые строки до первого найденного ID разбираются
повторно; Host сохраняет обработку пустых строк и прежний путь для старого
или тестового Core. Публичные CLI/MCP/schema и полномочия доступа не меняются.

При смене политики ошибок разбор продолжается строго после уже обработанной
строки; её конструктор и прежний префикс не повторяются. Ошибка выделения
памяти при сравнении необязательной политики означает промах кэша. После
повреждённой истории только распознанный стандартный C-сериализатор может
дополнить сведения о новой записи; неизвестный сериализатор отключает кэш
без лишнего конструктора ошибки после fsync. Подготовка, межпроцессная
блокировка, байты, flush/fsync, дубликаты и hooks после снятия блокировки
сохраняют прежние границы. Legacy-обёртка CLI не менялась.

Первое независимое ревью v2 отклонено по R1/R2 и сохранено. R1/R2 подтверждены вторым ревью, которое отклонило R3. До сравнения
сепараторов теперь проверяется точный строковый тип без пользовательского
callback; исправление принято третьим узким ревью. Пройдены исходный concurrency smoke с необходимыми регрессиями,
неизменённый ingress и ограниченные проверки ошибок, порядка, долговечности,
памяти и четырёх параллельных писателей.

На одной истории 101 379 731 байт с одной повреждённой строкой пять чередующихся
пар по четыре вызова, включая первый холодный поиск, сохранили результаты
и точные выходные байты. Медиана wall/CPU append: 5,197518/4,84375 →
2,511963/2,109375 с; поиска: 5,470902/5,296875 → 1,866624/1,671875 с.
Прежний установленный Runtime работал; допуск и подготовка последнего
нативного ревью пересеклись с частью исходных серий. Это наблюдения операций
исходников, без доказательства тихого CPU Runtime, создания Work, установки
или фактически подключённого хоста. Полное чтение/хеширование остаётся линейным,
внешняя запись инвалидирует сведения.
