# Привязка Каталога Диагностики MCP — 2026-10-16

Необязательная обёртка диагностики старых операций теперь сравнивает с сессией
и project ID, и канонический путь. Для другого каталога с тем же ID сохраняется
существующий пустой приёмник журнала. Исправлено одно условие; основной
диспетчер и его ответы сохранены.

Одиннадцать изолированных проверок используют настоящие обёртку, диспетчер
и журнал JSONL, с явными портами стенда для сессии и свежести контекста. Две
формы передачи сессии прежде создавали журнал в чужом каталоге с тем же ID;
после исправления диагностический каталог там не создаётся. Привязанные
и нормализованные пути, выбор только по сессии и поддерживаемый Garage-запрос
только с каталогом сохраняют записи с верным request ID. Разные ID, конфликтующие
и неизвестные сессии, отсутствующий каталог сохраняют исходы. Все одиннадцать
ответов совпадают с прежними. Работающий Ledger и подключённый хост не проверены.

Независимое нативное PF-ревью воспроизвело все 22 исхода до/после и отказ
контрпримера со старой обёрткой; блокирующих замечаний к исправлению нет.
Обнаружена прежняя граница: конфликт настроенной и запрошенной сессий без
`project_root` в обеих версиях создаёт две записи и lock-файл в привязанном
каталоге до ответа `session_mismatch`. Исправление не обещает отсутствия файлов
для каждого отклонённого запроса и не вводит общую предметную проверку доступа.
В ревью необязательные сведения о сборке использовали штатный запасной путь
после отказа в чтении тела файла версии за пределами разрешений.

Действующие проверки MCP JSON-RPC, action tools и отсутствующей сессии прошли.
Общая проверка диагностики падает на прежнем условии многопроцессной записи;
неизменённая проверка предыдущего коммита также падает там. Наблюдение шести
дочерних писателей воспроизвело два отказа `PermissionError` при получении
Windows-блокировки у одного писателя в пределах прежних 50 мс ожидания. Ошибка
квалификации остаётся открытой. Условия и бюджеты сохранены; исправление MCP
не меняет блокировку журнала.

Исходники, чистый кандидат и архив, установленное ядро, Runtime и подключённый
MCP требуют отдельных доказательств. Для накопленного кандидата 1.2.0 необходима
полная квалификация. Стабильный тег, публичные файлы релиза и канал обновлений
требуют подробного отчёта и отдельного одобрения пользователя.
