# Порядок инициализации

Используйте этот порядок для новой установки ProcessForge, workplace и проекта:

1. Проверить [требования](../requirements.md) и [установить](installation.md)
   дистрибутив ProcessForge в изолированное Python-окружение.
2. Проверить сам ProcessForge.
3. Для настройки с участием человека по умолчанию запустить пошаговую настройку
   workplace; прямой вызов `workplace-init` использовать при заранее
   определённых ответах для автоматической настройки.
4. Настроить константы путей и корневые каталоги.
5. Настроить корни знаний, особенно корни локальной документации.
6. Зарегистрировать нужные сценарию инструменты и необязательные MCP-серверы.
7. Создать или импортировать пакеты знаний.
8. Создать повторно используемые шаблоны.
9. Создать контракты платформ.
10. Подключить проект.
11. Начать управляемую работу через `pf.context` и `pf.work.start`; создавать
    отдельный пакет задач, только если нужен такой сценарий.
12. Создать собственные процессы, если они нужны.

## Почему контракты платформ создаются позже

Контракт платформы объединяет уже существующие пакеты знаний, шаблоны,
инструменты, MCP-серверы, процессы, правила оформления кода и возможности
(`capabilities`). Он не создаёт эти зависимости вместо их авторов.

Не начинайте с контракта платформы, если обязательные пакеты, шаблоны или
инструменты ещё не созданы. Сначала подготовьте или зарегистрируйте зависимости.

Базовые языки и веб-технологии тоже относятся к зависимостям. Описывайте их
как пакеты знаний и возможности, затем подключайте к нужным платформам.

Большие деревья документации и исходников храните отдельно от публичных
манифестов пакетов. Ссылайтесь на них через корни знаний workplace, например
`knowledge_roots.local-docs`, и ресурсы пакета с `path_ref`.

## Среды агентов

Не копируйте весь репозиторий ProcessForge в `.codex`, `.claude`, `.agents` или
похожие папки конфигурации агентов.

Установите ProcessForge один раз как инструмент, инициализируйте workplace и
добавьте короткую инструкцию в конфигурацию агента: где установлен ProcessForge.
Для входа используйте корневой `AGENTS.md` (в старом проекте без него — `.pf/AGENTS.md`).
См. [политику входа](../concepts/agent-entry.md): одного указателя недостаточно,
чтобы подтвердить загрузку инструкции агентом.
