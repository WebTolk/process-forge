# Хуки агентов при инициализации проекта в Forge

Инициализация автоматически подготавливает поддерживаемые проектные хуки, если
у связанного рабочего места `coordination.default_project_mode: organized`
(Forge). `project-init`/`project-onboard` и
`pf.project_initialization.initialize` используют общий Core workflow и прежнее
явное подтверждение apply. Dry-run только показывает план, включая
`.codex/hooks.json`, когда он требуется.

Решение принимает действующий reader рабочего места. Поле проекта
`process_forge.mode: file_only` не отключает настройку. Доступность Director сама
по себе не означает Forge; проектный override `organized` не переводит рабочее
место Garage в Forge. Инициализация не меняет режим устройства. В Garage сохраняются
прежняя необязательная установка и действующая политика сбора
`runtime.garage_hooks`.

## Поддерживаемые интеграции

| Агент | Штатная интеграция PF | Файл настройки |
| --- | --- | --- |
| Codex | Адаптер `codex-hooks`, envelope `codex-hooks.v1` | Проектный `.codex/hooks.json` |
| Claude Code, Cursor, Gemini CLI | В дистрибутиве нет зарегистрированного нативного hook-адаптера PF | Файлы хуков не создаются |

Для Codex используются готовый установщик и его существующий формат команды
(`py -3` в текущем поддерживаемом Windows launcher). Настраиваются SessionStart,
SessionEnd, PostToolUse, UserPromptSubmit, PreCompact, PostCompact, Stop и
SubagentStop. Это версия протокола штатного адаптера, а не подтверждение поддержки
во всех версиях приложения Codex или доверия его хосту. Бинарник агента не
устанавливается, его версия не угадывается, приложение не перезапускается.
Для остальных агентов сначала нужен отдельный ограниченный контракт адаптера
и допуска событий.

## Результат и восстановление

Прежний раздел результата `codex_integration` показывает события, изменения,
относительную ссылку на резервную копию и необходимость перечитать хуки. В Forge
интеграция обязательна. Отсутствующий адаптер, неверный JSON или структура групп,
небезопасный путь и конфликт обработчика PF дают ограниченную диагностику
`codex_hooks_*`. Сбой обязательной настройки не выдаётся за полную готовность.
Статус инициализации показывает отсутствующие обязательные хуки как repairable
или blocked и добавляет `initialize` в существующий план восстановления.

Штатное объединение сохраняет пользовательские хуки и другие настройки. Файл
хуков исключён из обычной карты force-перезаписи инициализатора. Повторная
инициализация без изменений сохраняет его байты и время модификации. Перед
заменой существующего файла создаётся резервная копия; при ошибке замены
исходный файл и копия сохраняются. Копия находится рядом с приватным файлом хуков
и должна храниться приватно вместе с ним. При необходимости восстановите указанную
копию, устраните причину диагностики и повторите инициализацию. Изменение настроек
между планированием и apply вызывает отказ вместо потери новых пользовательских
изменений.

Настройка не меняет глобальные файлы агента, не выдаёт права и не запускает
сервисы PF. События проходят прежний адаптер и Runtime либо file-first Host ingress
с действующими project/session binding, provenance, deduplication и обязательным
gatekeeper эффективного Forge. Проектный режим координации по-прежнему определяет
сбор через эту политику; наличие файла хуков её не меняет.

Доверие и активация остаются обязанностью хоста агента. Для изменённых хуков может
понадобиться новая сессия Codex; `/hooks` показывает фактическую регистрацию.
Локальная проверка события в исходниках и проверка установленного подключённого
хоста — разные доказательства. Регистрация MCP-хоста остаётся отдельной операцией.
