# Общие инструменты качества Python

Набор [tools/python-qa](../../../tools/python-qa/README.md) устанавливается один
раз в слое инструментов рабочего места, вне проектов и заменяемого ядра PF.
Его запускатель регистрируется в реестре инструментов рабочего места и доступен
разным проектам через один общий контракт toolchain.

Состав: Ruff, pytest, pytest-cov, coverage.py, mypy, Bandit и pip-audit. Настройки
проекта и его прикладные зависимости имеют приоритет; общие настройки применяются
при отсутствии соответствующих локальных. Автоматическое исправление всего
проекта и обязательное полное сканирование не включаются.

```powershell
python <shared-tools>/python-qa/qa.py --project-root <project> lint -- src
python <shared-tools>/python-qa/qa.py --project-root <project> format -- src
python <shared-tools>/python-qa/qa.py --project-root <project> typecheck -- src
python <shared-tools>/python-qa/qa.py --project-root <project> test -- tests
```

`format` проверяет оформление; `format-fix` изменяет его, а `fix` применяет
поддерживаемые исправления линтера. `lint` и `docstrings` отключают проектные
настройки `fix`/`fix-only`; небезопасные исправления требуют явной опции
`--unsafe-fixes` в операции `fix`. Для проверки документации служит отдельная
операция `docstrings`. Аргументы после `--` передаются выбранному инструменту
без разбиения строк оболочкой. Ошибки типов и упавшие тесты сохраняют ненулевой
код завершения.

Тесты выполняются в Python выбранного проекта: явно переданном через `--python`,
найденном в его `.venv`/`venv` либо исходном интерпретаторе общей установки.
Пакеты QA добавляются после прикладных зависимостей проекта. Совпадение основной
и дополнительной версии Python и платформы обязательно; для другого Python
нужна отдельная общая установка. Прикладные зависимости автоматически не
устанавливаются. Проверка уязвимостей получает манифест или явно выбранное
окружение проекта и не подменяет его окружением QA.

Для новых документируемых областей Core приняты PEP 8/257 и Google docstring
style. Описываются ответственность модуля/класса, смысл параметров и результата,
исключения, ограничения и существенные побочные эффекты. Типы задаются настоящими
аннотациями. Полное документирование и систематическое покрытие ядра тестами
сохранены отдельными будущими задачами; текущий набор проверок их не закрывает.

Установка, все операции, приоритет конфигурации и официальные источники описаны
в README набора. Инструменты разработки не становятся зависимостями Runtime
и не меняют стадии процессов или разрешения проекта.
