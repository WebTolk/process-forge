# Доверенные адаптеры провайдеров

ProcessForge отделяет приём исходного события от разрешения на создание эффектов в проекте. Сначала ядро raw ingress сохраняет частную квитанцию. Принятая квитанция подтверждает надёжный приём данных, но сама по себе не разрешает нормализованное событие, запись в журнал или захват переписки.

## Доверенный реестр

В `tools/pf_runtime/provider_adapters.py` определены `AdapterPolicy`, `WorkerBinding` и неизменяемый `AdapterRegistry`. Приложение создаёт реестр из уже созданных объектов политик. Ключ — точная пара `(provider, adapter)`; повторяющиеся и некорректные ключи отклоняются, а `.policies` возвращает зарегистрированные политики. Поля входящего события не загружают код, не задают команду, не меняют реестр и не выдают доверие.

Host в исходном коде использует `DEFAULT_ADAPTER_REGISTRY` из `builtin_provider_adapters.py`. В него входят адаптер хуков Codex (`codex` / `codex-hooks`), захват worker, запускаемого ProcessForge через Codex (`processforge` / `pf-codex-exec-worker`), и адаптер нормализованного Runtime для совместимости (`processforge` / `runtime-legacy`). Эти имена описывают текущую реализацию исходников; они не подтверждают готовность установленного Core или подключённого Host.

Доверенная интеграция может создать отдельный конечный реестр в коде приложения и передать его в `host.ingest_event`:

```python
from pf_runtime.provider_adapters import AdapterRegistry
from pf_runtime.builtin_provider_adapters import DEFAULT_ADAPTER_REGISTRY
from pf_runtime import host
from my_application.review_adapter import ReviewHooks

registry = AdapterRegistry([*DEFAULT_ADAPTER_REGISTRY.policies,
                            ReviewHooks("review", "review-hooks")])
result = host.ingest_event(envelope, workplace_root, core, registry=registry)
```

Пример предполагает доверенный модуль приложения с реализацией `ReviewHooks`. Политика должна реализовать чистую проверку `valid_raw_identity` и метод `validate`: по умолчанию оба отказывают в допуске. `allows_message` также отказывает по умолчанию. Проверяются поля идентичности, каноническое производное событие и точное происхождение сообщения. Затем применяются общие проверки Host. Полный пример интеграции находится в `tools/smoke_provider_adapter_admission.py`.

Некорректные поля raw identity сохраняются в отдельном детерминированном пространстве rejected-identity с неизменным исходным payload. Поэтому подмена stable/scope/version не совпадает с легитимной квитанцией. Отказ в допуске возвращается после надёжной записи raw. Replay Codex сверяет канонический raw digest и сохранённые метаданные до создания эффектов. Неполный нативный конверт не получает права нормализованного Runtime.

## Допуск и общие проверки

`host.ingest_event(..., registry=...)` сначала передаёт нативное событие ядру raw ingress. Если квитанция принята, Host ищет политику по точной зарегистрированной паре и проверяет происхождение данных провайдера. Неизвестная пара остаётся только в raw-хранилище с кодом `adapter_untrusted`; отклонённая политика или ошибка её выполнения — с кодом `provenance_rejected`. Эти стабильные коды запрещают производные эффекты, сохраняя принятую raw-квитанцию. Конфликты идентичности обрабатываются существующим механизмом карантина ядра.

Адаптеры интерпретируют специфичные для провайдера идентификаторы событий, сопоставление содержимого, привязки worker и происхождение сообщений. Host сохраняет общие проверки проекта и сессии, текущей задачи и попытки, пути и байтов/хеша файла результата, безопасного содержимого, надёжной записи, детерминированных идентификаторов, дедупликации и отложенного захвата. Производные идентификаторы должны совпадать с исходным конвертом. Событие не может выбрать более разрешительную политику или объявить себя доверенным.

Для worker адаптер передаёт нейтральные сведения: запуск, задачу, попытку, ожидаемый файл отчёта, содержимое и хеш. Host сравнивает их с текущим состоянием назначения и объявленным файлом результата. Интерпретация хуков Codex остаётся в адаптере Codex; известный адаптер может оставить неизвестное имя хука только в raw-записи.

## Совместимость и инициализация

Адаптер совместимости нормализованного Runtime принимает только уже нормализованное событие через аутентифицированный путь Runtime и отклоняет сообщения переписки. Это сохраняет существующую границу аутентификации транспорта; данный адаптер не является универсальным входом для других провайдеров.

Общая инициализация и статус проекта считают телеметрию Codex необязательной. Отсутствующая функция статуса или ограниченная ошибка возвращает информационный статус недоступности, не блокируя общую готовность проекта. Установка хуков остаётся явным действием восстановления `install_codex_hooks` и требует обычного подтверждения `apply`; инициализация не устанавливает хуки автоматически.

Эти сведения относятся к исходному checkout. Приёмка установленного Core, Workplace и подключённого Host — отдельная часть T06; проверки исходников и документация её не заменяют.
