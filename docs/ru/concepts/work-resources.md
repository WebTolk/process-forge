# Чтение ресурсов в контексте Work

Для новых закреплений Work состав разрешённых ресурсов по-прежнему берётся из
авторизованных строк локального поиска, но политика индексирования считается
авторитетной из resolved-декларации ресурса, если там есть явное `indexing` или
распознанное legacy-поле `index_policy`. Legacy-написания полного текста
`fulltext` и `full_text` материализуются как fulltext; явные политики
`metadata` и `none` не расширяются до полного текста.

Для подготовленных поисковых документов также действует общий предел: 2048
документов и 32 МиБ текста UTF-8, включая повторяющиеся сводки метаданных.

Чтение в контексте Work позволяет искать и разрешать ресурсы, закреплённые
за одной неизменяемой управляемой работой. Команды CLI и маршруты MCP
используют общий исходный сервис. Для запроса нужно явно указать Run,
Assignment и идентификатор контекста; система не выбирает более новую работу
автоматически.

## CLI

Для обеих команд обязательны `--project-root`, `--run`, `--assignment` и
`--context-id`. Параметр `--workplace` позволяет явно задать корень Workplace,
а `--json` выводит структурированный результат.

```powershell
python tools/processforge.py work-search --project-root . --run RUN_ID --assignment ASSIGNMENT_ID --context-id CONTEXT_ID --query "руководство по развёртыванию" --limit 10 --limitstart 0 --json
python tools/processforge.py work-resolve --project-root . --run RUN_ID --assignment ASSIGNMENT_ID --context-id CONTEXT_ID --resource-id RESOURCE_ID --json
```

Для поиска нужен параметр `--query`; для постраничной выдачи доступны `--limit`,
`--limitstart` и `--offset`. Для разрешения ресурса нужен `--resource-id`.
Если Workplace нельзя определить по настройкам проекта, добавьте к любой
команде `--workplace PATH`.

## MCP

Для `pf.work.search` обязательны `run_id`, `assignment_id`, `context_id` и
`query`; также принимаются `limit`, `limitstart` и `offset`. Для
`pf.work.resolve` обязательны `run_id`, `assignment_id`, `context_id` и
`resource_id`. Обе операции сохраняют существующие проверки проекта и
авторизации привязанной сессии.

## Результат чтения

Успешный ответ имеет область `work_context` и содержит идентификаторы
Work/контекста и происхождение ресурса, включая закреплённое поколение и
отпечатки материала. Поиск указывает покрытие проверенного материала и
возвращает совпадения из выбранных ресурсов. Разрешение различает переход
только по метаданным (`metadata_only`) и `verified_declared_material`, для
которого проверено полнотекстовое содержимое. Заблокированный ответ содержит
стабильную причину. Описанное поведение относится к исходному коду; приёмка
на установленном Core и реальном хосте ещё ожидается.

Доступ ограничен пересечением ресурсов, закреплённых за Work, текущей
авторизации проекта и подмножества ресурсов этапа процесса. Если подмножество
этапа не задано, действуют закреплённые разрешения; пустое подмножество не
разрешает ни одного ресурса. Отозванный доступ, изменившиеся метаданные или
материал, неверная область и отсутствующий либо непроверяемый материал
блокируют чтение. Новый ресурс, разрешённый сегодня, не добавляется в старую
работу. Существующий капсула контекста не переписывается: если в нём нет
закреплений ресурсов, чтение предложит создать Work-преемник вместо скрытой
миграции.

Перед полнотекстовым поиском проверяется объявленный материал в заданных
пределах; для запроса создаётся временный FTS-индекс. Содержимое не берётся из
общего кэша и не копируется в постоянный корпус. Для ресурсов только с
метаданными закрепляются объявление и доступность источника, а не меняющееся
содержимое дерева выходных файлов. Происхождение результата можно приложить
к свидетельствам артефакта: оно фиксирует прочитанное и не выдаёт разрешение
на будущий доступ.

Эти маршруты дополняют навигацию по проекту (`pf.search` и `pf.resolve`),
сохраняя её прежнюю область действия. Готовность поискового индекса, покрытие
текущей авторизацией и разрешение ресурса — разные свойства; готовность
индекса проекта не доказывает, что он покрывает выбранные ресурсы Work. См.
[индекс поиска ресурсов](resource-search-index.md) и
[контракт Work и выполнения](../../concepts/work-execution-contract.md).

## Лимиты, идентификаторы и свидетельства

Точный идентификатор контекста берите из `context.id` в выводе исходных команд `work-start` или `work-state`. Поле `work.context_checksum` в ответе на чтение указывает контрольную сумму проверенных байтов капсулы. Новые управляемые капсулы содержат `resource_bindings.schema_version: 1`; существующие капсулы не переписываются. Поле процесса `stage.resource_subset` сужает закреплённый список ресурсов.

Полнотекстовый материал проверяется в пределах фиксированных бюджетов на запрос: не более 64 ресурсов, 2 048 файлов, 32 МиБ общего содержимого и 20 000 просмотренных записей. На один ресурс допускается не более 256 файлов и 8 МиБ, на файл — 1 000 000 байт. При превышении лимита запрос блокируется, материал не обрезается молча.

Происхождение результата можно сохранить в свидетельстве артефакта, например:

```json
{
  "kind": "artifact",
  "artifact_id": "investigation-report",
  "status": "ready",
  "path": ".pf/artifacts/investigation-report.md",
  "resource_provenance": [
    {
      "project_id": "example",
      "run_id": "run-1",
      "assignment_id": "task-1",
      "context_id": "task-1-context-1",
      "context_checksum": "sha256:<capsule-digest>",
      "resource_id": "guide:root",
      "generation": "v1",
      "material_fingerprint": "sha256:<material-digest>"
    }
  ]
}
```

Происхождение фиксирует выполненное чтение и не предоставляет право на будущий доступ. Типичные причины блокировки: `resource_access_revoked`, `resource_material_changed`, `resource_generation_changed` и `legacy_contract_incomplete`.
