# Глобальная секция агента

ProcessForge не владеет целым глобальным `AGENTS.md`, `CODEX.md` или похожим
файлом инструкций. Он обновляет только ограниченную навигационную секцию:

```markdown
<!-- PROCESSFORGE:START -->
...
<!-- PROCESSFORGE:END -->
```

Секция объясняет, когда применяется PF, и указывает на корневой `AGENTS.md`
и `.pf/process-forge.yaml`. Старый проект без корневого входа явно использует
`.pf/AGENTS.md`. Контекст проверяется через `pf.context`; сохранённые снимок
и START не подтверждают актуальность. Дальнейший путь по возвращённым Work
и capsule описан в [порядке входа](session-bootstrap.md).

Текст вне маркеров сохраняется; повторное обновление идемпотентно. Глобальная
секция служит навигацией, но не заменяет минимальный контракт K и не доказывает
его загрузку клиентом.

```bash
python bin/pf.py global-agents-section --path <agent-file> --dry-run
python bin/pf.py global-agents-section --path <agent-file> --force
```

Не создавайте одинаковые файлы-ссылки для всех клиентов. Выберите маршрут по
[политике профилей и адаптеров](agent-entry.md). Для клиента с подходящим
загрузчиком корневого AGENTS файл производителя не нужен. Импорты Claude/Gemini
размещаются только через явный plan/apply; Aider получает инструкцию чтения,
OpenClaw — оценку предпосылок. Эти операции не меняют настройки клиента и не
запускают его.

Ссылка, напечатанный промпт или созданный адаптер сами не доказывают доставку,
поведение или принудительное соблюдение правил. K должен попасть в клиент
через выбранный маршрут с учётом фактического бюджета инструкций. Обычная работа
использует `pf.work.start`, `pf.work.state`, `pf.work.transition` и не требует
ручного создания сессии. Глобальные инструкции пользователя продолжают действовать.
