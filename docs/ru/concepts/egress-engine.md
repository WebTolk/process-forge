# Движок управляемой передачи данных

T07 реализует HTTP/JSON-брокер для Windows. Через него проходят начальный
запрос, последующие чтения ресурсов, результаты доверенных инструментов и
экспорт производных данных. У Codex CLI, generic-shell и режима isolated-local
нет подтверждённой строгой capability. Запрошенный `mediated_session` нельзя
молча заменить передачей только начального запроса. Протокол брокера конечен;
это не готовый клиент любого API моделей и не ОС-песочница для произвольных
программ. [Полный контракт и поля протокола](../../concepts/egress-engine.md).

## Запуск оператором

1. Создайте доверенную локальную JSON-политику. Проверьте каждый исходный файл
   целиком, задайте классификацию и контрольную сумму `sha256:`. Отсутствие
   срабатывания детектора само по себе не означает публичность.
2. Выполните `pf egress bind --policy <policy.json>` и сохраните JSON как новый
   файл намерения. Для преемника добавьте `--project-root <project>
   --predecessor <assignment-id>`.
3. Создайте Work штатной командой `pf work-start --project-root <project>
   --objective <new-objective> --process-id <allowed-process>
   --egress-intent <intent.json> --json`. Политика включается в неизменяемый
   контекст v2 до записи журналов. Для нового намерения нужна новая цель;
   существующий Work с несовместимыми правами не будет возобновлён.
4. Выберите существующий каталог вне проекта; его дочерний каталог
   `.pf-egress-private` будет хранилищем. Выполните `pf egress qualify
   --project-root <project> --store-root <store>`. Проверки используют только
   синтетические данные и локальные получатели. Нужны Python, зависимости Core
   и OpenSSL, в том числе поставляемый с Git for Windows. После изменения
   Core, Python или ОС квалификация становится недействительной.
5. Выполните `pf egress run --project-root <project> --assignment <id>
   --attempt 1 --policy <policy.json> --store-root <store>`. Номер попытки
   одноразовый. Ответ — JSON-квитанция и, если это предусмотрено политикой,
   отфильтрованный результат. `--credential-file` передаёт аутентификационные
   данные только в HTTP-заголовок; файл должен быть доступен только владельцу.

`egress status` показывает локальную квалификацию. `egress revoke --policy
<policy>` запрещает привязку в том же хранилище. Все команды должны использовать
одно хранилище: его замена — изменение доверенной конфигурации оператором.
При `egress_busy` отзыв **не применён**: оператор должен повторить команду после
освобождения блокировки. Эта блокировка упорядочивает отзыв и отправку.

`egress export` принимает параметры Work, политики, попытки и хранилища плюс
`--output <new-file>`. Он создаёт новый проверенный файл, не заменяет исходный
и не исправляет исторический результат doctor. Частные связи с исходниками
остаются в аудите. `egress prune` удаляет только тела квитанций старше 30 дней;
необратимые отметки бюджета и использованных попыток сохраняются.

## Правила передачи

Политика содержит `schema_version: 1`, `id`, `recipient`, `limits`, `sources`,
`denied_sources`, `redact_classes`, `exceptions`, `tools`. Получатель задаёт
точные `id`, `purpose`, `endpoint`, `transport`. Источник задаёт относительный
путь, классификацию, контрольную сумму, `format`, `required`, `initial` и
`transform`. Разрешены UTF-8 текст и JSON. Классы: public, internal, restricted,
personal, secret, credential, unknown. Запрет области или текущий отзыв
проверяется до чтения. Обработка содержимого не расширяет права.

Чувствительный обязательный блок останавливает передачу. Необязательный блок
можно целиком заменить либо исключить только по явному правилу. Движок не
обещает сохранить смысл произвольно отредактированной инструкции. Бинарные
данные, неподдерживаемая кодировка, неизвестная классификация, повторные ключи
JSON и превышение границ блокируются. Детекторы консервативны и конечны;
корректная исходная классификация остаётся необходимой.

Исключение для заведомо безопасного совпадения фиксирует точные байты, детектор,
получателя, цель и срок. Оно не отменяет секреты, учётные данные и обязательные
запреты. Необязательное поле политики `result` задаёт правило для итогового
текста. Без него операция finish не может вернуть текст.

Брокер принимает только read по непрозрачному дескриптору, tool по разрешённому
имени с точной схемой аргументов и finish. Нет операций чтения окружения,
домашнего каталога, загрузки плагина, запуска процесса, произвольной сети или
изменения политики. Строки-заглушки остаются строками. Штатный инструмент
`text-stats` выполняет только подсчёт текста. Дополнительный доверенный
инструмент требует закреплённого в политике fingerprint и отдельного разрешения
эффекта. Для эффекта, кроме чистого вычисления, нужно также разрешение Work;
явный запрет Work имеет приоритет для любого инструмента. Политика инструмента
не расширяет права Work. Его код и зависимости входят в доверенную часть системы.

Границы: 1 МиБ на блок, 4 МиБ на конверт, 32 МиБ и 128 раскрытий на попытку,
глубина JSON 16, классификация до 2 секунд, токен 30 секунд по монотонным часам.
Разрешено только уменьшать эти потолки. Повторная проверка источников тоже
учитывается в бюджете чтения. Превышение останавливает работу, а не отключает
проверку. Замеры синтетического корпуса не являются SLA или доказательством
отсутствия всех возможных утечек.

HTTPS проверяет имя сервера и сертификат по хранилищам Windows. Переменные
окружения для proxy, TLS-журнала ключей и дополнительных файлов доверия не
используются. Numeric loopback HTTP предназначен для явных локальных проверок
и не означает изоляцию от сети. Нет перенаправлений, SDK-добавок, повторных
отправок и потоковой передачи. Для ответа обязательны конечная длина и JSON;
сетевые тайм-ауты не являются обещанием жёсткого времени системного DNS.

## Сбои и границы доказательств

До отправки резервируется бюджет и синхронно сохраняется обязательный аудит.
Отказ необязательной диагностики не меняет решение. Если отправка могла
произойти, а окончательной квитанции нет, состояние — `delivery_unknown`.
Автоматического повтора и возврата бюджета нет. Использованный view повторно
не авторизуется. Перезапуск не восстанавливает токены.

Частное хранилище создаётся сразу с защищённым ACL владельца и исключено из
читаемых ресурсов Work. Views и обратные соответствия живут в памяти попытки;
закрытие немедленно лишает дескрипторы силы. Защита от администратора,
вредоносного кода того же пользователя и ранее сделанных резервных копий не
заявляется. Удаление по сроку хранения не означает криптографическое стирание.

Проверки исходников, архива, установленного Core и подключённого получателя
фиксируются отдельно. Квалификация этого брокера не доказывает фильтрацию
стороннего native-assistant или уже подключённого к хосту MCP.
