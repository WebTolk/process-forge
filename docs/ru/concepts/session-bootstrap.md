# Вход в проект и запуск сессии

Обычная работа Garage проходит через `pf.context`, при необходимости
`pf.search`/`pf.resolve`, затем `pf.work.start`, `pf.work.state` и
`pf.work.transition` до `run_completed`. Ручная сессия и запуск шаблонного
`first-assignment` для этого не нужны. Session bootstrap — отдельный интерфейс
Forge для оператора.

## Порядок входа

1. Загрузите корневой `AGENTS.md` через выбранный маршрут клиента. В старом
   проекте без него явно прочитайте `.pf/AGENTS.md`.
2. Прочитайте `.pf/process-forge.yaml`, проверьте актуальный контекст через
   `pf.context`. При недоступном MCP используйте существующий CLI
   `project-context-check` и проверенный файловый контекст. Само наличие снимка
   не доказывает его свежесть.
3. Найдите и разрешите нужные ресурсы через `pf.search`/`pf.resolve`, затем
   вызовите `pf.work.start`. При `process_choice_required` выберите из
   возвращённых процессов; не подставляйте предполагаемый процесс по умолчанию.
4. Используйте возвращённые идентификаторы Run, assignment и неизменяемой
   capsule для `pf.work.state` и `pf.work.transition`. Читайте их обязательные
   источники и актуальные передачи. Старый отчёт не выбирает другую задачу.
5. Расширенные `.pf/AGENTS.md` и дополнительные ресурсы читайте по необходимости.

Глобальные инструкции действуют, но навигационная ссылка не доказывает доставку
K. `agent-start-prompt` только печатает актуальную подсказку, не меняет файлы
и не считает сохранённый START источником полномочий. См. [контракт входа](agent-entry.md)
и [глобальную секцию](global-agent-section.md).

## Явный запрос сессии

Запрос включает session id, mode, actor, role, project root, необязательный
assignment и параметры записи, кэша и обновления контекста. Сохраняются схема
`schemas/session-start.schema.json` и шаблон `templates/session-start-template.yaml`.

`resume` исследует состояние: по умолчанию публичные артефакты не меняются,
приватная телеметрия сессии записывается. `project_init` запускает инициализацию:
при apply создаёт `.pf/` и обе проекции K с проверками владения и бюджета.
`assignment_execute` передаёт ограниченную задачу и Execution Context Package
или capsule; worker соблюдает их границы. Устаревшие `context_resolve` и
`context_compile` сохраняются для совместимости и записывают `.pf/contexts/`.
Run/Task/session API доступны для явных совместимых и операторских сценариев.

Проверенный актуальный контекст имеет приоритет над старыми отчётами. При stale,
broken, запрете ресурса или отсутствии обязательной capability сообщите причину;
обновление выполняйте только в разрешённой области. Явные session-операции пишут
приватные данные в `.pf/runtime/`, события — в `.pf/runtime/events/`. Обычная
работа не устанавливает, не запускает и не чинит Runtime, MCP, hooks или Ledger.
Файловому bootstrap не требуются backend, база данных или обязательный runner.
