# Поддерживаемые действия и нативные операции MCP

Перед вызовом PF используйте карту действий: она описывает CLI-парсер и реестр
MCP, загруженные работающим экземпляром. Наличие операции не заменяет проверки
полномочий, входов, текущего контекста и стадии процесса. Параметр соседней
команды не считается поддерживаемым без проверки.

```bash
python bin/pf.py actions list --query worker --surface cli --limit 10 --json
python bin/pf.py actions describe --action-id "cli:worker-run prepare" --json
python bin/pf.py actions describe --action-id "mcp:pf.work.start" --json
```

Идентификатор CLI имеет вид `cli:<фактический путь команды>`, MCP —
`mcp:<объявленное имя инструмента>`. CLI aliases сохраняются как отдельные
существующие пути вызова. List возвращает упорядоченную ограниченную страницу;
describe — подробности аргументов и схемы выбранной операции. Неизвестный
идентификатор получает явный отказ; подстановка похожей команды не выполняется.

`pf.actions.list` принимает `query`, `surface` (`cli` или `mcp`), `limit`
от 1 до 100 (по умолчанию 25) и неотрицательный `offset`.
`pf.actions.describe` требует `action_id`. Действуют обычные проверки привязки
проекта и сессии. Необязательные `run_id`, `assignment_id`, `context_id` нужно
передавать вместе. Без них карта не выбирает текущую или последнюю Work и не
утверждает право на выполнение. С ними используются факты явно выбранной Work;
окончательные проверки остаются у нативной операции.

Карта строится по фактическим регистрациям, сохраняя имена флагов, choices,
обязательность и aliases. Она не создаёт второй вручную поддерживаемый перечень
сотен команд. Приватные значения по умолчанию и объекты-функции не публикуются
как переносимые параметры. Необъявленные контракты результата, дополнительные
валидаторы и побочные эффекты остаются неизвестными, а не выводятся из названия.

Версия и fingerprint каталога/схем относятся к описанным метаданным. Они не
подтверждают загруженный код, установку обновления или работу нового кода через
подключённый MCP хоста. Уже запущенный процесс может сохранить старый каталог
после изменения файлов. Для приёмки подключённого хоста нужны фактически
объявленные инструменты и свежие запросы после штатного переподключения.

## Дополнительные инструменты MCP

Фасады используют существующие нативные механизмы. Универсальный исполнитель
команд, произвольный executable override и новая модель полномочий не вводятся.

| Инструмент | Основные входы и поведение |
| --- | --- |
| `pf.actions.list` | Поиск и постраничная выдача метаданных CLI/MCP. Ничего не исполняет. |
| `pf.actions.describe` | Описание точного `action_id`. Ничего не исполняет. |
| `pf.runtime_driver.list` | Зарегистрированные ID драйверов и их статусы для проекта и рабочего места. |
| `pf.runtime_driver.describe` | Обязательный зарегистрированный `driver`; метаданные без значений command/environment. |
| `pf.worker.prepare` | Точные селекторы Work, явно выбранный зарегистрированный `driver`, `apply: true`; нативная подготовка входов и scope. |
| `pf.worker.start` | Те же требования к identity и драйверу, `apply: true`; запуск всегда detached с немедленным возвратом. |
| `pf.worker.status` | Точные селекторы Work и `apply: true`; наблюдение может согласовать записи и собрать завершённый результат. |
| `pf.worker.collect` | Точные селекторы Work и `apply: true`; штатные проверки отчёта, хешей и попытки. |
| `pf.session.heartbeat` | `apply: true`; продление существующей привязанной сессии Ledger. Параметра `ttl` и регистрации нет. |
| `pf.chat.record` | Обязательный `content`, `apply: true`; сообщение assistant от привязанного агента Ledger в transcript его собственной сессии. |

Prepare/start дополнительно принимают `model` и `reasoning_effort`
(`minimal`, `low`, `medium`, `high`). Драйвер должен быть зарегистрирован по ID;
пути manifest и подмена executable в этот MCP-фасад не входят. Полные параметры
существующей CLI доступны по отдельным описанным маршрутам. В MCP отсутствуют
`wait`, произвольные participant/role и подмена адресата чата.

```json
{
  "project_root": "<project-root>",
  "run_id": "<returned-run-id>",
  "assignment_id": "<returned-assignment-id>",
  "context_id": "<returned-context-id>",
  "driver": "codex-exec",
  "apply": true
}
```

Это пример входа `pf.worker.start`. Для запуска нужна возвращённая PF identity
и применимая политика модели выбранного драйвера. Фасад отклоняет терминальную
governed Work перед prepare/start/collect, затем обращается к существующему
CLI application с его проверками вызова. Locks, проверка prepared input и сбор
результата остаются у нативных владельцев. Успешный запуск или `exit 0` провайдера
не означают приёмку родительской Work: основной агент читает отчёт и доказательства.

`pf.worker.status` намеренно не объявлен чтением без изменений.
`pf.worker.start` может запускать настроенный внешний драйвер и имеет annotation
open-world. Heartbeat/chat требуют существующую сессию Ledger и совпадение
проекта; инструмент не создаёт отсутствующую сессию. Общие каналы координации,
обслуживаемые другими нативными CLI-операциями, этим ограниченным маршрутом
сессионного transcript автоматически не открываются.

Объявленные ограничения схемы проверяются до business dispatch: размеры
массивов, длины строк, неизвестные поля, числовые границы и точные JSON-типы.
Карта действий не отменяет эти проверки и не расширяет файловый или ресурсный scope.

Манифест выбирается из реестра по точному ID; нативная команда получает эту
проверенную ссылку, исключая выбор одноимённого локального файла. Отсутствующий
манифест зарегистрированного драйвера даёт отказ. Привязанная сессия
требует тот же канонический каталог проекта; совпадения project ID недостаточно.
