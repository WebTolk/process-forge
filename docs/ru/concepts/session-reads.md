# Чтение данных сессии Ledger

Инструменты MCP читают существующую сессию Agent Ledger. Передавайте её
`session_id` при каждом вызове. Переменная `PF_MCP_SESSION_ID` также позволяет
явно привязать процесс сервера к одной сессии. Для сверки проекта передайте
`project_root`. Контекст проекта без привязки к сессии доступен через `pf.context`.

| Инструмент | Какие данные возвращает |
| --- | --- |
| `pf.session_context` | Текущий проект и Work, блокировки, активных агентов, актуальность контекста, ресурсы и готовность к исполнению |
| `pf.session_chat` | Приватную переписку этой сессии с удалёнными чувствительными данными. Для страниц используйте `limit` (1–100) и `before` или `cursor`, для фильтрации — `roles`. |
| `pf.session_activity` | Ограниченную выборку нормализованных событий проекта, отнесённых к сессии |

Даже при актуальном снимке проекта Work может быть заблокирована. Причину
показывает поле `execution_readiness.missing_capabilities` в ответе с контекстом.
При несовпадении проекта возвращается `session_project_mismatch`, а при попытке
передать другой идентификатор сессии привязанному серверу — `session_mismatch`.

В переписку попадают сообщения, которые PF получил и смог связать с этой сессией.
Полнота зависит от клиента, зарегистрированного адаптера и событий, которые он
передаёт. [Адаптеры событий](provider-adapters.md) · [Пример с хуками Codex](../../concepts/codex-session-read.md)
