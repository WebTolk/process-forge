# Предметно-нейтральное ядро

Ядро ProcessForge задаёт артефактные контракты и runtime-механику для рабочего
места, проектов, процессов, заданий, запусков, задач, итераций, capability
resolution, оркестрации, review, handoff и release evidence. Оно не предполагает
разработку ПО, веб, документацию, медиа, право или другую предметную область.

В ядре допустимы универсальные процессы, схемы, шаблоны, реестры, политики,
валидаторы и непрозрачные идентификаторы ресурсов. В нём недопустимы domain
knowledge packages, capability по умолчанию, определение технологии по именам
файлов и автоматическая активация конкретных платформ.

Предметная нейтральность не означает пустую поставку. Готовые к эксплуатации
процессы могут поставляться в `packs/official/` как версионируемые пакеты
данных. Они доступны из дистрибутива, но не являются зависимостями runtime и не
активируются в generic workplace. Ресурсы workplace, проекта и пользователя
остаются отдельными слоями расширения.

Каталог `examples/` предназначен для учебных сценариев и fixtures, а не для
канонических определений официальных процессов. Здесь уместна осторожная
аналогия со встроенными расширениями Joomla: официальный pack сразу пригоден к
работе и показывает архитектуру расширения, однако ядро не зависит от его
предметных правил.

Граница контролируется `policies/core-hardcode-policy.yaml` и
domain-neutral smoke-набором публичного релиза.
