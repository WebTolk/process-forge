# ProcessForge 1.3.1

## Исполнители Codex

Драйвер `codex-exec` получает список моделей и допустимые уровни мышления из
настроенного Codex CLI. Посмотреть список можно командой
`pf runtime-driver describe --driver codex-exec --catalog --project-root .`.
При запуске без явно заданной модели и уровня мышления применяются настройки
агента. [Руководство по драйверу](../concepts/runtime-drivers.md)
[PR #167](https://github.com/WebTolk/process-forge/pull/167)

## Журналы и обновления

- Журнал событий зарегистрированного проекта можно перенести при работающем
  совместимом Runtime. Операция `--project-events` проверяет резервную копию и
  позволяет продолжить прерванный перенос.
  [Обслуживание журналов](../concepts/sqlite-journal-maintenance.md)
  [PR #144](https://github.com/WebTolk/process-forge/pull/144)
- Из плана обновления можно выбрать подходящую версию. Откат применённого пакета
  доступен после обновления списка кандидатов и при недоступном источнике пакета.
  [Обновление и восстановление](../concepts/update-lifecycle.md)
  [PR #166](https://github.com/WebTolk/process-forge/pull/166)
  [PR #140](https://github.com/WebTolk/process-forge/pull/140)

## Проект и Runtime

- Параллельные вызовы через Core, Runtime и MCP получают свои результаты. Поиск
  сначала ограничивает результаты и счётчики выбранным экземпляром ресурса,
  затем сортирует их и разбивает на страницы.
  [PR #130](https://github.com/WebTolk/process-forge/pull/130)
  [PR #131](https://github.com/WebTolk/process-forge/pull/131)
- Неудачную доставку вебхука можно повторить отдельно для каждого получателя.
  Runtime и мост MCP используют общий код прямого подключения к loopback.
  [PR #142](https://github.com/WebTolk/process-forge/pull/142)
  [PR #147](https://github.com/WebTolk/process-forge/pull/147)
- Настройка проекта восстанавливает приватный временный каталог. Глобальная
  инструкция «по флоу» сохраняется в UTF-8 и учитывает скрытый файл инструкций
  проекта, когда корневой файл отсутствует.
  [PR #146](https://github.com/WebTolk/process-forge/pull/146)
  [PR #165](https://github.com/WebTolk/process-forge/pull/165)
- Объединили проверки привязки проекта, расширили проверки совместимости
  на Windows и Linux и обновили описание архитектуры и план развития.
  [PR #145](https://github.com/WebTolk/process-forge/pull/145)
  [PR #164](https://github.com/WebTolk/process-forge/pull/164)
  [PR #139](https://github.com/WebTolk/process-forge/pull/139)

## Обновление с 1.3.0

Подтвердите файловое обновление Core. Для проекта с готовыми хранилищами этот
патч не требует миграции данных. Если ещё на 1.3.0 проект сообщал
`storage_migration_required`, завершите его прежнюю миграцию перед возобновлением
записи. Режим `--project-events` нужен при обслуживании журнала событий отдельного
проекта. [Обновление и восстановление](../concepts/update-lifecycle.md) · [Миграция хранилищ](../concepts/sqlite-journal-maintenance.md)
