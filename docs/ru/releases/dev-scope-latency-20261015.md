# Dev-контрольная точка: скорость допуска Work

Dev-версия: 1.1.0. Коммит исполняемого кода: `4b0b3433a8f08ffed6e291da2004d049ad87ef9c`.
Чистое дерево исходников: `55cc4d65cb9dab695103a581d6c94449b1fce8a6`.
SHA-256 архива: `8e560914d55acf0ab4aff236f95557c111fe48d0216651d163ae6b3d738fd181`.

Измеренное узкое место допуска Work перенесено в конкретный сервис ядра
`ScopeConflictService`. Его используют допуск, supervisor и проверка планов.
Несовместимые обязательные литеральные префиксы исключают лишний обход дерева;
неразрешённые пары glob используют одну ленивую нормализованную опись за операцию.
Сохранены решения, причины, порядок, приоритет запретов, зависимости, handoff
и чтение актуальных данных. Межоперационного кеша и нового публичного контракта нет.
См. [сопоставимые измерения до и после](../audits/work-start-scope-latency-20261015.md).

В композиции остаются legacy-код и обратные вызовы. CLI передаёт запрос в
`ProcessExecutionService`; этот класс существовал и в предыдущем публичном
релизе. Все пять ООП-эпиков остаются открытыми.

Два штатных PF-воркера независимо проверили байты архива и готовое исправление.
Совпали все 1 249 элементов release-архива, 1 248 файлов ядра и предоставленные
Git-хеши восьми изменённых файлов. Прошли точечные source/extracted-проверки
scope и recovery, archive quick и проверки схем, публичной чистоты и контрольных
сумм на нейтральном кандидате. Это не новый полный public suite. Проверка
symlink на устройстве недоступна; ограничения ревью и сбои его временного
окружения сохранены в закрытых материалах.

Штатный updater применил этот архив один раз без force. Совпали 1 247 установленных
файлов ядра; сохранено одно ранее существовавшее локальное исключение манифеста.
Проверены все 22 резервных прообраза, три статических конфигурации и 695 защищённых
файлов истории и капсул. Незавершённого обновления нет. Прошли установленные
scope, recovery, HTTP body, Unicode transport, context и doctors. Unicode-тест
использует управляемый bootstrap; отдельно обычный установленный stdio-процесс
инициализировался и прочитал настоящий context и Work.

Замеры чтения выполнены при остановленном общем Runtime и прогретой файловой
системе. Создание Work измерено с настоящим работающим Runtime и накопленной
историей, включая запуск процесса, проверки, публикацию и итоговый state.
Это одно наблюдение, не распределение и не сопоставимое отношение «до/после».
Чтение с точными идентификаторами по-прежнему сканирует исторический каталог:
в отдельном профиле 8,285 с из 8,432 с state и 1 353 загрузки документов.
Время под профайлером не подменяет обычные измерения из таблицы.

GitHub v1.1.0 (`06acea7bcfe1bb5d7d009feb250e72c52b95e671`) и dev-код сравнены
на одинаковых 855 записях истории и 2 000 файлах, по пять повторов на версию.
Медианы общего запроса создания: 13,645990/6,963371 с; одинаковой проверки scope:
4,632357/0,653523 с. В старом API нет scope-file; общий dev-запрос имеет пустые
права и blocked execution readiness. Это сравнение создания не означает
сравнения одинаково исполняемых Work с полезной областью доступа.

Две ранее падавшие изолированные проверки прошли с прежними лимитами:
task batch — 57,00 из 180 с, долгоживущий Runtime — 67,84 из 240 с; последовательно,
без профайлера. Настоящий общий Runtime запущен из установки с новой идентичностью,
но остаётся degraded. За 45,011 с ОС измерила 44,8125 с CPU процесса — почти целое
ядро. Отдельный 20-секундный неблокирующий профиль py-spy преимущественно показал
supervisor collection, семантическую проверку prepared-input и загрузку context
и ресурсов. Сохранены 487 успешных выборок и 231 ошибка чтения стека; точный
процент CPU и состояние простоя из этого профиля не выводятся. Причина отказа
scheduler и безопасное сокращение затрат повторов требуют отдельной работы.

Настоящий подключённый MCP приложения ещё не квалифицирован для новых модулей.
Новый Runtime или отдельный stdio не подтверждают этот уровень. Открыты затраты
каталога, здоровье общего Runtime, legacy-маршрутизация диагностики MCP и полная
накопленная квалификация source/archive/install/connected-host. Контрольная точка
**не готова к стабильной публикации 1.2.0**. Для публичных тегов, assets и stable
channel требуется отдельное одобрение оператора после подробного отчёта;
в этой контрольной точке они не публиковались.

Эта переносимая заметка и checksum выпускаются отдельным коммитом документации
после установки и не входят в указанный исполняемый архив. Точные квитанции,
проверки Git и обоих remote и ограничения ревью сохранены в закрытых материалах PF.
