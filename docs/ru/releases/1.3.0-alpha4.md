# ProcessForge 1.3.0-alpha4

Накопительный предварительный релиз отделяет работу с контекстом проекта от
индексации документации рабочего места и включает квалифицированные изменения
alpha3.

Инициализация, refresh и repair проекта, чтение контекста и поиск наблюдают уже
существующий индекс. Они не запускают индексацию, не ставят её в очередь и не ждут
завершения. Свежесть контекста и проверки обязательных ресурсов сохраняются;
отсутствие, устаревание, построение или сбой индекса показываются отдельно.
Изменения ресурсов помечают производный индекс устаревшим для явного обслуживания.

Ручной запуск выполняется в разрешённой области рабочего места:

```bash
python bin/pf.py search-index-maintain --workplace <workplace> --apply --json
```

CLI и вызываемая задача будущего планировщика обращаются к одному компоненту Core.
Выпущенные проектные команды `search-index refresh`, `rebuild` и `tick` сохраняют
параметры и область выбранных ресурсов, используя общую сериализацию писателей и
восстановление. Периодический запуск остаётся задачей будущего планировщика PF.

`knowledge-add-batch --workplace <workplace> --package <package> --batch-file
batch.yaml --apply --json` добавляет YAML-записи через существующие отдельные
транзакции. Команда показывает результат каждого элемента и один раз в конце
индексирует только успешные ресурсы, сохраняя остальные документы. Dry-run ничего
не записывает. Сбой индексации сохраняет добавления и даёт ненулевой код выхода.
Выборочный проход снимает только известные изменения успешных ресурсов; старые
сбои, неизвестные и невыбранные изменения остаются необработанными;
полная сверка остаётся отдельной явной командой рабочего места.

Текущий backend — SQLite FTS5, расположение:
`<workplace>/runtime/search/local-resource-search.sqlite`. Узкий контракт backend
отделяет индексатор от хранилища. Другие SQL/векторные адаптеры и RAG-конвейер
развиваются отдельно с использованием запланированного общего DB-слоя. Отбор
ресурсов CLI/MCP и актуальные ограничения проекта/Work сохраняются.

Обслуживание исключает одновременных писателей блокировкой ОС, фиксирует состояние
и результат, допускает явный повтор после прерывания. Чтение SQLite не создаёт
исчезнувшую базу и не ждёт стандартный busy timeout. Диагностика ограничена
безопасными кодами и не раскрывает приватные пути.

Релиз относится к opt-in alpha-каналу; stable остаётся на 1.2.0. Доказательства
доставки отдельно фиксируют исходники, точный архив, нативное ревью и хеши
опубликованных assets. Сам выпуск не обновляет установленное устройство.

Существующему производному кешу может понадобиться один явный полный проход для
новой идентичности корней и метаданных. Refresh контекста не выполняет эту миграцию.

См. [поиск ресурсов](../concepts/resource-search-index.md) и
[контекст проекта](../concepts/project-context-snapshot.md).
