# Переход на промежуточную версию 1.2.0

Используйте существующий [manifest-controlled Core update](../concepts/core-update-manifest.md)
с построением плана и проверкой. Перед явным apply рассмотрите локальные
изменения и необходимые резервные прообразы. Кандидат, архив, установленный Core,
Runtime и фактически подключённый host имеют отдельные доказательства приёмки.

Существующая Work сохраняет неизменяемый контекст и версию процесса.
Продолжение использует точные run/assignment/context selectors. Изменение scope
проходит существующий governed handoff/continuation. Завершённая Work не может
запустить новую native worker attempt. Обновление Core не переносит старые
определения процессов и капсулы автоматически.

Версия выпуска становится 1.2.0; схемы и startup contract сохраняют собственные
версии и правила совместимости. Миграция входа в проект требует рассмотрения
текущего контракта и локальных инструкций. Прежние START-файлы сохраняются;
операция start-prompt по умолчанию показывает результат без записи.

Устойчивый отказ автоматического collect виден как требование восстановления.
Проверьте его причину и актуальные входы перед явным восстановлением/ручным
сбором или новой попыткой. Исторический успешный capture остаётся наблюдением
той попытки, а не новой приёмкой изменённых исходников. Временные ошибки I/O
и блокировок сохраняют возможность повтора.

Внутреннее владение модулями продолжает меняться при рефакторинге. Существующие
внешние CLI/MCP и форматы хранения проверяются в затронутых границах;
наличие нового класса само по себе не означает завершённого переноса.
Квалификация egress остаётся явной и привязанной к реализации; при изменении
implementation identity используйте её существующий путь квалификации.

Перед выбором этой промежуточной версии для установки рассмотрите
[заметки о выпуске и известных ограничениях](1.2.0.md). Эти заметки не запускают
автоматический перезапуск служб, host hooks или подключённой сессии.
