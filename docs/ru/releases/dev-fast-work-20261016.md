Накопленный архив содержит общий расчёт конфликтов scope, ограниченное исправление

пользователем выбор по паре Run+Assignment. Подробности — в
[каноническом аудите](../audits/canonical-work-selection-20261016.md).
Проверенная пара сохраняет четыре актуальных чтения с финальной проверкой;
для недоказанной или неполной пары остаётся прежний полный каталог.

ядра; сохранено единственное прежнее неизменяемое локальное исключение конфигурации.
Проверены 12 резервных прообразов, три конфигурации и 704 защищённых записи проекта.
Незавершённой транзакции нет. Собственный Runtime остановлен и восстановлен штатными

Ранее пять чередующихся пар direct CLI на настоящем проекте сохранили полные

После восстановления нового общего Runtime чтение счётчиков ОС за 45,000778 с
показало 44,953125 процессорной секунды —99,894% одного ядра; health остался

Безопасное сокращение повторов проверяется отдельной задачей; ускорение Work state
не устранило фоновую нагрузку.

Общая диагностика падает и при остановленном Runtime. Наблюдения указывают на
отказ получения Windows byte-lock в прежние 50 мс. Исправление должно сохранить
проверку и бюджет. Полное создание Work остаётся отдельным медленным путём:
настоящий последующий допуск без профайлера занял 18,910 с; отдельный допуск с
cProfile сохранён для локализации. Переход к Core остаётся частичным, OOP-эпики открыты.

До публичной 1.2.0 нужны исправление измеренных дефектов, version/changelog и
migration notes, чистый накопленный кандидат с полными обязательными проверками,
применимые install/update и подтверждение настоящего подключённого хоста.
Затем — подробный отчёт о готовности и отдельное одобрение пользователя. До него
публичные теги, assets и stable channel запрещены. Общая чистка smoke и список
допустимых моделей устройства остаются отдельными будущими задачами.
