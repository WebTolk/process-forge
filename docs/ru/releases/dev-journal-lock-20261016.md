# Dev-поставка журнала и диагностики, 16 октября 2026

Статус: исходники независимо приняты; накопленная квалификация продолжается. Готовый архив, обновление устройства и ускорение
Runtime пока не заявляются. Публикация 1.2.0 не одобрена. До проверки нового
нативного обновления установленным исполняемым источником остаётся
`61a7b74cfa7b1812641d7cef85760449dccb06be`.

Накопленный кандидат добавляет независимо принятое
[исправление допуска диагностики](../audits/diagnostics-admission-fairness-20261016.md)
и, после независимой приёмки, [исправление журнала текущих байтов](../audits/process-event-journal-latency-20261016.md).
Второе передаёт алгоритм конкретному Core-классу и использует ограниченный
производный набор ID в памяти; повреждённая история всегда разбирается полностью.
Предыдущие отклонённые варианты остаются доказательствами и не дают допуска сборке.

Для поставки нужны чистый коммит и checksum, хеши архива/Core/sidecar, прежние
адресные проверки распакованного архива, нативный план без блокировок, сохранность
локальных настроек/истории и резервных образов, одна контролируемая установка,
обычные установленные CLI/stdio и прежние проверки диагностики, журнала и лимитов.
CPU и стеки восстановленного Runtime измеряются в отдельных тихих окнах.
Независимый свежий stdio не доказывает приёмку фактически подключённого хоста.

Предыдущий установленный Runtime потратил 44,953125 с CPU за окно 45,000778 с
и оставался degraded. Выборка стеков указывает на приём HTTP-событий и перестроение
stage obligations. Прототип пустой проекции не доказывает свежесть всех зависимостей
и исключён из кандидата. Улучшение Runtime нужно измерить после установки;
изолированный append этого не доказывает.

До подробного отчёта о готовности и отдельного одобрения остаются полные
накопленные проверки, версия/changelog/migration 1.2.0 и фактический подключённый
хост. Аудит и чистка smoke, а также каталог моделей устройства — отдельные будущие
задачи; разные модели могут одновременно работать на одном устройстве.
