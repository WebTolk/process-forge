# Временные файлы проекта

Создавайте временные файлы проекта **только в `.pf/tmp/`**, в отдельном каталоге
текущей задачи. Итоговые материалы храните в `.pf/artifacts/`, передачу результата —
в `.pf/handoffs/`. Так эксперименты и служебные черновики не смешиваются с файлами
в корне репозитория. Core включает это правило в создаваемые инструкции проекта.

Удаляйте собственные временные файлы, когда они больше не нужны задаче. Сначала
проверьте, что ими не пользуется воркер или незавершённая операция, и сохраните
необходимые доказательства. Правило относится к временным материалам задачи;
постоянные записи PF и файлы подготовки атомарной замены рядом с назначением
сохраняют своё назначение.

## Уведомления о старых файлах

Необязательный app-server наблюдает за `.pf/tmp/` и сообщает о файлах старше
заданного возраста. **PF не удаляет их.** Возраст — повод проверить файл,
а не доказательство его ненужности. Система не просматривает журналы Work,
чтобы угадать, какие материалы ещё полезны.

Настройки рабочего места находятся в `configuration.yaml`:

```yaml
schema_version: 1
runtime:
  temporary_files:
    mode: notify
    max_age_hours: 168
```

По умолчанию включены уведомления (`notify`) с порогом 168 часов, то есть семь
дней. Для отключения задайте `mode: "off"`; кавычки нужны, чтобы YAML прочитал
строку. Возраст принимает конечное число
от 1 до 87600 часов. При редактировании существующего файла сохраняйте остальные
разделы настроек.

В `.pf/configuration.yaml` проекта можно переопределить каждый параметр.
Отсутствующее значение или `null` означает наследование настройки рабочего места.
Например, чтобы в одном проекте сообщать о файлах старше трёх дней:

Если файл настроек рабочего места или проекта ещё не создан, сначала выполните
соответствующую команду ниже. Рабочее место и подключённый проект уже должны
существовать. Для имеющегося файла настроек команду `create` пропустите:

```bash
python bin/pf.py config create --workplace <workplace> --json
python bin/pf.py config create --workplace <workplace> --project-root <project> --json
```

```bash
python bin/pf.py config update --workplace <workplace> --project-root <project> --key runtime.temporary_files.max_age_hours --value 72
python bin/pf.py config read --workplace <workplace> --project-root <project> --key runtime.temporary_files.max_age_hours --json
```

Удаление переопределения возвращает наследование:

```bash
python bin/pf.py config delete --workplace <workplace> --project-root <project> --key runtime.temporary_files.max_age_hours
```

## Что означает результат наблюдения

App-server проверяет проект не чаще раза в час. Он просматривает ограниченную
часть локального временного каталога и не переходит по символическим ссылкам
или junction. Отсутствующий каталог не считается ошибкой и не создаётся.

Последний результат хранится приватно в
`.pf/runtime/maintenance/temporary-files.json`. Контекст и статус читают готовую
сводку; запрос контекста не запускает просмотр временных файлов. Неполные,
устаревшие и неизвестные результаты обозначаются явно. Счётчики могут показывать
нижнюю границу; уведомление не заменяет полную проверку занятого места.

Для просмотра сохранённой сводки:

```bash
python bin/pf.py project-context-check --project-root <project> --json
```

Результат содержит `temporary_files`. В ответе агента `pf.context` та же сводка
находится в `diagnostics` с `code: temporary_files_status`. Имена файлов в этих
сводках не раскрываются. Отчёт возрастом от часа или с другими эффективными
настройками обозначается как устаревший.

В файловом режиме app-server не обязателен, а правило размещения временных
файлов продолжает действовать. Без работающего наблюдателя свежего фонового
уведомления не будет. Запуск и настройка инфраструктуры относятся к выбранному
оператором [порядку работы Runtime](getting-started/runtime-autostart.md).

## Разрешение сохранять ненужные данные

`runtime.temporary_files.retain_unused` — параметр существующего PFConfig.
Глобальное значение по умолчанию — `false`; проект принимает `true`, `false`
или `null` (наследование). Явный проектный `false` отменяет глобальный `true`.
Приоритет: встроенные значения, device, явно заданные workplace-поля, проект,
затем разрешённый typed project context. Строки и числа недопустимы.

Только точный `true` в снимке операции без ошибок разрешает сохранять ненужный
PF-owned payload. Last-valid значение при текущей ошибке конфигурации нового
разрешения не даёт. Параметр не предоставляет filesystem- или Work-права.
Режим уведомления (`off`/`notify`) и возраст не разрешают хранение или удаление.
Собственный sibling staging для atomic replacement можно удалять после
использования даже при разрешённом сохранении других данных. Нужные input,
recovery и evidence сохраняются до завершения реальных потребителей.
