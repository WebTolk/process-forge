# Требования

Проверьте эти требования перед [установкой](getting-started/installation.md).
ProcessForge работает как локальный Python CLI. Для режима Garage не нужны
PF Runtime, MCP, хуки Codex или вручную открытая сессия Agent Ledger.

## Python и библиотеки

Рекомендуется **Python 3.11+**. Текущие приёмочные проверки выполнены на
**CPython 3.14.3 под Windows**. Это не подтверждает совместимость со всеми
сочетаниями версий Python и операционных систем. Успешный разбор исходников
старой грамматикой Python не заменяет запуск проверок на нужном интерпретаторе.

| Компонент | Требование и назначение |
| --- | --- |
| PyYAML | `PyYAML>=6.0` — единственная внешняя Python-зависимость в `requirements.txt`. Используется для чтения и записи конфигурации и артефактов YAML. |
| `sqlite3` | Нужны модуль стандартной библиотеки Python и сборка SQLite с поддержкой UPSERT. Локальные журналы событий и входящих хуков используют транзакции, WAL и `synchronous=FULL`. Отдельный сервер БД не нужен. |
| SQLite FTS5 | Нужен для индексированного полнотекстового поиска по ресурсам. PF проверяет наличие расширения; без него сообщает `degraded` / `fts5_unavailable`. Работающий журнал ещё не подтверждает наличие FTS5. |
| `ssl` и доверенные CA | Нужны для загрузок по HTTPS и исходящих HTTPS-запросов. Python должен поддерживать SSL и доверять цепочке сертификатов сервера. В Windows исходящие запросы используют системные хранилища сертификатов. |
| `zlib` и `zipfile` | Нужны для чтения сжатых архивов релизов и обновлений, а также для создания ZIP с DEFLATE. Для этих операций урезанной сборки Python без `zlib` недостаточно. |
| `venv` и `pip` | Нужны при настройке изолированного окружения и установке PyYAML. В некоторых ОС устанавливаются отдельными пакетами. Это инструменты настройки, а не фоновые службы. |
| Windows `ctypes` | Нужен для сохранения прав доступа к файлам, диагностики процессов и нативных исходящих запросов в Windows. Сборка Python должна включать рабочие привязки к Windows API. |

CLI, MCP и HTTP-службы используют стандартную библиотеку Python. Внешний MCP
SDK, веб-фреймворк, Node.js, PHP и PowerShell не являются общими зависимостями CLI.

## Хранение и права доступа

Разместите отдельно заменяемый дистрибутив ProcessForge, изменяемое рабочее
место (workplace) и каждый проект. Среда должна поддерживать UTF-8. Учётной
записи PF нужны чтение дистрибутива и выбранных ресурсов, создание, запись,
переименование и блокировка файлов в workplace и проектной `.pf/`. Для
обновления Core дополнительно нужны запись в дистрибутив и место для архива,
подготовленных файлов и резервных копий. Проверки тоже могут записывать отчёты.

Храните журналы SQLite на локальной файловой системе с надёжными блокировками
и возможностью создавать рядом файлы `-wal` и `-shm`. Одного права записи в
файл БД недостаточно: каталог также должен быть доступен для записи. Не
считайте сетевую или синхронизируемую папку равноценной локальному диску по
гарантиям блокировок. Планируйте место для журналов, индексов, артефактов и
резервных копий по своей нагрузке; единый минимум диска не измерен.

Временные материалы задачи храните в `.pf/tmp/`, а итоговые доказательства —
в `.pf/artifacts/`. См. [временные файлы и уведомления](temporary-files.md).

## Планирование памяти

Для начала заложите **512 МиБ на один процесс app-server**. Для небольшого
workplace рекомендуется **начальный резерв 1 ГиБ**. Это ориентиры планирования,
**а не подтверждённый минимальный объём и не принудительный лимит**. При
ограниченном наблюдении за двумя существующими процессами Windows рабочий набор
составлял примерно 115–136 МиБ, частная выделенная память — 136–169 МиБ, а
пиковый рабочий набор за время жизни — 182 МиБ. Работа при ограниченной памяти
и максимальной нагрузке не проверялась.

Измерьте свою нагрузку, особенно при больших YAML-каталогах, индексах и
одновременных запросах. Память ОС, IDE, AI-хоста, исполнителей, необязательных
Runtime и MCP и других приложений учитывайте отдельно. Для нескольких
app-server резерв нужен каждому процессу. Обычная файловая работа через CLI
не требует app-server.

## Предварительная проверка без записи

После установки зависимостей выполните команды выбранным для PF интерпретатором.
Они показывают версии и проверяют БД в памяти, не создавая workplace, проект,
журнал или службу:

```bash
python --version
python -m pip show PyYAML
python -c "import sqlite3, ssl, zlib, venv, yaml; print('PyYAML', yaml.__version__); print('SQLite', sqlite3.sqlite_version); print('SSL', ssl.OPENSSL_VERSION); print('zlib', zlib.ZLIB_VERSION)"
python -c "import sqlite3; db = sqlite3.connect(':memory:'); db.execute('CREATE TABLE probe (id INTEGER PRIMARY KEY, value TEXT)'); db.execute('INSERT INTO probe VALUES (1, ?) ON CONFLICT(id) DO UPDATE SET value=excluded.value', ('ok',)); db.execute('CREATE VIRTUAL TABLE search_probe USING fts5(content)'); db.close(); print('UPSERT and FTS5 available')"
python bin/pf.py version
python bin/pf.py --help
```

В Windows также проверьте `python -c "import ctypes; print('ctypes available')"`.
Проверка в памяти не подтверждает работу WAL на диске, права на каталог,
доверие к сертификату удалённого сервера или прохождение полного набора тестов
PF. Не отключайте проверку сертификатов ради успешного HTTPS-запроса.

## Необязательные инструменты и службы

Git нужен для клонирования исходников и проверок разработки и релиза. Из
распакованного релиза PF работает без Git, если его не требует выбранная
интеграция. AI CLI, оболочка, инструменты и учётные данные исполнителя нужны
только соответствующему драйверу или процессу. Пакет и платформа могут задавать
дополнительные зависимости.

PF Runtime и stdio MCP, которым управляет хост, подключаются отдельно и явно.
Автозапуск Runtime использует Планировщик заданий Windows (`schtasks.exe`);
это не универсальный установщик служб для разных ОС. См.
[запуск Runtime и MCP](getting-started/runtime-autostart.md).
Агент обычного проекта не должен устанавливать или чинить эту инфраструктуру.
