## Точки переноса по прежним эпикам

В октябрьской очереди пять эпиков оставались открыты. Этот срез использует те же области владения и отдельную приёмку каждого перехода. [Предыдущая очередь OOP](../pf-audit-followups-20261014.md) · [Реестр перенесённых групп](../../concepts/python-core-structure.md)

| Эпик | Сохраняемое достижение | Следующий измеримый результат |
| --- | --- | --- |
| OOP-01, композиция | Конкретные читатели/политики и scoped factories, bootstrap Core identity. | Один активный путь композиции обходится без переданного целого модуля. P37 F01 и отдельный slice checker `pf.search`. |
| OOP-02, storage и I/O | YAML readers, SQLite driver/repositories, bound projections, SQL journals и явный restore. | Стабильная публикация outbox, recovery update и UUID search. Сохранить порядок transaction/writer и путь чтения старых данных. |
| OOP-03, Work execution | Selection/readiness/evidence, intents, процессы, replay, continuation и collection имеют отдельных владельцев. | Убрать мёртвые поля commit, измерить pending lookup и objective, провести parity intermediate/terminal/recovered. |
| OOP-04, каталоги и расширения | Канонические discovery/readers, policies и descriptors, неоднозначность разрешается явным выбором. | Зафиксировать живые registry reads, версия/отзыв и scope для pinned data. Новые Protocol вводить при конкретной границе. |
| OOP-05, транспорты | Parser families, `CliApplication`, bridge и request-local `NativeResult` уже работают. | Набор реальных parity fixtures и узкий slice Runtime Host. Alias, schema, ошибки и installed/connected qualification сохраняются. |

## Сверка P37

- **F01** остаётся актуальным. Фабрика принимает legacy `core`, а coordinator обращается к `assignment_capsule_path`, `project_context_check_result` и `registry_file_lock`. Выбрать один путь с существующим concrete owner и проверить его паритет. [Фабрика](../../../src/processforge_core/composition.py#L1385) · [Coordinator](../../../src/processforge_core/process_execution.py#L278)
- **F02** актуален для конкретной операции. `WorkSelectionService.find_by_objective` нормализует objective и запрашивает записи с `include_historical=True`. Широкий cache добавляется только при измеримой пользе и строгом доказательстве сортировки и exact identity. [Поиск](../../../src/processforge_core/work/selection.py#L78)
- **F03** подтверждён по классу. Из 14 зависимостей `commit` не обращается к `assignment_path`, `run_path`, `atomic_yaml`, `write_task_index`, `write_projection` и `emit`. Перед снятием сверить фабрику, прямых потребителей и сохранённое тестовое конструирование. Replay продолжает владеть публикацией. [Commit](../../../src/processforge_core/work/transition_commit.py#L13)
- **F04** требует измерения ожидания writer lock отдельно от работы и длительности commit/replay. Параллельный отказ и повтор обязаны сохранять порядок и pending intent. Открыт в #108. [Публикация старта](../../../src/processforge_core/work/start_publication.py#L43)
- **F05** остаётся отдельной квалификацией версии planning-only процесса. Текущий аудит применяет действующий pinned process. [P37 #24](https://github.com/WebTolk/process-forge/issues/24) · [Открытые F01–F05](https://github.com/WebTolk/process-forge/issues/108)

## Метод и охват

Пути и blob взяты из Git на базовой ревизии. Исходники прочитаны через PyCharm, разобраны Python AST. 425 модулей совпали с Git blob с учётом одной нормализации текста. Для фасада проверено единственное различие экспорта на строке 575, а длинный литерал учтён через нативный результат. Локальный полный перечень включает 4 503 объявления с координатами. Отдельно прочитаны runtime, database, process, resource и Work документы, release-аудиты и затем проверены ключевые исполнения. Runtime profile, символы Python и порядок import на статическом графе описывают инженерные гипотезы, а не полный runtime coverage. Нагрузочные показатели нового кода здесь не выводятся.
