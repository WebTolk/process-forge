# Аудит ProcessForge — 14 октября 2026 года

Полная работоспособность PF на текущем устройстве не подтверждена. Штатный полный public suite: **264 PASS и 3 FAIL из 267 проверок**, без пропущенных проверок верхнего уровня. Выявлены четыре подтверждённых нарушения контрактов и два наблюдения о функциональном сбое и временном бюджете. ООП-рефакторинг остаётся незавершённым; все пять эпиков открыты.

Аудируемая ревизия: `9d7cd54fd53caff003c4c46bff3a7e51e8ed8afa`. Локальный замороженный эталон публичного релиза: `v1.1.0`, `06acea7bcfe1bb5d7d009feb250e72c52b95e671`.

## Подтверждённые нарушения контрактов

### PF-AUDIT-01 — кодировка stdio MCP: высокая важность

`tools/pf_runtime/mcp_server.py:602` и `:614` используют унаследованную текстовую кодировку. UTF-8-запрос через cp1251 преобразует кириллический путь и приводит к ложной ошибке отсутствующего manifest. При ASCII-escaping вход проходит, но ответ содержит невалидные UTF-8 байты. UTF-8-контроль проходит. Независимый reviewer воспроизвёл это на exact-main/TextIOWrapper.

Подключённый MCP воспроизводит ошибку для кириллицы, смешанных имён, CJK/emoji и NFD при наличии файла; ASCII, пробелы и проверенная пунктуация разрешаются. Его реальная кодировка и loaded-code seal не подтверждены. Проверенные CLI argv и context-check проходят; общая неисправность CLI не заявлена. Следующая задача уже существует: `pf-filesystem-path-unicode-20261014`.

### PF-AUDIT-02 — ограничения массивов MCP: средняя важность

`tools/pf_runtime/mcp_server.py:477` не проверяет опубликованный `maxItems`. Превышения 129/129/33/33 достигают инертного business-dispatch для continuation, cancellation, initialization и repair; границы 128/128/32/32 проходят. Типовые отрицательные контроли проверены отдельно. Core cancellation отклоняет evidence больше 128, поэтому обход разрешений или реальная мутация не доказаны. Требуется проверять все опубликованные ограничения до dispatch с сохранением `-32602`.

### PF-AUDIT-03 — тело POST Runtime: средняя важность

`tools/pf_runtime/service.py:652` и `:655`: отрицательный Content-Length вызывает `read(-1)`; неполное тело и NaN/Infinity принимаются. Oversize и некорректная длина отклоняются в контрольных случаях. AST reader одинаков в stable/current — это существующий дефект, а не доказанная регрессия рефакторинга.

Проверки использовали инертный reader; блокировка сокета, DoS и запись не проверялись. Реальный POST требует bearer и слушает loopback. Нужны строгий framing, ограниченное чтение и проверка конечных JSON-чисел.

### PF-AUDIT-04 — терминальная governed Work перед запуском: средняя важность

`tools/processforge.py:17745`: ранний prelaunch отклоняет cancelled, но пропускает failed/completed до prepare/load. Downstream prepared/contract/stage проверки не проверяют terminal Work status. Reviewer подтвердил узкий пробел инертным prefix и чтением цепочки. Реальный запуск S1 и корректный отказ worker — наблюдения primary; его ошибка повторного запуска признана и локальная проверка оркестратора исправлена.

Это не доказательство выполнения терминальной Work и не основание запрещать все legacy retries. Требуется отдельная согласованная политика для terminal governed Work и failed worker attempts.

## ООП и совместимость

В Core есть реальные владельцы чтения Work, материалов, каталога, context rules/policy, выбора ресурсов и snapshot rendering; их переносы и потребителей следует учитывать отдельно. Конструкторы с узкими зависимостями и чистые функции соответствуют Python/KISS. Число классов, обязательный DI-контейнер и глубина наследования не являются приёмкой.

Обычная композиция по-прежнему передаёт legacy callbacks и `core: Any`; bootstrap загружает legacy CLI/transport. `tools/processforge.py` содержит 25 280 строк. Остаток затрагивает SRP, DIP и разделение интерфейсов; он остаётся явно неперенесённым. Полная OOP-программа не завершена. Последнее уточнение и migration contract требуют конкретных owners и перевода consumers, а новые Kernel/DI/plugin/lifetime подсистемы остаются предложениями.

С local stable добавлены 49 узлов CLI и 6 MCP tools, удалений нет. В полных телах схем — 10 добавлений и 6 изменений, включая process-definition/resource_subset. Начальная поверхностная оценка пяти схем исправлена по независимому чтению. Существующие CLI flags не удалены и не сужены в собранных declarations; это не доказывает полный паритет outputs/errors/order/persistent consumers.

Default `agent-start-prompt` документированно изменён с refresh/write на preview; explicit plan/apply имеют другую семантику. Это наблюдаемое изменение совместимости, которое требует самостоятельной приёмки. Оно не описывается как чистый перенос поведения.

## Независимое ревью и корректировки

Reviewer дал **pass_with_conditions** для исходного замороженного отчёта. Он независимо сверил code/matrix/declaration seals и воспроизвёл четыре ограниченных контрпримера. Шесть условий применены primary: точный active/public corpus; named capability checks и явная атрибуция; узкая terminal-guard классификация; terminal monitor вместо browser; граница raw/live readback; errata diagnostics budget 180 с.

Reviewer не читал новые raw stdout/trace, installed/live seals, дополнительную привязку вызовов и три egress result bodies: immutable prepared input не разрешал эти дополнительные тела. Эта граница соблюдена. Они являются primary evidence; расширенная независимая квалификация не заявляется. Первоначальные byte seals и ошибочное budget metadata сохранены, исправления добавлены отдельной записью.

Иные ОС, все concurrency/recovery/crash входы и реальные API неподключённых провайдеров полностью не квалифицированы. Все пять OOP эпиков остаются OPEN. Следующие ограниченные работы: Unicode/UTF-8 stdio, array validation, framing Runtime, terminal admission, локализация startup/registration и измерение штатных бюджетов.

Публичный результат задачи — этот отчёт, JSON-матрицы и canonical checksum. PF-артефакты процесса, native capture/collection и private raw evidence сохранены отдельно. Коммит и оба remote readback фиксируются в delivery report текущей Work.
