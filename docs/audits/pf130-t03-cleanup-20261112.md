## Current integrated behavior

`verify_accepted_collection` in `prepared/input.py` validates bounded immutable
metadata belonging to the exact historical attempt. It checks the capsule,
prepared input, receipt, completion marker and saved output pins without
regenerating acceptance from the current stage or reading the new report.

The CLI's `_finalize_worker_scratch` independently selects exact SQL/native
end-of-use evidence. For accepted output, `release_accepted_scratch` requires
current assignment/capsule/resource authorization and owned creation metadata.
SQL must still identify the exact absent, collected attempt with matching
generation, revision and latest record; the legacy path separately proves
attempt-bound native absence. A historical receipt grants no current permission.

The caller rechecks its captured task, state, acceptance and resource identity
around resource authorization. Only release publication occurs under worker
serialization. Resource admission and physical disposal occur outside the
lifecycle lock; the CLI calls cleanup before prepare/start admission and after
collection serialization has unwound. Failed and never-launched paths retain
their separate evidence requirements. Unknown activity, foreign ownership,
pending collection and changed observations refuse cleanup and preserve data.

## Reproduction and failure disposition

Use the isolated fixture environment in
[`repository-checks.yml`](../../.github/workflows/repository-checks.yml),
step “Qualify historical collection cleanup and native stage advance”, then run:

```text
python -m pytest -q -ra --capture=sys -p no:cacheprovider --basetemp=<owned-scratch>/pytest --junitxml=cleanup-results.xml tests/prepared_collection_state tests/temporary_disposal tests/executions/test_lifecycle.py
```

`PYTHONPATH` includes `src`, `tools` and `tests`, joined with `os.pathsep`.
The workflow creates separate owned roots for all fixture and temporary-file
variables and runs the same selection on Windows and Linux. It pins pytest
9.1.1 and saves each platform's JUnit artifact.

The first local Linux invocation stopped before running tests: pytest's default
file-descriptor capture could not truncate a temporary file on the mounted
filesystem. Its nonzero exit and traceback were retained. The corrected run
uses `--capture=sys` and ran all selected cases, but four failed. The mounted
filesystem reported directory mode `0777`: two owned-creation mode assertions
failed, and private staging plus native-cycle initialization refused with
`private_acl_unavailable`. Initialization additionally exposed a frozen exception
traceback-assignment error while unwinding that refusal; that failure is retained,
and this delivery does not change the exception implementation. These are not
passes. No PF guard, assertion or required scenario was weakened. Linux CI must
execute the same cases on a filesystem supporting POSIX privacy; remounting or
changing host configuration is outside this task. Earlier Windows-only evidence
also did not satisfy the Linux condition.

No executable Python changed, so this delivery introduces no new Python
