# ProcessForge 1.3.0-alpha5

Исправлен источник идентичности Core в CLI, Runtime, мониторе, MCP и Host.
Общий объект CoreProperties читает метаданные принадлежащей процессу поставки;
адаптеры больше не выдают дублирующую константу фасада за текущую версию релиза.

Процесс сохраняет неизменяемую загруженную идентичность. Отдельное обращение
читает актуальные метаданные установленного Core с диска. Обновление файлов
не означает, что работающий процесс уже загрузил новую сборку. После установки
нужно штатно перезагрузить или переподключить долгоживущие приложения.
Отсутствующие или противоречивые метаданные дают явный результат unknown.

Версии релиза, компонента Runtime, протокола, spec и schema остаются разными
контрактами. Публичные параметры и поля ответов CLI/MCP сохранены. Новый owner
допускает внедрение зависимости через конструктор и библиотечное/file-only
использование без запуска транспорта и загрузки фасада CLI.

Runtime/Host state schema2 добавляет переносимый `core_identity`; provenance
каталога MCP contract2 сообщает загруженную и установленную сборки и требует
reconnect при расхождении. Runtime doctor обнаруживает замену сборки даже
с прежним release label. Старое состояние без сведений о build остаётся unknown.
MCP initialize, протокол и входные схемы инструментов сохраняют прежний контракт.

Включены изменения предыдущих альф: явное обслуживание общего поискового
индекса и проверяемые операции обслуживания/восстановления SQLite. Это
предварительный выпуск для opt-in канала alpha; stable остаётся 1.2.0.
Установка использует существующие явное подтверждение и сохранение данных.

См. [свойства Core](../../docs/ru/concepts/core-properties.md): контракт
идентичности, ограничения происхождения и различие загруженной и установленной
сборок. Проверки source, архива, установки и подключённого хоста различаются.
