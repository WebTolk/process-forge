# ProcessForge 1.3.0

## Что изменилось с 1.2.0

- Новые проекты хранят состояние исполнений воркеров и журналы в SQLite.
  Текущие исполнения читаются по индексу. Миграция сохраняет исходные записи
  и переносит состояние последней известной попытки.
- В Forge запросы MCP обрабатывает Runtime выбранного рабочего места. Клиент
  может переподключиться после совместимого обновления Core или перезапуска
  Runtime.
- Updater проверяет содержимое выпуска и сохраняет данные проекта и рабочего
  места. Он умеет управлять Runtime при замене Core и продолжать прерванное
  обновление файлов по сохранённому состоянию.
- На Windows и Linux PF проверяет принадлежность процессов воркера. Ранее
  собранный результат сохраняется, если записи о завершении и сборе совпадают.
- В поставке есть [архитектурные решения](../../docs/ru/architecture/README.md)
  и обновлённые руководства на русском и английском.

## Обновление с 1.2.0

Сделайте резервные копии проекта и рабочего места перед заменой Core.
Запускайте проверенный updater из каталога вне установленного Core. В Forge
можно передать `--manage-runtime` для управления Runtime при обновлении.
Прямые команды Work через Forge CLI ещё могут выполняться локально.
На время обслуживания остановите и эти команды.
[Обновление и восстановление Core](../../docs/ru/concepts/update-lifecycle.md)

Если существующий проект возвращает `storage_migration_required`, выполните
явную миграцию хранилищ при остановленных Runtime и остальных писателях.
Известные форматы heartbeat 1.2.0 сохраняются побайтно, в том числе при наличии
новой подготовленной попытки. Резервные копии и контрольные точки позволяют
продолжить прерванную миграцию.
[Миграция журналов и исполнений](../../docs/ru/concepts/sqlite-journal-maintenance.md)
