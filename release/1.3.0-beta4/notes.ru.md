# ProcessForge 1.3.0-beta4

В beta4 вошли изменения Core по итогам архитектурной сверки 18 ноября.
На поддерживаемых Linux-хостах PF отслеживает принадлежность процессов worker.
Новые проекты используют SQLite для состояния исполнения и журналов событий.
При поддерживаемой миграции сохраняются идентификаторы Work, назначений и капсул.

## Обновление существующей установки

Запускайте проверенный updater из каталога вне установленного Core. В Garage
перед обновлением или миграцией остановите PF и остальных писателей. В Forge
внешний updater с `--manage-runtime` останавливает управляемый Runtime,
обновляет файлы Core и запускает Runtime снова. Прямые команды Work через CLI
пока могут выполняться локально. На время обслуживания остановите и этих писателей.

Если обычная запись возвращает `storage_migration_required`, выполните явную
миграцию хранилища. Миграция сохраняет исходные байты, контрольные точки и
резервные копии. После перехода на SQL восстановление использует сохранённые
данные и журнал миграции. [Руководство по миграции](../../docs/ru/concepts/sqlite-journal-maintenance.md)

## Изменения в beta4

- В Forge MCP обращается к Runtime и восстанавливает соединение после его
  перезапуска. Событие и запись о предстоящей доставке фиксируются одной
  транзакцией. Доставка начинается после фиксации.
- При росте истории проверка текущих исполнений читает индекс текущего состояния.
  При восстановлении сохраняются принадлежность worker и сведения о ранее
  собранных результатах.
- Updater обрабатывает замену файла из поставки на каталог и сохраняет прежнее
  содержимое для восстановления. В Windows права на служебные файлы agent-entry
  устанавливаются до записи данных.
- В поставку включён реестр архитектурных решений на русском и английском.
  [Архитектурные решения](../../docs/ru/architecture/README.md)

В стабильном канале остаётся версия 1.2.0. Beta4 доступна в файлах
предварительного выпуска.
