# ProcessForge 1.3.0-beta1

Этот кандидат исходного кода следует за внутренним checkpoint alpha6 и включает
предыдущие альфа-выпуски. Он фиксирует стабилизацию существующего поведения;
смена идентичности выпуска на beta1 не добавляет функциональности.

Идентичность Core по-прежнему определяется принадлежащей процессу поставкой.
Загруженная идентичность и актуальные установленные метаданные различаются,
как и версии релиза, компонента Runtime, протокола и схем. Существующие
контракты CLI/MCP сохраняются.

Политика обновления Core требует при подтверждённом обновлении приводить каждый
принадлежащий релизу файл Core к байтам проверенного целевого релиза, заменяя
локальные правки даже при неизменных официальных байтах между релизами.
Существующий recovery backup должен сохранять фактическое содержимое до замены
или удаления, включая локальные правки и отсутствие недостающих файлов.
Существующие публичные флаги продолжают приниматься; force не требуется только
из-за локальных правок Core и не обходит проверки полномочий, владения, выбора,
путей, коллизий и безопасности. Неизвестные файлы вне владения PF, конфигурация,
данные проектов и Workplace, состояние runtime сохраняют прежние правила
обработки. Первое обновление с 1.2.0 сохраняет существующие требования передачи
управления, подтверждения и восстановления. Сверка итоговой реализации с этой
политикой и штатные проверки документации и выпуска остаются обязательными.

Кандидат включает исправления подготовки, повторов и уборки после отмены
принадлежащего воркеру scratch. Зафиксированные привязки scratch сохраняются
при повторной подготовке; неопубликованный scratch восстанавливается до повтора.
Разрешение retention не заменяет проверку владения; обязательные входы, данные
восстановления и постоянные доказательства защищены.
См. [временные файлы](../../docs/ru/temporary-files.md).

Проверка выпуска сохраняет запечатанные отчёты, вывод ошибок дочернего процесса
и доказательства извлечённого пакета до disposal. `release-archive-test` снова
допускает отсутствие `--root`, используя прежний корень evidence по умолчанию;
явный корень сохраняет проверку исходного кода.

Эти заметки не подтверждают приёмку beta или публикацию. Проверки исходного кода,
архива, установленного Core и фактически подключённого хоста — разные уровни
доказательств. Настоящие OS cold-stop, restart и reboot требуют отдельной
delivery-операции. Эта смена метаданных не публикует beta update channel, tag,
URL пакета или его hash; stable остаётся 1.2.0.

См. [свойства Core](../../docs/ru/concepts/core-properties.md): ограничения
идентичности и происхождения. Итоговая квалификация beta и независимое ревью
остаются открытыми.
