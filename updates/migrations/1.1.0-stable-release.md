# ProcessForge 1.1.0 Stable Release

No mandatory project migration is required when updating from ProcessForge
1.0.2 to 1.1.0.

Existing Workplaces do have a compatible migration. Run the staged 1.1.0 Core
updater with `--workplace-root` to plan and explicitly apply it. The migration
definition is executable data in
`updates/migrations/1.1.0-workplace-runtime-drivers.yaml`: it adds the missing
PF-owned `codex-exec` runtime driver and registry entry without replacing
existing user configuration. `workplace-init` remains a first-time initializer,
not the update path.

After replacing the distribution, start ordinary project work through the
Garage path: inspect `pf.context`, use `pf.search` or `pf.resolve` when needed,
then call `pf.work.start` for governed work. Missing Codex hooks or PF Runtime do
not make a project incomplete.

Operators using Forge infrastructure should verify their optional Runtime,
Codex MCP registration, and host telemetry separately after the distribution
update.
