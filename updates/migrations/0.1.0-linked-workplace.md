# Migration: 0.1.0 Linked Workplace

This baseline release documents linked mode as the primary model.

Projects should keep `.pf/` thin and resolve ProcessForge core, schemas, tools,
processes, packages, templates, and platform contracts through the workplace
layer.

No automatic migration is required for projects already using `.pf/` with
file-first runtime artifacts. Review:

- `.pf/process-forge.yaml`
- `.pf/process-forge.local.yaml`
- `.pf/hooks.yaml`
- `.pf/contexts/project-context.snapshot.*`

After review, run schema validation, public cleanliness, checksum validation,
and `doctor-project`.
